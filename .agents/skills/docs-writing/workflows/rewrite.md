# Rewrite a repository's markdown onto the convention

This workflow converts documents onto the convention or restructures them; [../SKILL.md](../SKILL.md) § Writing says when it applies. The scope is what was asked for: one file, one folder or the whole repository. Every step runs over the files in that scope and the references the change affects, and a step that names no file in scope is skipped. Extract first, then write from a blank page: read the old files for what is unique in them and the code for truth, then write each new file against its list in [../SKILL.md](../SKILL.md) § Per file type, starting from the example of its type. Delete old content that list does not admit. The code, the tests and git history hold it.

## Steps

1. Inventory every markdown file in scope with the kind of content it holds. For a repository-wide rewrite that is every file the repository owns: the root `AGENTS.md`, every nested `AGENTS.md` or `CLAUDE.md`, every harness-specific instruction file, every file under `docs/`, every `README.md`, `DEVELOPMENT.md`, `SKILL.md`, `workflows/*.md`, `agents/*.md`, and every reference doc.
2. For every file the rewrite will delete or shrink, extract what is unique in it to its new home first: a reason to a comment at the code it explains, a principle to a retained architecture doc, a choice to a decision record, a maintainer step to `DEVELOPMENT.md`, an operator step to the runbook, a plan or research file to its tracker issue. Record each destination in the cleanup item before the old home goes.
3. Classify each remaining claim against the list for its file type: kept or excluded. Verify every kept claim against the code. A claim that says a checker enforces something names the checker; a constraint without an enforcer names review, an operator step, or the gap.
4. Plans, research reports, measurements and handoffs under `docs/` leave the repository. One that is the evidence behind a constraint still in force is attached to that constraint's tracker issue, verified readable, and the constraint links to it; the rest are deleted. Fix every path or link that named them first: a pattern that only classifies files keeps working or goes, and a link to a deleted file goes.
5. Write each principle doc under `docs/architecture/` from [../examples/architecture-plugins.md](../examples/architecture-plugins.md) or [../examples/architecture-design-system.md](../examples/architecture-design-system.md), one cross-folder idea per file. Delete a doc that holds no principle. Give every retained doc its "Read when" line in the root `AGENTS.md` or the nested `AGENTS.md` of the folder it governs.
6. Redo the decision records from [../examples/decision.md](../examples/decision.md) under the [decider](../../decider/SKILL.md) bar. A record whose choice still holds stays active, shortened per the shortening rule in the decider's `SKILL.md` § What warrants a decision record, and why, or is removed per the decider's `workflows/update-decision.md` when its choice is routine and its reason moves to the code or principle doc it governs. Retire a record per the same workflow only when its choice is withdrawn and nothing replaces it. Fix every reference to a retired, removed or renumbered record in code comments, docs and `AGENTS.md` in the same change; a citation of a removed record points at the reason's new home. Take each such ID from its INDEX row and search for that ID literally, and search the INDEX links; leave no dangling ID, and keep a one-line pointer document only where a citation outside the repository needs the path.
7. Write the root `AGENTS.md` from [../examples/root-agents.md](../examples/root-agents.md). Keep the `## Code Review Rules` section the bot-instructions package renders.
8. Write a nested `AGENTS.md` from [../examples/nested-agents-plugins.md](../examples/nested-agents-plugins.md) or [../examples/nested-agents-components.md](../examples/nested-agents-components.md) in each directory with local rules. Delete a hand-written `CLAUDE.md`, a `.claude/rules` file, and every other harness-specific instruction file a kendex shim replaces. A file a package renders and keeps current, such as the bot-instructions package's `.github/copilot-instructions.md`, `.github/instructions/code-review.md` and `.github/instructions/*.instructions.md`, is that package's and stays.
9. Write each `README.md` from [../examples/readme.md](../examples/readme.md) and each `DEVELOPMENT.md` from [../examples/development.md](../examples/development.md). Move the repository's `DEVELOPMENT.md` to the root and its images to `docs/images/`, and fix every link.
10. Write each `SKILL.md` from [../examples/skill-entry.md](../examples/skill-entry.md) and each reference doc from [../examples/reference.md](../examples/reference.md). Preserve its canonical schema or pattern and field semantics. Include defaults only when defined. Move rationale out of a `SKILL.md` into a decision record or a comment at the code.
11. Run `kendex refresh` so the shims are written, then `kendex verify`.
12. Run the commit-guards `md-format` and `md-refs` lanes over the files the rewrite touched. Reflow a file only where `md-format` names it; the rewrite is not a tree-wide reflow.
13. Remove every instruction the installed packages now enforce from the prose, and report anything portable the packages lack upstream through `kendex report`.
14. Run the repository's own validation.
