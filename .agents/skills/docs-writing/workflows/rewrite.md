# Rewrite Markdown to what its readers need

This workflow converts Markdown onto this skill's convention, restructures it, or cuts what its readers do not need; [../SKILL.md](../SKILL.md) § Writing says when it applies. The scope is what was asked for: one file, one folder or the whole repository. Every step runs over the files in that scope and the files that cite them, and a step that names no file in scope is skipped.

A scope of `docs/` or a file under it edits `AGENTS.md` only for the "Read when" lines of the docs it keeps or deletes, and edits no `SKILL.md`. A rewrite of an `AGENTS.md` or `SKILL.md` body runs only where the request names that file or the whole repository, which is the owner's approval of that rewrite.

## Steps

1. **Readers.** For each file, name who reads it and when: each loader, how it loads (at session start, at skill activation, by a route to one section, from a hook or from a program), the task it is doing, and whether it reads the whole file or one section. A program that parses a heading or a table is a reader. Count the words each loader reads, in the installed copy where kendex renders project instructions above the body. The readers give the file its jobs: an entry read before the loader knows its workflow, a workflow run from first line to last, or a reference read at one section ([../references/skill-files.md](../references/skill-files.md)). For a repository-wide scope, the files are every Markdown file the repository owns: the root and every nested `AGENTS.md`, every harness-specific instruction file, every file under `docs/`, and every `README.md`, `DEVELOPMENT.md`, `SKILL.md`, workflow, agent file and reference doc.
2. **Directive list.** Number every rule of the old file, one row each. A rule's "never" clause is part of its row. List the file's headings, anchors and named rules as rows too, since other files cite them. Write the list under `tmp/` and attach it to the tracker issue the work serves: it records every fact that moves or goes.
3. **Verdict per rule.** For each row, write the mistake it prevents, whether an agent makes that mistake untold, what the mistake costs, and what else already stops it. [../SKILL.md](../SKILL.md) § Per file type sets the bar and names what can stop a mistake. Each row takes one verdict: keep, move to a named file and section, or cut as a duplicate, a tool's refusal, never applies, or competence.
   - **Cut.** A cut carries a trace. Follow one ordinary request from the agent that needs the rule to the check that stops the mistake, naming each file and step. The check acts before the effect: a refusal after a merge does not stop a mistake made before it. The route is the files step 1 says that agent reads for that task, so a rule in a file off its route stops nothing. The trace covers every case the rule governs. If the refusal leaves the agent to read long help to recover, keep the literal form beside the rule. If you cannot trace a cut, keep the rule.
   - **Move.** A rule whose home is another file or another package's step moves there in the same change. It keeps its name as its heading at the new home, and a literal form moves with the rule that needs it. The homes outside the skill are a comment at the code for a reason, an architecture doc for a principle, a decision record for a choice, `DEVELOPMENT.md` for a maintainer step, the runbook for an operator step, and the tracker issue for a plan or research file. A value table or journal moved to `references/` is the same content at a new path; it stays only where a named reader loads it ([../references/reference-docs.md](../references/reference-docs.md)). Write each moved rule at its new home and read it there before you delete the old copy. A removed paragraph proves removal alone.
   - **Keep.** A kept rule keeps its actor, condition, scope, exceptions, order and enforcement claim; a row whose meaning changes is a defect of the write, or a separate change that names it. Verify each kept claim by [../SKILL.md](../SKILL.md) § Writing, and check that each kept source link is readable. A failed, unchecked or unread verification stays unresolved, with its source and next action. Disagreement with an active decision does not make its policy obsolete: keep the choice and any owner-only approval, and report the disagreement through decider. A kept rule that would serve every install, and that no installed package states, is also reported through `kendex report`.
   - **Design claims.** Sort each internal design claim by [../SKILL.md](../SKILL.md) § One home per fact. A behaviour a test holds is deleted, the test being its home. A behaviour no test holds becomes a test item on the tracker.
4. **Edit in place or rewrite.** Where step 1 finds one job, edit in place: delete the cut rows, apply the moves, and leave the rest as written. Where it finds two, such as an entry that other packages also read by section, or a workflow holding a contract that other jobs look up, split the file by job and write each part from a blank page. Open the reader list, the verdict table, the type's section and its example ([../SKILL.md](../SKILL.md) § Per file type), and copy no old text except a literal form a verdict keeps. A `SKILL.md` holds what [../references/skill-files.md](../references/skill-files.md) gives an entry, whatever roles its example has.
5. **Citations.** Search the repository for every heading, anchor and named rule the change moves, renames or deletes: source files, scripts, manifests, tests and printed help, not renders, which follow their sources. md-refs judges links and `§` code spans, never a plain-text citation or a bold rule name, so the search is the check. Change each citer in the same pull request, or keep the name. Keep a name a program parses or prints, and one a citer outside the repository uses. Update a claim in a touched file that the change makes false, by [../SKILL.md](../SKILL.md) § Maintenance. After the write, search again: the second search finds no stale name.
6. **Conversion.** These apply only where the scope holds the files:
   - Plans, research reports, measurements and handoffs under `docs/` leave by [../SKILL.md](../SKILL.md) § Plans and research. Name the inspected tracker attachment as the destination of retained evidence. A missing local report whose tracker attachment is unread leaves preservation unchecked: read the attachment before you claim either preservation or loss.
   - Delete a doc under `docs/architecture/` that holds no principle by [../references/architecture.md](../references/architecture.md).
   - Redo decision records from [../examples/decision.md](../examples/decision.md) under the [decider](../../decider/SKILL.md) bar and its update workflow. A record whose choice still holds stays active, with its authority unchanged. Keep a one-line pointer for a removed record only where a citation outside the repository needs its path.
   - Keep the root `AGENTS.md` section `## Code Review Rules`, which the bot-instructions package renders. A file a package renders and keeps current, such as that package's `.github/copilot-instructions.md` and `.github/instructions/` files, is the package's and stays.
   - Migrate hand-written harness-specific rules, `.claude/rules` content included, only under the consumer's selected instruction-migration policy and only where the request authorizes the source and destination files. A prose rewrite alone authorizes no migration. With no selected policy, or with files outside the authorized scope, keep the existing rule files.
   - A reference keeps its canonical schema or pattern and its field semantics, and states a default only where one is defined.
7. **Refresh.** If the rewrite changes kendex-owned inputs, follow the selected project's declared refresh owner and verification route. In an ordinary local checkout with no declared refresh owner and no recorded lane, run `kendex refresh --scope project --yes --leave`, then `kendex verify --scope project`; stop on failure. An ordinary worktree keeps normal project resolution. A recorded implementation lane does not refresh. An authorized refresh lane passes `--lane-refresh` as its brief permits. A hosted control checkout receives committed outputs through `sync-base` after the owner's refresh pull request merges. For a hosted control checkout with no declared owner, confirm an owner outside the control host.
8. **Mechanical checks.** Run the commit-guards `md-type` and `md-refs` lanes over the files the rewrite touched. Reflow a file only where `md-reflow --check` names it; the rewrite is not a tree-wide reflow. Then run the repository's own validation.
9. **Check by use.** A top model from another provider than the writer's does real tasks of the readers step 1 names, reading only the new files each task's route reaches. Give it a task for each reader, and a failure case for each cut: the request the cut rule governed, which its trace says another check now stops. For each task it reports the route, the outcome against the old file's, and the words read before and after; the words are a reading, not a target. A rule that became a list or a table is tested on its actor, scope, exceptions and order. Name the checker's model and effort in the result. The second-opinion skill guarantees another model, not another provider, so name its target. The check passes when every task reaches the old outcome and every cut's trace holds. The writer repairs each failing row, and the same checker reads the repaired rows once more. A second failure goes to the owner for a ruling, never to another round.
