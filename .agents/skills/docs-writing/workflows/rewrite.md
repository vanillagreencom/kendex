# Rewrite a repository's markdown onto the convention

This workflow converts documents onto the convention or restructures them; [../SKILL.md](../SKILL.md) § Writing says when it applies. The scope is what was asked for: one file, one folder or the whole repository. Every step runs over the files in that scope and the references the change affects, and a step that names no file in scope is skipped. A scope of `docs/` or a file under it edits `AGENTS.md` only for the "Read when" lines of the docs it retains or deletes and edits no `SKILL.md`; steps 7, 8 and 10 run only where the request names those files or the whole repository, which is the owner's approval of their rewrite. Extract first, then write from a blank page: read the old files for what is unique in them and the code for truth, then write each new file against its list in [../SKILL.md](../SKILL.md) § Per file type, starting from the example of its type. Delete old content that list does not admit. The code, the tests and git history hold it.

## Steps

1. Inventory every markdown file in scope with the kind of content it holds. For a repository-wide rewrite that is every file the repository owns: the root `AGENTS.md`, every nested `AGENTS.md` or `CLAUDE.md`, every harness-specific instruction file, every file under `docs/`, every `README.md`, `DEVELOPMENT.md`, `SKILL.md`, `workflows/*.md`, `agents/*.md`, and every reference doc.
2. For every file the rewrite will delete or shrink, extract what is unique in it to its new home first: a reason to a comment at the code it explains, a principle to a retained architecture doc, a choice to a decision record, a maintainer step to `DEVELOPMENT.md`, an operator step to the runbook, a plan or research file to its tracker issue. Record each destination in the cleanup item before the old home goes. Inspect each destination: a journal, a value table or a field inventory moved to `references/` or another folder is the same content at a new path, and it stays only where a named reader loads it, per [../SKILL.md](../SKILL.md) § Reference docs; otherwise it is deleted.
3. Classify each remaining claim against the list for its file type: kept or excluded. Verify every kept claim against the code. A claim that says a checker enforces something names the checker; a constraint without an enforcer names review, an operator step, or the gap. Sort each internal design claim by [../SKILL.md](../SKILL.md) § One home per fact. A behaviour spec under `docs/architecture/`, what a page, key or button does, is checked against the tests that hold it: a behaviour a test holds is deleted, the test being its home; a behaviour no test holds becomes a test item on the tracker, never a doc. [../examples/behaviour-spec.md](../examples/behaviour-spec.md) sorts one.
4. Plans, research reports, measurements and handoffs under `docs/` leave the repository. One that is the evidence behind a constraint still in force is attached to that constraint's tracker issue, verified readable, and the constraint links to it; the rest are deleted. Fix every path or link that named them first: a pattern that only classifies files keeps working or goes, and a link to a deleted file goes.
5. Select the retained principles before writing a file: for each, the reader's task and the harmful mistake the doc prevents, per [../SKILL.md](../SKILL.md) § `docs/architecture/<name>.md`. A subsystem name alone selects nothing, and the rules one reader uses for one task are one doc. Then write each retained doc from [../examples/architecture-plugins.md](../examples/architecture-plugins.md) or [../examples/architecture-design-system.md](../examples/architecture-design-system.md). Delete a doc that holds no principle. Give every retained doc its "Read when" line in the root `AGENTS.md` or the nested `AGENTS.md` of the folder it governs; a link from another doc is not a route. A human architecture page, [../SKILL.md](../SKILL.md) § Human architecture page, is product content: it stays where the site loads it and takes no "Read when" line.
6. Redo the decision records from [../examples/decision.md](../examples/decision.md) under the [decider](../../decider/SKILL.md) bar. A record whose choice still holds stays active, shortened per the shortening rule in the decider's `SKILL.md` § What warrants a decision record, and why, or is removed per the decider's `workflows/update-decision.md` when its choice is routine and its reason moves to the code or principle doc it governs. Retire a record per the same workflow only when its choice is withdrawn and nothing replaces it. For a retirement, retain the short record and its historical citations under decider's update-decision workflow. Fix active-policy references to a withdrawn choice. For a removed or renumbered record, fix every affected reference; a removed record's citations point at the reason's new home. Search each affected ID and filename literally and check INDEX links. Keep a one-line pointer for a removed record only where an external citation needs the path.
7. Write the root `AGENTS.md` from [../examples/root-agents.md](../examples/root-agents.md). Keep the `## Code Review Rules` section the bot-instructions package renders.
8. Write a nested `AGENTS.md` from [../examples/nested-agents-plugins.md](../examples/nested-agents-plugins.md) or [../examples/nested-agents-components.md](../examples/nested-agents-components.md) in each directory with local rules. Move hand-written harness-specific rules, including `.claude/rules` content, into `AGENTS.md` and delete the empty rule files. Keep project-owned `CLAUDE.md` imports under [../SKILL.md](../SKILL.md) § `CLAUDE.md`. A file a package renders and keeps current, such as the bot-instructions package's `.github/copilot-instructions.md`, `.github/instructions/code-review.md` and `.github/instructions/*.instructions.md`, is that package's and stays.
9. Write each `README.md` from [../examples/readme.md](../examples/readme.md) and each `DEVELOPMENT.md` from [../examples/development.md](../examples/development.md). Under the default layout, move the repository's `DEVELOPMENT.md` to the root and its images to `docs/images/`, and fix every link; keep supported variants and owner-approved departures per [../SKILL.md](../SKILL.md) § Layout.
10. Write each `SKILL.md` from [../examples/skill-entry.md](../examples/skill-entry.md) and each reference doc from [../examples/reference.md](../examples/reference.md). Preserve its canonical schema or pattern and field semantics. Include defaults only when defined. Move rationale out of a `SKILL.md` into an admitted principle doc, a decision under decider's bar or a comment at the code.
11. Run `kendex refresh` to update package renders, then `kendex verify`.
12. Run the commit-guards `md-format` and `md-refs` lanes over the files the rewrite touched. Reflow a file only where `md-format` names it; the rewrite is not a tree-wide reflow.
13. Remove every instruction the installed packages now enforce from the prose, and report anything portable the packages lack upstream through `kendex report`.
14. Run the repository's own validation.
