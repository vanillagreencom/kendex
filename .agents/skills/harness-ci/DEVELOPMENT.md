# harness-ci development

Maintainer notes. Consumer docs: [README.md](README.md); the wiring rules: [SKILL.md](SKILL.md).

## Invariants

- `--no-renames` is fixed, never a flag. Rename detection emits only the post-image, so `git mv src/app.ts .agents/skills/x/app.ts` would list one harness path and nothing else, and the deletion of `src/app.ts` would go unjudged. Without it both paths are listed and the diff answers `false`.
- `pull_request` uses the merge base (`base...head`) because the base branch moves under an open PR. `push` and `merge_group` use the two endpoints (`base head`): a force-push leaves the `before` sha off the head's history, and a merge base there is a commit the push already discarded, so measuring from it reads a push that dropped product work as render-only. A merge group's base is an ancestor of its head by construction, so the two forms agree there.
- An empty changed-file set answers `false`, because it is also what a diff that read nothing looks like.
- Docs mode answers `false` when any changed path is outside the path set in `harness-only --help`. The `docs-only` suite enforces the set.
- The engine derives `.kendex-generated.json` from rendered artifact files, shared registration files, and instruction shims. It excludes in-place declarations. Pi carrier payloads do not enter the render model and remain source.
- Inventory membership is exact, never a folder prefix. A generated file adopted as source must be absent from the head inventory, which causes product checks to run. Deletions use the base inventory.
- A missing or invalid inventory runs every lane, including the commit that first installs the inventory. Inventory additions also run every lane before the new paths become trusted base data.
- `change-class` measures a size only on the two `harness-only` `false` causes raised after it has read every changed path against an inventory it could read, `cause=product-source-or-unreadable-ownership` and `cause=generated-ownership-gain`: those are the readable product diffs, and they keep their `harness-note:` line while the class comes from the size rules. Every other cause is a refusal to read something rather than a diff to measure, and answers `standard` carrying the cause as it stands, ahead of every path and size rule. The script's list names what may be measured, never what is refused, so `cause=invalid-generated-paths`, `cause=unreadable-base-inventory`, `cause=unreadable-head-inventory`, `cause=unreadable-changed-path`, `cause=file-lookup-failed` and every cause `harness-only` adds later are refused by the default without being named.
- `aggregate-needs` accepts a skipped job only when the classifier succeeded, its waiver is `true`, and the job is in the caller's explicit skippable set.
- `change-class` reads no diff range of its own: it calls `harness-only` for the changed-path set and for the generated-path ownership rules, and repeats that run's `changed-path:` and `base-rev:` lines as they stand and its verdict cause as a `harness-note:` line. The `base-rev:` line is the operator's record of the range the paths came from, and the one base-dependent read this script makes: the render proof hands that revision to `kendex verify --base`, and resolves no base of its own. The git it does run on the judged checkout is two reads and no write: `rev-parse --git-common-dir` and `--git-dir`, and `status --porcelain`. The header `--help` prints names both and claims no merge base. Suite rows hold it to that text, and one more counts the script's `git -C "$repo"` call sites against the number the header spells, having first established that no invocation is spelled another way, so a read added while the sentence stands reds rather than reaching a reader who trusted it.
- A refresh that ADDS a rendered file gains an inventory entry, and `harness-only` refuses a gain, so the `render` class is out of reach for it and the diff takes the class its size earns. That refusal is `harness-only`'s, raised before the render proof runs, and it stands: a gain is a path the base inventory never carried, and accepting one on the head inventory's word alone would let a branch name a product file as generated. The `harness-note:` line is what tells an operator this happened.
- The `render` class reads nothing of orch's, and is the one class a checkout without that sibling can still reach. `trivial`, `micro` and `small` are all judged on orch's line count and all refused by its path list, which runs ahead of the trivial decision. The ceilings in that file are `micro`'s and `small`'s alone.
- A cross-package call into orch checks `BRANCH_GROWTH_CONTRACT` first. Each package is installed at its own revision, so the sibling can be older than the caller, and errexit is off inside `measure`: a missing function would be `command not found` on stderr and an extra argument would be dropped in silence.
- A harness instruction pointer (`CLAUDE.md`, `*/CLAUDE.md`) is refused every narrow class except `render`. Inside a diff the render proof covers it is a render like any other; anywhere else nothing re-rendered it and the shipped documentation set would take a root one for ordinary markdown.
- The `render` class needs `kendex verify --scope project --json` to report files checked and none failed, and needs every changed path to be owned by a position a passing row of that document prints. A row's positions are the engine's own answer to where the installation sits, printed with the row: a file kendex owns whole, a tree it owns whole, or keys inside a shared file it writes entries in. A file position owns exactly the path it names; a tree position owns its path and the paths under it. A keys position — a hook registry, a settings file, an MCP server list — owns its path only where the row also says `foreign: unchanged`, which is kendex's own judgement that the file as the range's base held it, with kendex's edits applied over it, is byte for byte the file on disk; the classifier hands `kendex verify --base` the revision `harness-only` printed on its `base-rev:` line and parses no settings file itself. Anything else on such a file answers `standard cause=render-path-partial path=<p> foreign=<changed|unknown>`, and a changed path no passing position covers answers `standard cause=render-path-unowned path=<p>`. Either refusal is printed under `render-coverage: named=<n>`, the count of positions the run read, which goes out ahead of the ownership pass so a refused run still says what it weighed; beside it the refusal prints verify's own rows and one `render-position: owns=<o> foreign=<f> path=<p>` line per position printed under the refused path's top-level directory, so the log names the rows an operator would otherwise re-run kendex to see. Ownership is read off rows in state `ok` alone. A clean exit alone is not proof: it also closes a run that checked nothing, so the document's `checked` count is read, and a run that checked nothing answers `standard cause=verify-counted-nothing`. The document is the whole contract with kendex, version first: a kendex that rejects `--json`, which every release up to and including v5.0.1 does, exits non-zero on the flag and answers `standard cause=verify-refused`; one that accepts the flag but prints no document, or one of another `version`, answers `standard cause=verify-document-unreadable` rather than being read by guesswork, and the human rows are never parsed. The two files kendex keeps about itself, `.kendex-lock.json` and `.kendex-generated.json`, reach the proof as positions of the `record` and `inventory` rows that document prints, each in state `ok` only where `kendex verify` found the file as it would write it, and are granted by name to nobody; the record no longer decides anything in this script, and no base-record read survives. What makes those rows trustworthy is `kendex verify` itself, whose row set is closed against the scope's declarations in both directions — a recorded entry nothing declares fails its row and a declared installation the record does not hold is a gap — and whose record and inventory rows fail on an edit to either file. A diff of generated files alone that fails the proof answers `standard`; it never falls through to a measured class. The de-listing chain KEN-1637 recorded closes at its first step: a commit that drops a rendered path from the inventory and its entry from the record fails the inventory row and names the gap, so it never buys the class; the hand edit cut from it still measures as product code, since the path is on the inventory at neither of its endpoints, which `tests/change-class.test.sh` pins beside the refused de-listing.
- No shipped kendex reaches the failed-count refusal on a zero exit today, since a run with a failing row exits non-zero before the document's `failed` count is read; the refusal is the guard against a kendex that later reports failures beside a zero status, and its survival under mutation is that, not a gap.
- The verdict describes a working tree, so the working tree has to be one a commit left: a checkout with anything uncommitted, untracked content included, is refused the `render` class rather than verified. Without that, any step running ahead of the classifier that writes into the judged checkout — an install pass primed there, a generator — would have the proof attest to its own repair instead of to the commit the pull request would merge. What `git status --porcelain` establishes is that the tree matches the checkout's own HEAD, which `references/wiring.md` § Shape 4 makes the pull request's merge ref rather than `--head`; every way those two commits differ costs a package its row, so the gap is conservative, and closing it would cost that shape its merge-ref checkout. `git status --porcelain` also omits ignored files, so an ignored harness file such as a lane's `.claude/settings.local.json` is invisible to the read; the only shipped caller today is the `references/wiring.md` § Shape 4 classify job on a fresh CI checkout, which carries none, and a caller that reads the render grant in a working checkout has to widen the read to `--ignored` over the harness surface paths.
- `kendex verify` runs a package's declared checker out of the tree it checks wherever the checkout carries kendex's arming record under a git directory. That checker is a file a pull request can change, so a checkout carrying a record is refused the `render` class rather than verified. The whole-project scope is also what makes the proof slow and what makes unrelated drift refuse the class; the rows now carry the path-to-package map, and the proof still runs whole because the row set closed against the declarations is a whole-scope fact.
- A changed configuration or instruction source refuses every narrow class, ahead of the render proof: kendex's own configuration, the instruction sources it renders from, and `.gemini/settings.json`, which kendex generates but whose shim row weighs one key of the document. The registry files a harness executes as configuration refuse every narrow class but `render`, below the render branch, one project-scope entry per structured surface the adapters under `crates/core/src/harness` name: `.claude/settings.json`, `.claude/settings.local.json`, `.mcp.json`, `.codex/config.toml`, `.codex/hooks.json`, `.agents/hooks.json`, `.agents/mcp_config.json`, `.pi/settings.json`, `.pi/kendex/hooks.json`, `opencode.json`, `opencode.jsonc`, `.cursor/hooks.json`, `.cursor/mcp.json`, `.github/copilot/settings.json`, `.github/copilot/settings.local.json`, `.github/mcp.json` and `.github/hooks/*.json`. The last is a glob because Copilot's hook registry is one file per hook named for the hook, which `engine/targets.rs` `copilot_hook` writes as `.github/hooks/<name>.json`. Their keys name the hooks that run and the MCP servers that may be started, and a harness executes them whether or not kendex wrote the file, so a hand-authored one the inventory does not carry must not fall through to the size rules. One the inventory does carry reaches the render proof first, where the owner rule for such a file is stated once, on `Owns::Keys` in `crates/core/src/engine/desired.rs`: kendex owns keys inside it and never the file, so the row owns it only with `foreign: unchanged` beside it. The two groups together cover every harness the adapters name: this list holds every one of them but Gemini, whose settings file sits in the configuration-source group above because the row kendex prints for it vouches for one key alone. A harness added later joins this list, unless its surface is one kendex only partly vouches for, which joins the configuration-source refusal instead; nothing derives either group from the adapters at run time.
- The measured classes come from orch's `branch_size_classified`, which owns the production/test split and the render-mirror pairing `branch-size-check` judges an allowance by. `change-class` hands it the base endpoint the call named, so the lines are counted over the range the paths came from. Only `--event pull_request` and `--event merge_group` reach a measured class; every other event answers `render` or `standard`. The size reader takes a three-dot range, which on a merge group is the same commits as the two-dot one because its base is an ancestor of its head, so the two events are measured over the range each already defines.
- The judged tree's configuration decides nothing. `branch_growth_render_roots_from_env` fixes the render roots from this process's environment before the measurement runs, so the tree's settings are never loaded: loading them would let the change under judgement choose the roots its own size is scored against, and would source the file its `KENDEX_ENV_FILE` names.
- A glob list is split with pathname expansion off. Splitting it under the default would replace a glob naming a real directory with the files under the caller's working directory, and the list would no longer be the list.

## Tests

`tests/` runs in kendex CI on every change to this repository; run one locally with `bash skills/harness-ci/tests/path-set.test.sh`.

| Suite | Covers |
| --- | --- |
| `path-set` | Writer-recorded paths, mixed diffs, carrier source, deletions, and unrecorded neighbors |
| `in-place` | Source adoption removes generated ownership |
| `rename-into-render` | The `git mv` into a render tree, and the control proving the flag is load-bearing |
| `event-ranges` | The force-push case, the moving base branch, merge groups |
| `fail-closed` | Unclassified events, unresolvable endpoints, an empty diff, a merge-base diff git refuses, a path git had to quote |
| `docs-only` | Documentation paths, excluded source paths, pull requests, merge groups, and the path-set must-fail control |
| `aggregate-needs` | Successful dependencies, authorized skips, refused results, invalid input, and must-fail controls for classifier success, dependency success, the waiver, and skippable membership |
| `wiring-errors` | Exit 2 on bad calls, a flag where a value belongs included; `--output` and `$GITHUB_OUTPUT` behaviour |
| `wiring-shapes` | Every shape in `references/wiring.md` keeps each expression on one line, orders the push endpoints, names the shipped script path, and steps its indentation by two |
| `change-class` | One row per class and per boundary, the author-writable fields that assert nothing, the wiring outputs, both trivial settings, the render rows read off the verify document — an agent-and-hook refresh, a skill tree, a registry file changed only where kendex writes keys, one changed elsewhere and one the run could not judge, a hand edit under a failing row, a path no passing position covers, a verifier printing human rows or another document version, and the four awkward spellings owned from their printed positions — the causes that answer `standard` ahead of every path and size rule — the three inventory-integrity ones, a changed path git had to quote, a path lookup and an invented cause both driven through a stubbed `harness-only`, each beside the measured row that proves the default refuses a refusal and not a diff — the bookkeeping diff owned from the record and inventory rows and from no name, the Gemini settings file refused ahead of the proof, the header's git-read count against the script's own call sites, the priming step and the dirty checkout it must not leave, and the must-fail controls where a classifier trusting the inventory passes a hand edit inside a render, one naming its own bookkeeping files passes a diff of them, one re-deriving a leaf from a row's name refuses the scoped extension, and one reading catalog bytes never clears the proof |

The `change-class` suite's last section installs and refreshes a real consumer with a real `kendex` rather than a double, which is the only way its rows can say what a real refresh earns: the pure refresh is a `render`, owned from the positions its passing rows print; the same refresh with one rendered file hand-edited is refused at the proof itself; and a commit that de-lists one render from the inventory and drops its entry from the record is refused at the proof too, the inventory row naming the de-listed path. It drops the fetched mirror and primes it back with `kendex source refresh` before the classify rows, which is how `references/wiring.md` § Shape 4 primes a runner, and it asserts the judged tree is unchanged across that step. Every call it makes runs through `kendex_here`, which captures the output and prints a `FAIL:` line naming the command, that output and the binary's version before the suite reports and stops: the rows after a failed install would judge a tree that was never built, and with the output discarded a runner carrying the wrong binary died at exit 2 with nothing in the log to say which call it was. Without a `kendex` on PATH the section skips itself, so `.github/workflows/skill-tests.yml` builds the checkout's own `kendex-cli` on the Linux leg of the `rest` shard and sets `HARNESS_CI_REQUIRE_KENDEX` for every Linux leg of the job, which turns that skip into a failure wherever the suite runs. Building from the checkout is what keeps the rows and the verify they read from in one commit: the contract between them is the `--json` document's `version`, pinned in `change-class` as `VERIFY_DOCUMENT_VERSION`, and a consumer copying `references/wiring.md` § Shape 4 pins a release whose `kendex verify --json` prints that version. The fixture builds its own catalog as a local git repository and fetches it into a sandbox `HOME`. The macOS leg keeps the skip: it is already that shard's slowest leg, and the rows judge the classifier rather than the platform, so one leg proves them.

`tools/bash32-lint` checks the shipped script for Bash 4+ syntax, because consumer runners include macOS system Bash 3.2.
