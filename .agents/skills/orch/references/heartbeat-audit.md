# Heartbeat audit

This rule applies to the fleet's Linear team. A GitHub-only fleet skips it with a note: `audit-issues team` has no GitHub mode. Keep Triage enabled only for public-repository teams receiving outside issues; fleet filings enter Backlog per [audit-issues § 7.2](../../project-management/workflows/audit-issues.md#72-execute-approved-creations-and-cancellations).

| Heartbeat input | Action |
|-----------------|--------|
| Fresh, complete team Backlog count and `last_backlog_audit` from fleet state | Run a full audit when the record is missing, its `at` is older than 24 hours, or today's count is at least 50 above its `backlog`. Otherwise skip the full audit |
| Every team Triage item, fetched with `--max`, without a created-since or `triaged` filter | Decide every item whose `created_at` is older than 24 hours at this heartbeat, even when no full audit is due |
| Failed, truncated or unreadable input | Report the failure; do not treat it as zero or advance the audit record |

Read counts and identifiers only in the overseer; the TPM reads full bodies, comments and source. Use the fleet's explicit `[OVERSEE_STATE_DIR]` for every state command:

```bash
.agents/skills/orch/scripts/workflow-state --state-dir [OVERSEE_STATE_DIR] get oversee '.last_backlog_audit'
.agents/skills/linear/scripts/linear.sh issues list --team [TEAM] --state Backlog --max --format ids
.agents/skills/linear/scripts/linear.sh issues list --team [TEAM] --state Triage --max --format ids
```

- **Full audit order.** Run `reconcile-work-items` through [audit-issues § 1.2.1](../../project-management/workflows/audit-issues.md#121-preflight--linear-trackerlinear). Exit 1 supplies findings; exit 2 stops the audit. The primary overseer runs `audit-issues team` over Backlog, Todo, In Progress and In Review, then `audit-issues issue [TRIAGE_IDS]` over all Triage items. An empty Triage set needs no issue-mode invocation. These are primary-session wrappers, never delegated workflows.
- **One analysis subagent.** Combine those wrappers' § 4.1 analysis briefs into one fresh canonical `tpm` task, on the launch and single-return route of [Lane proposals](oversee-events.md#judgement-rules). It follows `tpm-audit.md` with `--team`, then `--issues [FILE_PATH]` using the existing-issue input file prepared by [audit-issues § 4.1](../../project-management/workflows/audit-issues.md#41-delegate) from the supplied Triage IDs. It returns separate inline team-mode and issue-mode payloads in one final return. Collect and validate each through `audit-issues` § 4.2, then execute the wrappers in the order above. A heartbeat with only aged Triage items delegates only that issue analysis. The brief includes [SKILL.md § The Cycle, Item work stays in lanes](../SKILL.md#the-cycle): the control host permits read-only analysis, no item work or bulk writes. The TPM changes no tracker fields. For this audit, Triage is an eligible input despite `tpm-audit`'s active-state restriction; it recommends acceptance to Backlog or Todo with labels, priority and project, duplicate merge, or decline with a reason. Leave younger Triage items unchanged.
- **Authorization.** An aged-Triage-only run authorizes and executes dispositions only for its original input Triage IDs, ignoring global-sweep rows for every other issue. Before `audit-issues` § 6, check every proposed action against live lanes, open PRs and branches, issue bodies and pending owner decisions. Hold every creation and every action on an item with a live lane, an open PR or branch, an owner hold or gate, a quoted owner directive, or Urgent or High priority. Also hold a cancel dependent on a pending owner decision and a close by folding into a larger item. Under `PM_CREATE_AUTONOMY=auto`, authorize only the remaining duplicate closes and obsolete closes whose row names a Done item or merged commit and shows that it satisfies the closed item's scope. Apply the remaining label, priority, relation, hierarchy and project corrections automatically. Accept an unheld aged Triage item with those fields; a decline outside the eligible close set needs an ask. Under `ask`, closures also wait for approval. Remove held rows from the execution set, including `supersedes[]` and cascading child cancellations; keep them in the findings for the owner. The automatic Cancel set is never the whole displayed Cancel section.
- **Triage execution.** After authorization, the primary accepts an aged Triage item with `.agents/skills/linear/scripts/linear.sh issues update [ID] --state "[Backlog|Todo]" --labels "[VALIDATED_FINAL_LABELS]" --priority [PRIORITY] --project "[PROJECT]"`, after `audit-issues` § 7.0 label preflight. Issue-mode `valid` or `skip` alone does not accept it. For an authorized duplicate close, including an existing issue assigned `skip` with the kept issue as `target`, write a reason naming the kept issue to a file, run `linear.sh comments create [ID] --body-file [REASON_FILE]`, then `linear.sh issues update [ID] --state "Canceled"` per the linear skill's patterns/workflow-actions.md § State Transitions. Verify every mutation live through `audit-issues` § 7.5 before counting it or recording audit completion.
- **One owner ask.** Batch the held rows from both passes into one file, naming each proposed action and its evidence. Send one `lane-mail ask --item overseer --to owner --file [PATH]` with options and the safe recommendation through [communication-modes.md § Owner asks](communication-modes.md#owner-asks), not the wrapper's interactive multi-select. An existing unresolved ask for the same rows remains pending, not duplicated. When a master runs, require the root's configured `SLACK_MASTER_FILE` to be younger than `SLACK_MASTER_MAX_AGE` under the slack skill's README.md § The master hold before sending the ask. Confirm `slack listen --status` reports `held-by=master`; the master then reads the root's mailbox first. Without that fresh configured presence, the relay posts the ask to the owner. Apply only the owner's authorized rows after its ruling.
- **Audit record.** After both full-audit passes validate and the primary applies the authorized actions and sends any owed ask, record the completion time as ISO 8601 UTC and a fresh post-audit Backlog count with the command below. Pending owner rows do not prevent recording a completed analysis. A failed pass or mutation leaves the prior record unchanged. An aged-Triage-only pass does not reset the full-audit clock.

```bash
.agents/skills/orch/scripts/workflow-state --state-dir [OVERSEE_STATE_DIR] set oversee last_backlog_audit '{"at":"[UTC_TIME]","backlog":[BACKLOG_COUNT]}'
```

- **Progress report.** In every `report-due` owner summary, add `created N, closed M since the last report` under Landed. Count distinct issue IDs from verified audit § 8 execution results and lane creation and closure receipts since the last report sent to the owner, or fleet start for the first report. Proposals and pending rows do not count; missing receipts read `counts unread`, never zero. Under Blocked, name every team Triage item still older than 24 hours and the reason it remains, including a pending owner ask. Read Triage fresh for the report, not from the fleet-lane verifier's `triaged` log.
