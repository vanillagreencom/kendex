# Lane host

The `scripts/lane-host` command selects a provider from `ORCH_LANE_HOST`. `resolve` prints `local` when the setting is empty or unset. Any other value is an executable script path. Credentials do not select a provider. `open-terminal --host SPEC`, or this setting, launches a lane through `create`; `oversee-watch --hosted` reads a hosted lane's mailbox and workflow state through `cat` and closes the lane through `close`; `lane-mail --host` adds a line to a hosted mailbox through `append`.

## Provider protocol

| Verb | Arguments | Result |
|---|---|---|
| `create` | `--item ID --repo OWNER/REPO --harness claude\|codex\|pi --account CONFIG_DIR [--relaunch] [--reuse]` | One stdout line: `ssh-target=TARGET`, `path=WORKTREE`, `remote-prefix=PREFIX`, separated by literal tabs, plus `state=preparing` from a create that returns before its preparation ends. |
| `wait` | `--item ID` | Block until the preparation a `state=preparing` create accepted ends. Exit `0` when the item is ready; any other status is a failed preparation, its cause on stderr. |
| `cat` | `--item ID PATH` | Exact file bytes on stdout. A missing file exits `2`. Any other failure exits nonzero and not `2`, so a caller can tell an unwritten file from a read it could not make. |
| `put` | `--item ID PATH` | Write stdin to the file with private permissions, through a temporary file beside it that is renamed over the target once the whole transfer has arrived. A provider that crosses a network compares the bytes it staged against the count the sender declared before renaming, because a sender that dies mid-feed closes the stream and the receiver reads that as an ordinary end of input. A transfer that fails never replaces the file, and no reader meets a half-written one. No credential bytes in argv or diagnostics. |
| `append` | `--item ID PATH` | Append stdin to the file under a lock taken on the host that holds it, creating the file with private permissions when it is not there. The lock must be the one mechanism every writer of that file on that host takes, since two mechanisms do not exclude each other and a writer under each tears the other's bytes; a provider reaching a kendex checkout takes it through that checkout's `scripts/lib/file-lock.sh`. A last line with no newline is closed before the bytes are added, so a fragment an interrupted writer left never swallows the line that follows. Compare the bytes staged against the count the sender declared before any of them reach the file, because a sender that dies mid-feed closes the stream and the receiver reads that as an ordinary end of input. An append that fails adds nothing. No credential bytes in argv or diagnostics. |
| `touch` | `--item ID` | Keep the host alive, or probe a static host with no idle expiry. |
| `close` | `--item ID` | When kendex classifies every dirty path as a changed whole-file render, save their binary patch under the clone's `tmp`, restore them to `HEAD`, sync the base, and continue. This includes a deleted render recorded by the committed inventory. Build the untracked renders' half of that patch from an index the provider writes, never from a working-tree comparison: a comparison follows a render symlink into the directory it names and exits there with the same status it uses for a real difference, so the caller cannot tell the two apart and nothing is saved for a link a `kendex apply` inside the lane added. Read the patch back and restore or remove nothing unless it carries every path. Refuse a shared settings file, any other dirty path, a path the patch does not carry, and a render the provider's index cannot read, each with exit `3` and a stderr line holding `close-refused path=PATH` naming that checkout. Archive remaining `tmp` records before deletion and print `kept=PATH` on stdout. An archive or sync failure stops close. |
| `stop` | `--item ID --harness claude\|codex\|pi` | Stop the named harness processes whose current directory is the item's owned worktree. Print `stopped item=ID processes=COUNT`. An empty match is a successful stop with `processes=0`. A process that exits or becomes a zombie counts as stopped. A process-table or ownership read failure, a process that changes ownership before the signal, or a process that does not exit inside the provider bound fails the operation. Never paste a shell command into the lane pane. |
| `list` | none | Tab-separated repository/item, state, age, name for each configured host of this repository. State `available` marks a host holding no item. A provider can append fields. |
| `accounts` | none | Optional verb. One tab-separated `key=value` line per account the provider holds a credential for, carrying the usage windows read through that credential. `account=CONFIG_DIR`, the value `create --account` receives, and `harness=claude` or `harness=codex` are required. `status=`, `session-5h-pct=`, `weekly-pct=`, `model-pct=`, `model-label=`, `session-resets=`, `weekly-resets=` and `model-resets=` are optional; each percentage is a whole number from 0 to 100 and each reset is a timestamp. A provider can append fields. |

- `create` uses a durable repository/item identity. A retry or reuse reaches the same host. An existing owner returns `75`; `--relaunch` requests reuse. Other create failures produce `host-create-failed` through the dispatcher. No failure starts a local lane. The caller runs `create` for one host one at a time, so a provider reads, merges and writes shared host files during `create` without a lock.
- `create` may return once it has accepted the work, before its preparation ends. By then it holds the item's durable identity, so a second `create` exits `75` and a retry reaches the same host, and its line names the host and path the lane will use and adds `state=preparing`. The caller learns the outcome from `wait`. What a synchronous `create` owes by its return, the worktree, the launch record and the pre-approval below, an accepted one owes by `wait`'s success. A provider whose `create` returns only once its preparation ends prints no `state` and needs no `wait`. `open-terminal` under a fleet state then opens the item's window, records the lane `preparing` and moves on to the next item, handing `wait` and the rest of the launch to a background job whose outcome `oversee-watch` reports; with no fleet state, and for a hosted codex relaunch, it waits itself.
- The dispatcher passes all provider bytes and exit codes unchanged. Provider verbs under `local` refuse with `host-local` and exit `2`; the launcher owns local work. That is the same `2` a provider uses for a missing file, so a caller reading `cat`'s `2` as an unwritten file confirms the host with `touch` first: every dispatcher refusal fails that verb too.
- A file several machines write is appended, never put. `put` replaces the whole file, so a writer that wants to add a line reads it, adds the line and puts it back under a lock on its own disk; two machines doing that hold different locks, both read the same file, and the second put drops the first one's line with no error. `append` takes its lock where the file is, one mechanism that every writer of that file reaches. A provider that does not implement `append` fails the verb, and the caller refuses rather than falling back to a read and a put.
- `cat`, `put` and `append` on a path under `tmp/lane-mail/` refuse, with a status other than `2` and before reading or writing, when its `tmp/lane-mail` or item directory is a symlink or not a directory, or the file is a symlink or not a regular file; every other path is unaffected.
- The credential a hosted lane runs on is the copy the provider put on the host. `create` receives the account's config directory as `--account` on every call, `--relaunch` included. A provider that installs its own secret for that account leaves the two copies independent, and either can expire while the other works. A provider that re-seeds the host from that directory at every `create`, as the reference implementation does, puts the control machine's copy on the host again, on a relaunch as much as a fresh launch. The caller's `CLAUDE_CONFIG_DIR` environment prefix reaches the host in neither case. `accounts` is the only place a provider reports which accounts it holds, and no provider has to implement it. A provider without the verb exits `2` on it. The verb takes no path, so `2` there means only that the verb is absent, and the caller reads it as no answer rather than as a failure: `lanes list` reports the control machine's reading alone, with nothing on stderr, provider bytes included. Any other non-zero status is the verb failing, which `lanes list` reports as `host-accounts-unreadable` below the provider's own message.
- One reader inside `lanes` parses this verb, for `lanes list` and for `lanes host-accounts` alike, and `lanes host-accounts` is the form another program asks it through. That command prints one validated row per account as `config-dir` and `harness`, tab-separated and `@tsv`-escaped, or the whole records under `--json`, which is the exact form a caller comparing a config directory reads. Its exit status is `0` for an answer, `2` for an absent verb, and `1` for any failure to produce one: a failed verb, an unbounded read it declined to make, `ORCH_LANE_HOST=local`, or a render it could not finish. The keyed `lanes:` line names which. A caller decides what the host holds from that command, never from the provider's bytes.
- `TARGET` opens an SSH shell session. The caller then types `PREFIX 'cd WORKTREE && exec START_COMMAND'` with shell quoting. `PREFIX` belongs to the provider. The caller does not add the local `CLAUDE_CONFIG_DIR` environment prefix. The local account path remains the claim identity.
- The provider fetches or clones the repository and writes the remote clone's `.env.local`. A fresh clone receives the source clone's `.cache/linear` when present, excluding lock files. The provider runs `kendex update-pi --leave`, then `kendex refresh --yes --leave` when `kendex.toml` exists. It calls the installed worktree command to create the item with `--hosted`, adding `--reuse` for relaunch or reuse only when the item worktree exists. Before the first turn, the provider places the caller's per-harness pre-approval, such as folder trust and hook approval, where that harness reads it. A failed preparation remains a failed create, or a failed `wait` after an accepted one, and leaves what it made for `close`. A local Codex lane has no provider to do this, so `scripts/lib/lane-launch.sh` makes the same folder-trust record itself before the window opens: the account's own config where it already trusts the launch directory, otherwise a `CODEX_HOME` of that launch's own under the account, holding the account's files by link and a `config.toml` carrying the account's tables plus the directory's trust entry. The launchers name the route they took and refuse `launch-trust-missing` where the entry could not be made, rather than opening a pane on the folder-trust question. An account config already answering for that directory with anything other than trust is such a refusal: a recorded answer is honored, never overwritten.
- A hosted lane's worktree sits at one path per repository, the same in every lane: `<WORKTREE_BASE_DIR>/<WORKTREE_HOSTED_NAME>`, by default `<parent of clone>/.worktrees/<clone name>/lane`, which the clone's `worktree path --hosted` prints. sccache keys a Rust compile by its absolute source path, so only a path every lane shares lets one lane's build, or a warm snapshot's, answer another's. A provider that snapshots a warm build runs it at that path, as kendex's `tools/lane-setup` does under `FLEET_WARM=1`. The item-keyed path stays for local lanes, where several worktrees of one repository coexist. A reader finds the tree through `worktree path ITEM`, which follows the item's registered branch, or through the `path=` field `create` printed, never by composing the item-keyed spelling.
- `create` writes the lane's launch record: the lane's root in `lane-mail/<item in lower case>` under the clone's common git directory, and the lane's own `tmp/lane-mail/<item>`. `lane-mail-check` hands a lane its mail and judges its handoff marks only where that record stands. The included provider writes it by calling the clone's own `scripts/lane-marker`, which owns both halves and their containment. `open-terminal --host` verifies that record rather than trusting the provider: after `create`, or after `wait` for an accepted create, it reads the worktree's `.git` through `cat` for the clone's common git directory, writes the lane's root through `put` at the path `lane-marker --marker-path` names, and reads it back through `cat`. Each step that fails names itself and fails the item, which is then never reported as launched: a `.git` the host does not produce is `host-gitfile-unread`, a `.git` that does not name a linked worktree git directory is `host-gitfile-invalid` and carries the line it read, and a marker that could not be written or that does not read back holding that root is `marker-failed`. A relaunch runs the same steps. `put` creates the marker's parent directory. The marker is outside `tmp/lane-mail/`, so the mailbox guard does not cover it. The launcher writes that half only; the mailbox half is created on the host by the first `append` that reaches it.
- `.kendex-lock.json` is committed and arrives with the clone. A provider neither copies nor commits it by hand. This machine's half of the record, `.cache/kendex/lock-local.json`, is per host: a provider does not copy it.

## Codex hook approval

A provider that places Codex hook approval writes one `hooks.state` entry in the account's `config.toml` per `command` handler and per `mcp_tool` handler outside `session_end`; `prompt` and `agent` handlers, and `mcp_tool` handlers on `session_end`, get no entry. An entry whose `trusted_hash` differs from the value Codex computes leaves the hook unapproved.

| Item | Value |
|---|---|
| Key | `<hooks.json path>:<event label>:<group index>:<handler index>`; the event label is snake_case, such as `pre_tool_use`, not the hooks.json name `PreToolUse`; both indices are zero-based positions in hooks.json |
| Hash input | `{"event_name": <event label>, "matcher": <matcher>, "hooks": [<normalized handler>]}`, with every field still unset after normalization omitted; the normalized `timeout` is always present |
| Digest | `sha256:` followed by the SHA-256 hex of the hash input as compact JSON, keys sorted at every level |
| `command` handler | `{"type": "command", "command", "timeout", "async"}`, `async` as written |
| `mcp_tool` handler | `{"type": "mcp_tool", "server", "tool", "input", "timeout"}`, plus `statusMessage` when set |

- Timeout: `session_end` and `interrupt` hash the timeout clamped to 1..3, 1 when absent. Every other event hashes the timeout floored at 1, 600 when absent, so a timeout of 0 hashes as 1.
- Matcher: `user_prompt_submit`, `stop` and `interrupt` never hash a matcher, even when the group sets one. Every other event hashes the group's matcher as written, an empty string included.
- Extra fields: a `command` handler adds `statusMessage` when set, and `additionalContextLimit` only when it is set to a value other than 2500 on `pre_tool_use`, `post_tool_use`, `session_start`, `user_prompt_submit` or `subagent_start`. `commandWindows` never enters the hash.
- Key path: the path Codex builds, `<dir>/.codex/hooks.json`, made absolute without resolving symlinks. A linked Git worktree keys under the main checkout's `.codex/hooks.json`.

These rules mirror Codex 0.154.0: `codex-rs/hooks/src/engine/discovery.rs` `hook_hash`, `codex-rs/config/src/fingerprint.rs` `version_for_toml`, and `codex-rs/config/src/loader/mod.rs` for the worktree key. Check a later Codex release against those files, never against this section.

## Static SSH implementation

`scripts/lane-host-ssh --help` owns the inventory shape, source selection, account files and static-host lifecycle. The inventory binds each item to a target and clone before dispatch; it performs no automatic allocation. The host already has SSH access, Git, gh, Bash, kendex and the selected harness. The reference requires Python 3.8 or later on the control machine.

It implements no `accounts` verb. It copies the account's files from the control machine at every `create`, `--relaunch` included: `ACCOUNT/setup-token` for claude, `ACCOUNT/auth.json` for codex and pi. Those are not the files `lanes list` measures. A claude lane runs on `ACCOUNT/setup-token` while `lanes` measures `ACCOUNT/.credentials.json`; a codex lane runs on a copy of `ACCOUNT/auth.json` that diverges from the local file once either side renews. Its argument parser exits `2` on the unknown `accounts` verb, which is the absent-verb status above, so a launcher asking what this host holds gets no answer and judges the lane on the control machine's reading.

`stop` resolves the item through the installed worktree command. It uses the installed lane process owner to find only the named harness processes whose current directory is that worktree, checks the directory again before each signal, and waits for every signaled process to exit. `close` checks the clone and any remaining worktree for uncommitted files. It asks kendex for the changed whole-file renders, so a shared settings file or unrelated path refuses cleanup. It archives their remaining `tmp` records on the control machine and prints the saved path before delegating worktree removal to the installed worktree command. No remaining `tmp` means no archive and no `kept` line. A worktree already removed by lane cleanup does not prevent close, but its deleted records cannot be recovered. Close keeps the static machine, source clone and account files. `list` reports configured hosts, including available ones; static hosts have no age or expiry timer.

`tests/fixtures/lane-host` implements the same protocol with fixed output and a call log. Launcher and watcher suites can install it without SSH or a provider account.
