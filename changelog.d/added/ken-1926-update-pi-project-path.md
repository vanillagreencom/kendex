- `kendex update-pi` takes `--project-path PATH`, as `refresh` and `apply` do, registers the project it names after the update, and, like them, refuses a project write from a marked lane worktree or into another checkout unless `--lane-refresh` is passed; `kendex check` run in a linked worktree names it with the main checkout's path. A personal Pi package the named project already holds is not installed a second time by `update-pi` or by `refresh`, whether or not the project ends up on the projects list, since Pi would load it twice.
