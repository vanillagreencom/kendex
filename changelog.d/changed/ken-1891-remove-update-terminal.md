- `kendex remove`, `kendex update` and `kendex update-pi` now draw in a terminal like `refresh` and `apply`, with colour and a mark on each line for what it needs from you; a pipe, `NO_COLOR` and `TERM=dumb` still get plain lines. `kendex remove` asks about what nothing needs anymore with one key, `s` to remove it too or Enter to keep it, and the question names only what a yes removes, then counts and lists the changes it adds. A leftover the sweep keeps, such as one you edited, is not named. With no terminal and neither `--sweep` nor `--no-sweep`, `kendex remove --scope all` now stops before any scope is written, where before it wrote the scopes ahead of the one that needed the answer. It stops only where the sweep would change something: a leftover the sweep would keep anyway, such as one you edited, no longer needs either flag. In plain output, a `kendex remove` warning now prints as `refresh` prints it, naming the tool where it has one and adding a `  fix:` line where it has a fix. When `kendex update-pi` cannot save the install record for one place, it goes on to the other places, counts every package it installed in its closing line, still offers the commit, and then exits with the error. Before, it stopped at that place, with no closing count and no commit offer. A commit offer that fails is named beside the run's other failures, not in their place. A drift snapshot that will not derive is now a warning, as in `refresh`, not the run's error, so a run with no other failure exits 0. `kendex update-pi`'s plain warning that a project could not be registered now starts with `! warning: `. Where the locale is not UTF-8, `kendex update` prints `updating <old> -> <new>` with an ASCII arrow. In a terminal, the closing line of `kendex remove`, `refresh`, `apply` and `add` puts the project folder whole on its own line under the outcome. In a terminal, a file path in a line kendex writes itself no longer splits across lines: a path that does not fit starts a new line and stays whole, so you can copy it, for example the folders `kendex update-pi` names when Pi loads a second copy of a package; an error's own text, another program's lines, such as diff lines, and the settings file `kendex project settings` names after `from` still break where they meet the edge of the terminal.
