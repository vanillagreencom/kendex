- `kendex apply` and `kendex refresh` name `update-pi` for every declared Pi package whose installed copy or install record does not match its declaration, which their own write does not install and which Pi does not already load from the other scope: `settle-with=update-pi scope=project` (or `scope=global`) beside the packages and, where nothing else is left and `update-pi` can read every declared package, `finish-with=update-pi` with the same scope on the closing line, each with the project when `--project-path` named it. A package `refresh` leaves for `update-pi` because its install runs a process is named the same way, and the refresh still exits clean. Before, `apply` and such a `refresh` closed the scope as up to date. A declared package neither the run's write nor `update-pi` settles (one Pi already loads from the other scope, one whose install record names another source, one whose source would not resolve, one whose copy or record would not compare) is listed under `left unsettled` with why, the run does not close as up to date, and neither `update-pi` nor the take-over is named as the scope's finish beside it. While a package is left for `update-pi`, the take-over is not named as the scope's finish either, since it does not install it. A Pi extension filter the same run writes is settled by that run: it does not hold back `finish-with=update-pi`, and `kendex refresh` no longer reports it as a failure after writing it. `kendex check`, and the session hook that runs it, draws one line for each declared Pi package from the same answer `apply` reads, judged as `check` runs and never from the last `kendex updates` evaluation: `update-pi` where `apply` leaves the package for it, and the reason with no fix where neither settles it. So `check` comes out clean only where `apply` leaves no Pi package, and after the person removes the copy Pi loaded from the other scope, restores a source, or moves a pin, it names `update-pi` at once. A muted update no longer silences that line; the mute still hides the update in `kendex updates` and the app, and a pin is the way to hold a package. `kendex updates` warns about a package `update-pi` leaves instead of offering it as an update.

  You do: to keep a muted Pi package at the version it has, run `kendex pin pi-extension <name> <version>` instead of relying on the mute.
