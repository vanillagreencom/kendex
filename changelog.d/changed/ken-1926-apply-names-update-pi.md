- `kendex apply` and `kendex refresh` name `update-pi` for every declared Pi package whose installed copy or install record does not match its declaration, which their own write does not install and which Pi does not already load from the other scope: `settle-with=update-pi scope=project` (or `scope=global`) beside the packages and, where nothing else is left and `update-pi` can read every declared package, `finish-with=update-pi` with the same scope on the closing line, each with the project when `--project-path` named it. A package `refresh` leaves for `update-pi` because its install runs a process is named the same way, and the refresh still exits clean. Before, `apply` and such a `refresh` closed the scope as up to date. A declared package neither the run's write nor `update-pi` settles (one Pi already loads from the other scope, one whose install record names another source, one whose source would not resolve, one whose copy or record would not compare) is listed under `left unsettled` with why, the run does not close as up to date, and neither `update-pi` nor the take-over is named as the scope's finish beside it. While a package is left for `update-pi`, the take-over is not named as the scope's finish either, since it does not install it. A Pi extension filter the same run writes is settled by that run: it does not hold back `finish-with=update-pi`, and `kendex refresh` no longer reports it as a failure after writing it. `kendex check` names `update-pi` only for a package `update-pi` installs, and gives a package it leaves its reason with no fix.
