- Removal now uses recorded dependency ancestry to keep the same items removed when a catalog is unavailable, including dependencies of hooks withheld from a tool. Lock version 11 gains optional `requirerProvenance` facts. Older writers discard them, and older verification can reject the new serialization. Removal refuses when a legacy or rewritten record lacks the ancestry needed to decide whether a requirer stays, and when a set carries an item declared from another catalog while the set's catalog cannot be read: a local folder catalog records no reading of its sets, so only reading the set can decide it.

  You do: if removal reports missing provenance, apply with the catalog readable using a build that records requirer provenance, then retry removal. If it reports a set's reading missing, retry the removal while that set's catalog is readable.
