- Removal now uses recorded dependency ancestry to keep the same items removed when a catalog is unavailable, including dependencies of hooks withheld from a tool. Lock version 11 gains optional `requirerProvenance` facts. Older writers discard them, and older verification can reject the new serialization. Removal refuses when a legacy or rewritten record lacks the ancestry needed to decide whether a requirer stays, and when a set carries an item declared from another catalog and the record holds no reading of that set, as is always so for a local folder catalog's set.

  You do: if removal reports missing provenance, apply with the catalog readable using a build that records requirer provenance and retry, and if it reports a set's reading missing, retry while that set's catalog is readable and still carries the item, or remove the set with it.
