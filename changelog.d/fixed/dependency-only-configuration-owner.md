- A review-file package that arrives only because another package requires it no longer takes the repository's review files over from an armed bot-instructions. bot-instructions keeps rendering and checking them, so `kendex verify` and the commit offer still catch drift, and `kendex apply` and `kendex refresh` name the pending setup. An add or apply without `--allow-repo-effects` that installs the new package while bot-instructions stays in charge commits nothing and names that setup, in a main checkout, a linked work tree and a fresh repository alike, so a yes to the setup after the commit offer no longer leaves the review files changed after a reported commit. That run names one step, the new package's setup: a linked work tree no longer asks to set bot-instructions up there first, and bot-instructions is not named as a second package to set up. Where the manifest has no `[bot-instructions]` table, the new package renders nothing, so the add or apply commits. A table added to `kendex.toml` but left out of the commit still holds it when the add or apply can set the package up after its commit offer. Set the new package up on its package page, or add the requiring package, or apply a hand-written declaration of it, with `--allow-repo-effects`, to move the files to it. That add or apply runs the setup once, before its commit offer, so its commit carries the new package's files, and the offer still sets up any other package it brings that holds the commit. Where it brings bot-instructions too, only the new package is set up, and a setup that fails is not run again at the commit offer.
