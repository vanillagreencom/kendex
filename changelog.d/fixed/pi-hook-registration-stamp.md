- Every Pi hook kendex installs names its install, project or global, to a pi-hooks carrier older than 0.19.3, which names none. `ui-copy-note` reads its skills from that install today. Where `PI_CODING_AGENT_DIR` points at a project's `.pi`, one hook file is both installs, and such a carrier cannot say which one started it. In that project a hook that needs its install's skills then refuses under `kendex-hook-scope-overlap` and names pi-hooks 0.19.3. An advisory hook reports the same key and lets the call through, and a hook that reads no install runs as before.

  You do: if a Pi hook refuses under `kendex-hook-scope-overlap`, update pi-hooks to 0.19.3 or later, or point `PI_CODING_AGENT_DIR` at a directory outside the project.
