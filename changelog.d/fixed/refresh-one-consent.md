- `kendex refresh` asks once about a Pi package update and the writes after it: the question lists every change it counts, the run asks again only about a change it did not list, the closing line names the changes it made, and a write stays reported when a later step fails. In the app, an update, removal, apply, fork or "Manage these files" whose step after the write fails no longer reports the write as refused. The commit offer now draws a blocked state as a failure in the terminal and the app, and the app offers the same commit choices as the terminal, each naming the branch or pull request it changes.
