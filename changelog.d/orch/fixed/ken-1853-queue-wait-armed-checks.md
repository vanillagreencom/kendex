- `queue-wait` now names an armed PR that GitHub has not yet enqueued. While ci-wait reads its checks as pending, the verdict is `armed_awaiting_checks` with the pending check names, and merge-pr waits again on the same head under a `QUEUE_WAIT_ARMED_MINUTES` wall-clock budget (default 90) without spending a ci-fix recovery cycle. `armed_blocked` covers a failed check, which takes the recovery cycle, and every check passed with still no queue entry, which returns to a fresh readiness check. `progress_unobservable` now means only that a queue entry exists and its head could not be read.
