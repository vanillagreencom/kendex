# crates/app/

Tauri commands over `kendex-core`, one module per page domain. A command reads, invokes core and answers; no domain logic lives here.

- A command that touches disk, git or a subprocess is `#[tauri::command(async)]`; only window operations stay synchronous. Not mechanically enforced.
- The command surface, the constants the UI reads and the runtime every `Result`-returning command answers through are declared in `specta_builder` (`src/lib.rs`); `ui/src/bindings.ts` is regenerated with `cargo test -p kendex-app -- --ignored regenerate_bindings` and byte-checked by `tests/bindings.rs`.
- Two raw spawns are sanctioned and exempt from the process constructor: the self re-exec in `src/launch_env.rs` and the detached editor launch in `src/native.rs`; anything else goes through core's `process::Hardened`.
- A whole-file write carries the `Base` its copy was read at and answers different bytes on disk with a refusal, never a silent overwrite. Two take that check here, in `src/whole_file.rs`, and answer `WriteRefused`: the Customize tab's manifest and the Settings page's app settings. The third is the project's private env file, which this crate never composes or writes: the Customize save forwards the draft with the `Base` the credential rows were read at, core's plan carries that as the op's own precondition, and a file that moved since answers `Moved` or `PlanStale` from there.
- A command answering `SourceReadRefused` from `src/refusal.rs` hands the page a source nothing has downloaded yet as its own kind instead of words. Its single `From<CoreError>` is the one place `CoreError::SourcePending` is told apart from a real failure, so a second match on that error in a command module is a twin. Every command that opens a source's content answers it, so no page reads a never-downloaded source out of a `String`; `git grep -n SourceReadRefused crates/app/src` is which. Its serde kind strings (`source-pending`, `failed`) are the wire contract the UI branches on, so renaming one is a bindings change. The mapping is enforced by `src/refusal.rs` `tests::an_undownloaded_source_is_its_own_shape`; which commands answer it is not.
- The window opens hidden and is shown in `setup` once the saved zoom is applied. Enforced by `tests/tauri_config.rs::the_settings_the_window_and_the_release_path_lean_on` for the hidden window; that the zoom range is a core constant reaching the UI through the bindings and that the close is never held for an in-flight settings write are not mechanically enforced.
- The launch environment is decided once, before GTK starts and before the first subprocess, by relaunching (`src/launch_env.rs`): on Linux the display environment, where `KENDEX_GDK_BACKEND` is honoured on any session and never overridden; on macOS the login shell's `PATH` in place of the one launchd hands a Finder launch, so every program kendex runs is the one a terminal would find. Enforced by the tests in `src/launch_env/tests.rs`.
- A `kendex://` link is parsed in `src/deep_link.rs` and reaches the page either held until the page's first `deep_link_take` or, after that, as the `DeepLinkOpened` event; the scheme it accepts is the one `tauri.conf.json` declares. On Linux the handler file is kendex's own (`src/deep_link/linux.rs`), with a bare `Exec=` path because `xdg-open` runs no quoted one. Enforced by the tests in `src/deep_link/tests.rs`, `src/deep_link/linux.rs` and `tests/tauri_config.rs::the_settings_the_window_and_the_release_path_lean_on`; that a link never writes a subscription is not mechanically enforced.
- Launch recovery rolls back pending journals in every registered project. Enforced by `tests/recovery.rs::launch_recovery_rolls_back_pending_journals_in_registered_projects`; that it runs under the scope lock is not mechanically enforced.
