# crates/cli/

Thin verbs over `kendex-core`: a verb parses, calls core and prints. No domain logic lives here.

- Every human line leaves through `src/ui.rs`, escaped there; a payload is not, and stdout stays clean. A converted verb draws with the components in § Output; a verb not yet converted uses the framed calls, where `ui::intro` arms the framing and a verb that opened no frame prints the plain lines scripts parse. Framing needs a terminal on both streams; `KENDEX_UI=plain|pretty` overrides. Enforced by `tests/presentation/`; the `cli-raw-output` lane of `tools/guard` refuses an escape sequence or a stdout/stderr handle under `src/` outside `src/ui`, and clippy's `print_stdout` and `print_stderr` refuse `println!` and `eprintln!`.
- Non-interactive is a mode, not a fallback: every verb completes without a TTY, selection flags suppress prompts, and a verb needing input fails naming the flag before its first write.
- A writing run closes on the outcome ledger (`src/commands/ledger.rs`): wrote, skipped, flagged, and a next step under each nonzero part; a run that scored something adds `safety: clean` when nothing was flagged and every item was read in full, or `not fully checked on safety: N item(s)` where a rule had no bytes to read; `refresh` adds `details folded` where its compact report left out lines a verbose run draws, with `--verbose` as that part's next step, a hint that leaves a clean run's outcome done.
- No verb emits a pasteable command line; errors, hints and recovery present the verb and its parameters as data, enforced by `tests/unmanaged_exits/refusals.rs::a_shape_with_no_way_to_keep_the_files_is_told_to_move_them` (the row for a link no declared tool sits at). Three exceptions: the session-start drift report, whose remedies come from the fixed template set in `crates/core/src/drift/report/`; the notice a retired item gets (`crates/core/src/engine/desired.rs::retired`), an owner ruling; and the commit offer's git and gh lines for a step it leaves to the person (`src/commands/commit_offer/block.rs`), pinned by `tests/commit_offer_cli.rs::the_branch_rules_are_read_before_a_push_and_a_refusal_under_them_names_the_way_on`.
- `add`, its collection form included, settles its destination through `commands::install_destination` — the walk up, else the folder the command was typed in, asked for first and never the home directory — and registers it through `commands::project::register_destination` on the strength of what landed, so the app sees the project without a second command. `template install` registers through the same call, its destination being the `--project` path it was given rather than a walk up; `project add --template` performs `template install`'s run and registers through it, so a refused template leaves no registry entry; and `bookmark install` performs `add`'s own run into that same given destination through `commands::add::run_into`. `adopt` resolves through `resolve_scopes` and registers nothing, and a global install registers nothing. `refresh`, `apply` and `updates` take `--project-path PATH`, which resolves through `commands::resolve_scopes_at` instead of the walk; that resolution validates the root and registers nothing. The three verbs register the named project after the write through `commands::project::register_target`, which is `register_destination` behind the `--project-path` that named it and whose docstring owns the one rule for when a named run registers and when it leaves the list alone. Every registering verb asks `commands::project::registrable` before its first write, which refuses a folder under a temporary path with a `temporary-project=<path>` first line unless `--throwaway` is passed; the named-target verbs ask it through `commands::project::target_registrable`, and `ThrowawayFlag` rides in `flags::ProjectTargetFlag` beside the path it answers for.
- `add`, its collection and bookmark forms included, and `apply` exit 3 in a run with no terminal on stdin that skipped on conflict, for any cause but the person's own edits, an item it was asked for: one named, a member of a set named, for `apply` one the manifest declares, or a package one of those requires (`EngineReport::asked_for`). Each is one `skipped-on-conflict=<kind> <name>` line on stderr. The rest of the plan is written, the manifest included, so `apply --replace-unmanaged` installs the skipped items afterwards. A run at a terminal, a skip of nothing asked for, a package its catalog retired, and a refusal that already exits nonzero keep their status. Enforced by `tests/skipped_on_conflict.rs`; the collection form by `tests/collection_cli.rs::a_member_skipped_on_conflict_ends_the_run_on_its_own_status`, and a refused commit's 1 by `tests/commit_offer_cli.rs::a_refused_commit_keeps_its_status_over_a_skip`.
- `kendex check` exits 0 clean, 1 drift or unevaluated, 2 could not check; unknown outranks drift. `--report-only`, which every session-start hook passes, never writes a project's committed install record; without it the check records a proven render only where `lock::branch` allows (D007). Enforced by `tests/unmanaged_copy_check.rs::a_session_start_writes_nothing_git_sees`.
- A new test file is a `mod` line of `tests/main.rs`, the `integration` target. A new `[[test]]` target in `Cargo.toml` is also named in one macOS cargo leg of `../../.github/workflows/skill-tests.yml`, which runs this crate's targets as two legs rather than one; `../../tools/tests/orch-shard-partition.test.sh` refuses a target no leg names.

## Output

A converted verb builds every human line from the components on `ui::Style` and prints them with `ui::stdout` (what another program composes with) or `ui::stderr` (what a person reads about the run); it never formats a line itself. The one exception is `check --quiet`, the session hook's bounded report, which core spells. `ui::channel(json)` picks the rendering. [OUTPUT.md](OUTPUT.md) is the reference: renderings, tokens, symbols and components. `src/commands/check.rs` is the pilot; `list`, `show`, `updates`, `verify` and `diff` are converted.
