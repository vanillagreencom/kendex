# crates/core/

Pure domain logic over the filesystem and git: no Tauri, no IPC, no UI concern, and no dependency on `crates/app`, `crates/cli` or `ui/`. The invariants and their enforcers are `docs/architecture/overview.md` § Invariants and the topic files beside it.

- One constructor builds every external process (`src/process/mod.rs`); a raw `Command::new` outside that module fails a `tools/guard` lane.
- `unsafe` lives in two places in the workspace: `src/fs/dacl.rs`, the Win32 security-descriptor calls behind the private credential file's owner-only access-control list, and the `acl` module of `src/fs/tests.rs` that reads such a list back. Neither has a safe binding. Each function allows `unsafe_code` per item with a reason; the workspace lint denies it everywhere else, and review, not a guard lane, holds the boundary at those two files.
- Every catalog read goes through `source_read::SealedSource`; a raw filesystem read in a catalog-reading module fails a `tools/guard` lane.
- Every root hangs off `Env::home` (`src/env.rs`); a debug build roots at `<data>/kendex-dev` and only `KENDEX_REAL_HOME=1` opts out (`src/env/sandbox.rs`).
- A path is canonicalized on entry through `paths::canonical` (`src/paths.rs`) and never re-spelled; no comparison meets two spellings of one root. Matching a registry entry whose folder has moved is the one exception, and `settings::recorded_entry` is the only place that makes it: `paths::as_written` makes a path absolute by spelling alone and folds nothing, for the entry recorded under exactly that spelling, and `paths::absolute` resolves what is still there before it folds what is left, for the aliases a person types and for the settings location `settings::refuse_temporary` judges before the file exists. Neither is used anywhere else.
- A test that needs a host path reads it from `Env` (`host_rooted`, `drift_dir`), never composes the platform path.
- A test's temporary root takes its canonical spelling on the next source line through `rooted()` in `crates/test_util.rs`; a `tools/guard` lane checks new fixtures.
- A test that shells out to git clears `GIT_DIR`, `GIT_COMMON_DIR`, `GIT_WORK_TREE` and `GIT_INDEX_FILE` together.
- A project-scope write typed inside a linked git worktree is refused by `hooks/block-worktree-refresh.sh`, a catalog hook a session opts into, except the verbs that write one project by being typed inside it where that project owns its manifest; no kendex code refuses it. The hook and `drift::report::remedy_target` ask one predicate of the same place: the project root `discover::project_root_from` resolves from the working directory, inside the worktree, owns its manifest when its `manifest::project_manifest_path` file exists there, readable or not. The hook spells discover's markers in Bash and reads any kendex.toml naming `is_source_catalog` as a catalog, a superset of core's rule that refuses where it misreads, and `hooks/tests/block-worktree-refresh.test.sh` plants each marker `discover.rs` lists. core marks the remedies for every worktree reader regardless, because a report cannot see which sessions run that hook and naming the project is the spelling that is right either way. So `drift::report` resolves one destination for every project remedy in a check — the checked project (`ProjectTarget::Worktree`) where it owns its manifest; the project at the same place under the main checkout `guard::Repo::main_checkout` names where it carries none; and none at all where the main checkout holds no project root there, which leaves the remedies in their bare spelling — and `Remedy::render` puts a resolved one in the command as `--project-path` when the native path has an exact UTF-8 command spelling, leaves that row without a command otherwise, or, for the verbs with no such flag, returns `Fix::Here` where the destination is the worktree itself (`ProjectTarget::Worktree`) and the verb writes where it is typed, and `Fix::Elsewhere` otherwise, so the reader keeps the command and is told why it will not run here. It is resolved after the lines are in and only where one carries a project remedy, so a clean check spawns no git child. Enforced by `tests/drift_worktree_remedy.rs`.
- `Op` writes its own `Debug` (`src/apply/op.rs`) so `WritePrivateFile` renders a byte count instead of the credential it carries; a `Plan` reaches assertion messages and panics, so restoring `#[derive(Debug)]` would put a person's API key in whatever formats one. Enforced by `tests/secret_storage.rs::a_plan_carrying_a_credential_never_renders_it`.
- Where a hook lands is decided about the declaration the plan writes: the dependency walk reads each companion from that declaration's catalog (`src/engine/deps.rs::wanted_by`), a withholding is one `Landing` (`src/engine/desired.rs`) carrying that declaration's provenance, and `src/engine/desired_kinds.rs::not_written` and `src/engine/plan_pass.rs::plan_withheld` ask that identity. A withheld hook's installed copy comes out behind invariant 4, `src/engine/item_plan.rs::rebound`, the only place a recorded source is told from a planned one; `src/engine/removal.rs` compares no sources. Enforced by `tests/dependencies/two_catalogs.rs`.
