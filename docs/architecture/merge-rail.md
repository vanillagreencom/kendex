# CI and merge rail

Covers: .github/workflows/, .github/actions/, .github/consumer-refresh-repos.txt, tools/consumer-refresh, tools/lock-record, skills/harness-ci/, skills/review-gate/, skills/orch/workflows/merge-pr.md, skills/github/scripts/commands/pr-merge.sh

Each repository owns its pull requests and refresh workflow. The classifier determines the change class. CI selects its jobs from that class. GitHub enforces approval and review-thread requirements. The lanes app can merge a green pull request past the queue only when the pull request is not queue-only and the base queue is empty. [D016](../decisions/D016-merge-route-reads-bypass.md) owns this route and amends [D013](../decisions/D013-admin-merge-green-prs.md). The queue merges the rest. Consumers pull kendex updates in their own GitHub Actions runners, per [D003](../decisions/D003-one-merge-path.md).

The classifier returns `change_class`, `harness_only` and `docs_only`. It derives `queue_only` from the `queue` rows in `skills/orch/references/narrow-change.conf` and `HARNESS_CI_QUEUE_PATHS`. `.github/actions/change-class` publishes the class, path families, `lanes` and per-lane verdicts; it does not classify. Its `proof` reuses a passing same-workflow, same-tree run: a merge group reads its pull request's record, and the queue's push reads the merge group's. It stands down covered lanes under invariant 6 and uploads this run's record. [Proof reuse](../../skills/harness-ci/references/wiring.md#proof-reuse) owns the rules. `tools/ci-job-set` selects `skill-tests.yml` lanes and shard runners from the class, changed paths through `tools/rust-reads`, and event, minus proven work. `tools/ci-aggregate` holds required contexts to those selections. `CI` holds the older aggregators' lanes plus Preflight and Markdown; those aggregators keep their required-context names. Locally, `dev-validate-run` classifies through `skills/orch/scripts/lib/change-class.sh` and exports the class, docs verdict and changed paths to `DEV_VALIDATE_CMD`. `tools/guard --full` passes them to `tools/ci-job-set`, as the `changes` job does. CI reads the shipped classifier from its trusted checkout. The classifier proves `render` in a private checkout of the range's head. For local validation, that head is a worktree snapshot, including uncommitted render edits. CI classifies the branch again, so a wrong local class can fail CI.

## Boundaries

- `harness-ci` writes nothing under `.github/`, so the repository wires the classifying step itself, from one of the four shapes or the CI template in [../../skills/harness-ci/references/wiring.md](../../skills/harness-ci/references/wiring.md). That the package writes no workflow is stated in [../../skills/harness-ci/SKILL.md](../../skills/harness-ci/SKILL.md) § This package never edits a workflow, and is not mechanically enforced. `skills/harness-ci/tests/wiring-shapes.test.sh` proves only that each shipped shape keeps its expression, ordering and script path, and `skills/harness-ci/tests/ci-template.test.sh` that the template's `CI` job needs every other job and that both events read each lane's verdict the same way.
- `kendex refresh` renders skill copies and settings. Workflow adoption owns files under `.github/workflows/`. Adoption records each verbatim workflow copy in `.kendex-generated.json` with its template hash. `kendex verify` checks equality against that template. A changed workflow copy cannot qualify as a render. Only exact templates in the authoritative kendex default-branch ancestry license refresh-workflow replacement. Consumer history and inventory hashes supply no permission. The adopter refuses edits before retired-writer removal and rechecks bytes before replacement. The runner refuses held render edits before adoption or publication. `skills/review-gate/tests/adopt-refresh.test.sh` and `refresh-consumer.test.sh` check those boundaries. [Review-gate adoption](../../skills/review-gate/references/adoption.md) defines setup and updates.
- Consumer refresh calls the release-installed orch's `ol_preference_entries` when orch is present, and lists committed `[env]` values naming Fable or Astra as `deprecated_models`. The parser runs under `env -i` with only `PATH` and `HOME`; the default-branch runner checks its stdout shape. Settings files are parsed, never sourced. `refresh-report.py --settings` formats the three arrays and parses nothing; `deprecated_models` is a warning that changes no exit or publication. Extraction failure stops publication and auto-merge. Held by `skills/review-gate/tests/refresh-consumer.test.sh` and `refresh-report.test.sh`.
- `refresh-consumer.sh` owns the engine-version line in its rolling pull request body and current-run summary. It reads `kendex --version`, not the installer's selected release tag. `skills/review-gate/tests/refresh-consumer.test.sh` checks both destinations and refusal on a failed version read.
- `skills/review-gate/scripts/validate-standard.sh` checks, read-only, a repository's GitHub settings. Its rule rows check part of [review-gate-platform.md § Target](../plans/review-gate-platform.md#target), not each context's app binding, and its `standard-bypass-actors` row checks [D016](../decisions/D016-merge-route-reads-bypass.md) item 3. Its environment rows check [D003](../decisions/D003-one-merge-path.md) item 2. Its `--help` lists each row and where its values come from. The owner-run `provision-environment.sh` creates the environment and secrets.
- The merge route is chosen in one place, `skills/github/scripts/commands/pr-merge.sh` (`merge_route`), per [D016](../decisions/D016-merge-route-reads-bypass.md) item 1. The lane's immediate `pr-merge` on its exact head, [merge-pr.md](../../skills/orch/workflows/merge-pr.md) § 5 step 1, passes `--admin` only where the queue is all it would skip, by the reads `pr-merge --help` § Merge route names. The early arm of [submit-pr.md](../../skills/orch/workflows/submit-pr.md) § 2 step 5, `--auto`, arms only under the approval rules that step names and only where the same route takes the queue; `--auto` never passes `--admin`. Every arm reads that route and refuses admin unless `--queue` explicitly requests the queue. The lane owns the approved-head CI wait and records the attempt's route in its status file and PR body; [merge-pr.md](../../skills/orch/workflows/merge-pr.md) § 5 step 1 owns those steps. Enforced by the route, merge-queue, approval-gate and retired-flag rows of `skills/github/tests/pr-merge.test.sh` and the `queue` rows of `skills/harness-ci/tests/narrow-change.test.sh`. The bypass actors are GitHub configuration the owner holds.

## Invariants

A refused consumer-refresh push defers only after GitHub reports the rolling pull request queued, armed, merged or closed, or a previously observed branch deleted. A failed or incomplete state read remains a failure. `skills/review-gate/tests/refresh-consumer.test.sh` holds the post-refusal ordering and publication boundary.

1. Every case the classifier cannot prove answers `false`, which authorizes no classifier-based skip. Enforced by `skills/harness-ci/tests/fail-closed.test.sh`. A `false` verdict does not mean every lane runs: in the two-gate shape a lane's own path-family predicate still applies. The verdict is not read from the diff alone either. Docs mode reads the changed paths; harness mode also reads `.kendex-generated.json` at both endpoints.
2. Every required context reports on every event the ruleset requires it on. The classifying job sits inside the workflow, never in an `on.<event>.paths` filter, and the job carrying the required name runs unconditionally. Both are repository wiring rules, stated in [wiring.md](../../skills/harness-ci/references/wiring.md#shape-3--merge-queues-where-the-required-context-must-report) and not mechanically enforced. The snippets `skills/harness-ci/tests/wiring-shapes.test.sh` reads carry no trigger block, so that test checks expression closure, script paths, options, endpoint ordering, lane conditions and indentation only. `skills/harness-ci/tests/ci-template.test.sh` holds the CI template to both triggers and to a `CI` job that runs whatever its needs did.
3. `aggregate-needs` accepts a skipped job only where the classifier succeeded and either its waiver is `true` with the job in the caller's skippable set, or the job's own lane verdict is `false`, so a lane that skipped for any other reason reds the required context. Enforced by `skills/harness-ci/tests/aggregate-needs.test.sh`, with a must-fail control per rule.
4. The classifier a merge trusts is the default branch's copy, never the pull request's. Held for the classifier scripts: the `changes` job of `skill-tests.yml` reads `skills/harness-ci/scripts` and orch's measurement contract from a separate default-branch checkout, through the action's `classifier` input. The action wrapper, `tools/ci-job-set`, `tools/ci-aggregate` and `tools/rust-reads` still run from the pull request's tree; review holds them, and `tools/ci-job-set` runs every lane for a change to one of them. Held for the classifier's own measurement settings: `change-class` reads `ORCH_SIZE_*` and `HARNESS_CI_TRIVIAL_*` from its environment, else from the `[env]` tables the commit `--base` names holds, and `HARNESS_CI_QUEUE_PATHS` from those tables alone, the pull request's base tip or a merge group's base and never the merge base, parsed and never sourced, and a pull request that changes a settings file classifies `standard`. The package's own source repository is the standing exception, because its checker and its candidate are the same commit, per [../../skills/bot-instructions/SKILL.md](../../skills/bot-instructions/SKILL.md) § A pull request changing its own review.
5. Orch does not map classes to policy. Its `approval-wait` requires consumer-base context before reading policy or native approval rules, per [Gate-mode routing](../../skills/orch/references/gates.md#gate-mode-routing). `off` disables Kendex requests and waits, not GitHub approval requirements. [micro.md](../../skills/orch/workflows/micro.md) § 4 reads the class through `item-tier` and admits only `approval` mode, since it runs no internal review. `skills/orch/tests/approval_wait.sh` enforces required context; `skills/orch/tests/workflow_helpers.sh` holds the caller contract. Orch's class-to-policy boundary is not mechanically enforced.
6. A proof stands down only what a completed, successful run of the same workflow on the same tree recorded, and of that only the lanes the workflow says do the same work on every event: all of them under `covers-all-lanes` with no declaration, or each lane its declaration marks `:event-uniform`. The run reading the record judges the mark, and the run writing it records what passed: in `tools/tests/change-class-action.test.sh` the row `lanes-decl-gated` holds a covered unmarked lane running, and `pr-decl-gated` holds an unmarked lane a run ran recorded as covered. Every refusal answers `reuse=false` with a reason and runs the lanes. Enforced by `tools/tests/change-class-proof.test.sh`, a must-fail control per rule, and `tools/tests/change-class-action.test.sh`, which holds what a record stands down and what a run records.

## Consumer replay boundary

The snapshot collector reads committed blobs and platform environment metadata, not consumer runtime output. Its main-only App credential never reaches captured code. The secret-free PR job runs the consumer's own preserved refresh scripts in a disposable checkout. It redirects catalog reads to the proposed catalog and publication to a local bare repository plus the existing GitHub API fixture. The replay owns all scratch Git repositories and keeps their automatic maintenance in the foreground until cleanup. It delegates refresh, adoption and verification to the committed scripts and the released CLI; it does not implement those decisions again. `tools/lock-record` owns snapshot rolling-PR publication as well as install-record publication. `tools/tests/consumer-snapshots.test.sh`, `tools/tests/consumer-refresh.test.sh` and `tools/tests/lock-record-snapshot.test.sh` hold these boundaries. [Consumer refresh gate](../plans/ken-2416-refresh-runs.md#consumer-refresh-gate) owns bootstrap authority and deployment order.

## Decisions

- Classify inside a job, never in `on.<event>.paths`. A path filter stops the workflow from starting, the required context is never created, and a merge queue waits forever on a check nothing will report.
- Fail closed everywhere. An empty diff, an unresolvable endpoint and an absent render inventory all answer `false`, which authorizes no skip the verdict would otherwise have allowed.
- Consumer refresh follows [D003](../decisions/D003-one-merge-path.md). `.github/workflows/kendex-dispatch.yml` sends an event. Each consumer's workflow runs `skills/review-gate/scripts/refresh-consumer.sh`, which owns its refresh branch and pull request. `skills/review-gate/tests/refresh-consumer.test.sh` checks this behavior. Consumer secrets stay in that repository's `kendex` environment. The catalog is excluded under [D007](../decisions/D007-lock-record-on-main.md). `adopt-refresh.test.sh` and `dispatch-refresh.test.sh` exercise that exclusion. The overseer takes no part in automatic refresh. Existing consumers first use the [trusted removal PR](../../skills/review-gate/references/adoption.md#trusted-removal-for-an-existing-consumer); its normally reviewed merge establishes the default-branch scripts that automatic refresh executes.
- Platform review requirements and the overseer fallback follow [D018](../decisions/D018-platform-review-requirements.md).
- Two merge routes, per [D013](../decisions/D013-admin-merge-green-prs.md) and [D016](../decisions/D016-merge-route-reads-bypass.md). The owner-credential merge, `--force` and `ORCH_MERGE_BYPASS` of [D003](../decisions/D003-one-merge-path.md) stay retired.
- The install record is recorded on `main` after each merge by `.github/workflows/lock-record.yml` and landed through one rolling pull request, never on a branch, per [D007](../decisions/D007-lock-record-on-main.md); no pull request check judges it.
