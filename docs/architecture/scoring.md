# Safety and quality scoring

Covers: crates/core/src/quality/, crates/core/src/engine/scoring.rs, crates/core/src/source/browse/safety.rs

Two advisory scores over an item's own bytes: safety answers "is this dangerous", quality answers "is this well made". `quality::AuditResult` (safety, quality, findings, skipped, ruleset) is the one shape every scored surface embeds, and the bound shapes flatten it so the UI reads fields at top level.

## Boundaries

- Rules read typed per-kind inputs and say when they cannot read: a skill carries its whole tree, a hook its registration and script, an MCP server its command, args, env and headers, a plugin its manifest and lifecycle scripts; a rule whose bytes are not in the input reports itself not applicable. Enforced by `crates/core/tests/quality/kinds.rs` and `crates/core/tests/quality/reading.rs`.
- The outcome is a function of exactly kind, path and name (`quality::observe::same_reading`), plus the harness for a hook in a shared config file whose parser is the harness's; no rule reads the harness. Not mechanically enforced beyond the signature.

## Invariants

1. Neither score holds anything back: severity is named in words, never colour-only, and install, update and apply proceed regardless. Enforced by `crates/core/tests/authoring_check.rs::a_safety_finding_is_reported_and_fails_nothing` for the check and `crates/core/tests/quality/advisory.rs::a_critical_finding_is_reported_and_installs_anyway` for the install.
2. Safety is `100 − Σ deductions` (Critical 25, High 15, Medium 8, Low 3), first hit per rule at full weight, repeats a point each up to as much again. Enforced by `crates/core/tests/quality/scoring.rs`.
3. A matched token never appears in any message, log or record, only a fingerprint. Enforced by `crates/core/tests/quality/scoring.rs::a_secret_finding_never_repeats_the_token` and `crates/core/tests/quality/rules.rs::an_mcp_rule_never_echoes_a_token_it_happened_to_quote`.
4. The file a harness loads is scanned at full weight, fences included: a fenced `sh` block in a SKILL.md is the instruction, and a switch counts wherever it stands as code rather than where the file only names it (invariant 6). One severity less for a blockquote and for a skill's supporting files (`tests`, `fixtures`, `references`); secrets never weigh less anywhere. Enforced by `crates/core/tests/quality/rules_blocks.rs` and `crates/core/tests/quality/advisory.rs`.
5. Bytes that will not decode as text are read lossily and the replacements reported; a binary asset is not reported as undecodable. Enforced by `crates/core/tests/quality/reading.rs`.
6. A `safety-bypass` switch or a `dangerous-commands` destructive command that a file only names is a mention, not a finding. Two quotations name text (`quality::Quotation`): a markdown code span, which only `safety-bypass` honours, and shell text, a full-line comment or a string that `echo`, `printf` or a function whose every body only prints, assigns, tests and steers hands to the terminal, which both honour. The same text in a command position, inside `eval` or `bash -c`, piped on, redirected into a file or captured by a command substitution is a finding, and so is a destructive command in a README's backticks. `quality::text::shell` reads the shell shapes, bounded at `MAX_NESTING` and erring toward the command past it; the two rules read every needle through `Line::standing`, naming the quotations they honour; every other rule, and the `sudo` hit, reads the line as before. Mentions are `AuditResult::mentions`, cost the score nothing, and print only under `refresh --verbose`. Enforced by `crates/core/tests/quality/mentions.rs` for the shapes, `crates/core/tests/quality/corpus.rs` over the shipped guard packages and hooks, and `crates/cli/tests/safety_print.rs::a_verbose_refresh_prints_what_the_rules_read_as_a_mention`.
7. Deobfuscation reports only what has no typographic use (invisible and bidirectional characters, letters imitating other letters) and normalizes emoji and compatibility forms silently; the confusables table in `crates/core/src/quality/homoglyph.rs` is not the whole of Unicode's data and says so. Enforced by `crates/core/tests/quality/reading.rs::confusables_outside_the_original_table_are_folded_and_reported`.
8. A finding kendex accepted in a package it publishes is set aside, not scored, for kendex's own item alone: `quality::allowance` reads the table compiled in from `crates/core/src/quality/allowance.toml`, and a finding is accepted where the item's recorded source is kendex's own repository (`quality::Publisher::of`, read off the browsed source, the plan's provenance, the lock entry an installed copy is recorded under, or the origin remote of a checked catalog), the file's `/`-spelled path inside the tree and the hash of its text match a row's file, the finding's rule, line and message match a row, and the table's rule set is the current one. Only kendex's own table is honoured, so no catalog can carry one; the same bytes from another repository, a hand-placed copy, an edited file, another rule set or another package keep the finding. Accepted findings are `AuditResult::accepted`, cost the score nothing, print only under `--verbose`, and re-key the browse cache through the table's digest. The table holds exactly the findings kendex's packages really run or emit; a row is added by hand with its review, `cargo test -p kendex-core -- --ignored regenerate_allowance` refreshes the hash, line and message of the rows already there and refuses a listed finding the catalog no longer raises, and `crates/core/tests/allowance.rs` fails while a listed finding moved, changed its message or sits in a file whose text changed. Enforced by `crates/core/tests/quality/allowance.rs` for the key, `crates/core/tests/quality/publisher.rs` for the publisher on the preview, plan and installed paths, `crates/core/tests/quality/corpus.rs::orch_keeps_its_fixture_findings_and_its_launcher_row_is_accepted` over the shipped tree, and `crates/cli/tests/safety_print.rs::a_finding_kendex_accepted_in_its_own_package_prints_only_on_a_verbose_run` for the plan path's printing.

## Decisions

- Quality is wshobson's weighted-dimension model, static layer only: no LLM judge, no simulation, no letter grades.
- Rule severities are calibrated against real catalogs, so a rule that fires on ordinary writing is wrong, not strict. A rule that fires on a guard's own comment or refusal message is that defect, answered by rule precision (invariant 6), never by a per-package allowance. A switch a kendex package really runs, a download a kendex reference page really pipes into a shell, or a workflow template that really emits that line is a finding the rule is right about; that one alone is accepted, for exactly those bytes and for kendex's own item, through the compiled-in table (invariant 8), never by a rule that stops seeing it. A fixture string or a homoglyph in a kendex package is neither: it stays a finding.
- A run that scored something closes on `safety: clean` only when nothing is flagged and every rule read every item; an item a rule had no bytes for closes on `not fully checked on safety` instead, never clean. A clean scan, a partly read scan and a scan nobody ran read differently. Enforced by `crates/cli/src/commands/ledger.rs::tests`.
- The CLI prints a score line then one finding per line with no fix line, and groups identical printed safety results.
