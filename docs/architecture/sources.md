# Sources and catalogs

Covers: crates/core/src/source/, crates/core/src/source.rs, crates/core/src/source_read.rs, crates/core/src/source_ref.rs, crates/core/src/remote/, crates/core/src/package/, crates/core/src/drift/, crates/core/src/check_catalog.rs, crates/core/src/library.rs


## Boundaries

- `source/config/agent_names.rs` owns agent aliases and complete `agent:` label tokens, not roles or skills. Declared and resolved `local` sources keep literal names, keyed settings, fork records and references. Other sources read canonical files only. Hook selectors change only when `render::agent::selects` returns `Named`. Plans normalize consumer keys and `LINEAR_AGENT_LABELS`, preserve comments and unrelated values, and refuse duplicate identities. One warning per old name lists affected settings. Compatibility follows [the release standard](../../changelog.d/README.md). Enforced by `crates/core/tests/agent_aliases.rs`.
- Every catalog read goes through `source_read::SealedSource`: resolved against the canonical root, symlinks refused, depth, count and byte budgets carried. A raw filesystem read over the catalog-reading modules is banned by a `tools/guard` lane. Enforced by `crates/core/tests/sealed_source.rs`.
- Snapshots are immutable: each commit is materialized in an object-id directory, published by rename; fetch touches only the bare mirror beside it. Reuse is verified against a receipt outside the checkout. Enforced by `crates/core/tests/source_store.rs`. Only publication removes snapshots: after publishing, the same cache lock protects removal outside the keep set. The keep set is the newest `KENDEX_SOURCE_CACHE_KEEP` by publish time, the one just published included (`crates/core/src/remote/store/retain.rs`, default `DEFAULT_KEEP`; empty reads as unset), plus every commit a lock names in a registered scope or in a scope the invocation stands in (`Env::stand_in`, recorded by `manifest::manifest_path`, so an unregistered project keeps its pins while a command runs in it), plus every checkout the store handed the invocation (`Env::hold_checkout`, so a plan with more pins than the count reads every root). A registry or lock this build cannot read holds every snapshot, and the CLI refresh output counts what its marketplace sync removed. The next read rebuilds a removed snapshot if the mirror holds its commit. Mirrors persist for the install's life, even after unsubscribe, until manual removal. A mirror removed while kendex is stopped is recloned from upstream refs; pins unreachable from those refs are lost. Enforced by the tests in `crates/core/src/remote/tests/retain.rs`, `crates/core/tests/package_pins/mod.rs::more_pins_than_the_cache_keeps_all_install_in_one_pass`, `crates/core/tests/package_diff.rs::a_diff_publishes_history_it_holds_and_dates_at_materialization` and `::a_diff_in_an_unregistered_project_keeps_what_its_lock_names`.
- Machine reads use the installing core: `crates/core/src/check_catalog.rs` owns `kendex check --catalog` authoring passes and checkout selection; `crates/core/src/source/index.rs` emits the community directory summary. Field order defines both JSON schemas. Enforced by `crates/core/tests/authoring_check.rs::check_and_index_agree_on_the_offered_set` and `crates/core/tests/marketplace_index.rs::the_summary_keeps_its_published_field_order`.
- `crates/core/src/source/header.rs` selects and parses each kind's header, so the Packages row, available-package page and directory index describe a version alike. Installed metadata comes from the declaration's source at the installed version (`crates/core/src/library.rs`). The harness file answers only when no declared source can resolve that installation, because each harness gets a different render. Source names belong to the declaring scope, so catalog caches are per scope; same-named packages in other catalogs never answer. Enforced by `crates/core/tests/authored_summaries.rs`.
- The session-start check installs like any other declared item and is described before it is offered: `crates/core/src/drift/hook.rs` writes the script into the scope's local source and declares it, and `crates/core/src/drift/setup.rs` answers what that would write by asking the renderer that will place it, so no surface keeps a second list of destinations. Both read the folder check before they plan, and the plans they build carry it under the landing invariant in [engine.md](engine.md) § Invariants. Enforced by `crates/core/tests/package_checks_plan.rs`.
- `crates/core/src/source/browse.rs` reads catalogs, subscriptions and bare repositories, so listed marketplaces open before subscription. Each call joins row state from the destination scope's manifest and lock. A refused lock still lists the catalog but gates every install surface. Enforced by `crates/core/tests/browse_unreadable_lock.rs`.

## Invariants

1. Full commit ids pin revisions offline once cached. Tags and branches track upstream and re-resolve on refresh with change previews. Item `rev` overrides source `rev` and must be a full commit id. Derivation preserves holds. Parents demanding different revisions of one dependency conflict and write nothing. Enforced by `crates/core/tests/source_store.rs` and `crates/core/tests/package_pins/`.
2. Source materialization takes one repository lock. Foreground calls wait through detached clone and fetch limits; detached reads keep the short skip. A busy cache costs only its source. Enforced by `crates/core/src/remote/tests.rs` and `crates/core/tests/source_store.rs`.
3. Discovery reads a closed, versioned search table (`DISCOVERY_VERSION` in `crates/core/src/source/discover.rs`) that yields skills only; hooks, MCP servers, commands and agents install only from a declared kendex layout or a plugin registry. Output styles resolve only from `output-styles/<name>.md` in a declared layout. Precedence fails closed: a plugin registry wins outright, else a parsed control file declares the layout, else the search runs, and an unreadable control file makes the source unusable with a finding. Enforced by `crates/core/tests/discovery.rs`.
4. Two directories folding to one name are both skipped with a finding naming both, identical bytes excepted; a frontmatter `name` disagreeing with its directory is a finding, the directory being the identity. Enforced by `crates/core/tests/discovery.rs::two_directories_folding_to_one_name_with_different_bytes_both_skip`.
5. A plugin-registry-shaped catalog is recognized only by `.claude-plugin/marketplace.json`; an item resolves only under a plugin the registry validated, and an entry naming another repository is skipped with a finding. Enforced by `crates/core/tests/plugin_registry.rs`.
6. A subscription reference is parsed, never guessed, by the two validators in `crates/core/src/source_ref.rs`: the typed one for what a person types, the untrusted GitHub-only one for directory rows and deep links. Both refuse a leading `-` and a `..` component, and a percent-escape that would smuggle a separator is refused, decoding exactly once. Enforced by `crates/core/src/source_ref/tests.rs::every_hostile_spelling_is_refused_with_its_reason`, `::every_accepted_spelling_parses_to_its_reference` and `::the_untrusted_validator_is_github_only`. One repository subscribes once per scope by canonical identity (`repo_identity` folds `.git`, trailing slash, host case and every GitHub spelling), the refusal naming the existing subscription. Enforced by `crates/core/tests/marketplace_subscribe.rs` and the tests in `crates/core/src/source_ref/`.
7. Installing into a project from a personal subscription copies the declaration into the project in that plan, a folder as the directory the personal scope names, so it never re-resolves against the project root; the personal manifest is read-only and the cache shared. Enforced by `crates/core/tests/install_into_project.rs`, the folder by `::a_personal_relative_folder_is_carried_into_a_project_as_its_home_directory`. A project add that names no marketplace, in a project that has no manifest yet, reaches the personal scope's default marketplace the same way, that one alone; a manifest that exists is left as written, a personal scope that removed the default or holds it switched off leaves the project's own refusal standing, and a name the carried default does not offer is refused naming that package and marketplace. Enforced by `crates/core/tests/marketplace_subscribe.rs::a_project_with_no_manifest_reaches_the_personal_scopes_default`, `::a_fresh_project_writes_nothing_where_the_personal_default_cannot_serve` and `::no_default_subscription_anywhere_is_a_typed_error_never_a_guess`.
8. Pre-install safety (`crates/core/src/source/browse/safety.rs`) caches the advisory payload under content hash, rule-set, discovery and record-format versions and the accepted-table digest, never in the receipt-signed checkout. Enforced by the tests in `crates/core/src/source/browse/safety/`.
9. `kendex check` reads manifest, lock, the per-scope drift snapshot (`crates/core/src/drift/snapshot.rs`) and per-mirror fetch stamps, and from a project scope declaring a Pi package the global manifest too, for the `declared at both scopes` row [harnesses.md](harnesses.md) invariant 7 states; its cheap pass materializes no source tree; exit 0 is clean, 1 drift or unevaluated, 2 could-not-check, and unknown outranks drift. A mirror that moved since its last evaluation is unevaluated, held packages are silent in the agent report, and every read API says when it cannot answer. Enforced by `crates/core/tests/drift_check.rs`. The one deep read the check makes is for a declaration whose position holds files no record accounts for: it plans the scope (`crates/core/src/engine/recovery.rs::compare_unmanaged_copies`), which opens no network and may re-publish an already-mirrored commit into the source cache, and judges each such installation by lock entry key: a copy the render matches is recorded with nothing printed, together with every other entry the same pass proved and can record on its own, or, where D007 withholds the write, reported unrecorded; a copy that differs is reported under `stale` with the count of differing files and the source, at the commit the declaration's revision resolved to where it resolved to one, and with `kendex apply --replace-unmanaged` as the fix only where that sweep would settle the whole scope (it would not refuse, every position it would take was measured, and no row's take-over moves a position the line never named) and with the plan as what to see next otherwise; a position that would not read is a `could not check` line carrying the plan's own reason (`DriftCause::Uncompared`); and a position the plan leaves as it is (a link, a shape) keeps the blocked line with the plan as what to see next. The verdicts are paid for once per state: memoized per installation under the manifest, the record's entry for it, every position it would take as the comparison's own bounded walk reads it (`engine::compared`) and its source mirror's fetch state (`crates/core/src/drift/copies.rs`), retired by every record write, read back by every later check, and re-planned only when one of those inputs moves. Inside the session hook every judgement read a scope's pass makes — the keys that read each position, the memo lookup, the plan, the hashes the record write binds to — runs on the one thread gated by one deadline set from `drift::hook::DEEP_PASS_BUDGET` for every scope the check covers, which with the commit-hook check's timeout stays under the hook's own; the one read past that gate is the record write's own precondition revalidation, the apply's journaled re-hash of the proven set on the main thread (invariant 7), made only after the binding fit the deadline and gone once the record holds the copies; that binding (`recovery.rs::bind_reads`) holds each proven entry to bytes under one of its two spellings and holds each proven registration's settings edits in sync as the plan proved them (`ConfigEdit::in_sync`, the one in-sync judge the plan itself uses), so a proven file gone since the plan, or a registration taken out of, or left unreadable in, a settings file no memo key reads, or a settings file the harness reads now that the plan never held, any of which the memo's proven set outlives by a session, refuses the record and retires the memo rather than recording an empty position as kendex's own or a registration the next apply would put back; a comparison past it is a `could not check` line naming the budget, the report says the plan is owed, a binding past it with the verdicts already in hand keeps those lines and names the binding under `could not check` with nothing owed, and the CLI's detached background refresh, where the environment lets it spawn, finishes the plan for the next session (`crates/core/tests/refresh_stale.rs`). A record that already holds other entries keeps them as recorded, even where the source re-resolved, and gains the proven ones; nothing is claimed when the pass would also rewrite the manifest or touch the entry's own files, and a record-only write leaves the drift snapshot standing. Enforced by `crates/core/tests/unmanaged_check/`, `crates/core/tests/drift_check.rs`, `crates/core/tests/guard_timeout_budget.rs` and `crates/cli/tests/unmanaged_copy_check.rs`. Missing selected installs use apply. Unwanted records use remove without a manifest and plan with one. Pi packages retain their carrier remedy. Enforced by `crates/cli/tests/missing_remedy.rs`. Pi installations also compare their files with the recorded hash through `crates/core/src/pi_ext/state.rs`; Updates compares Pi files with source-tip bytes, or local source bytes. Enforced by `crates/cli/tests/pi_staleness.rs`. An item pin holds installation at the declared revision while Updates can report a held newer release. Enforced by `crates/cli/tests/update_pi.rs::a_pinned_pi_extension_installs_and_verifies_against_its_revision`.
10. A bundle declaration the reader will not read — a body that is not a table, a key the reader does not read, a member list or description written as anything but a list of names or text, or a `bundles` table that is not a table at all — is reported, naming what could not be read, and costs the other sets and every item nothing to install; a body drops that set alone and an unreadable `bundles` table refuses every lookup, and nothing derived from that catalog is swept until it reads. Enforced by `crates/core/tests/authoring_check.rs::every_unreadable_set_body_is_reported_and_costs_the_catalog_nothing`. The authoring check reports each declared member that `source::find_item` cannot resolve as breakage. Enforced by `crates/core/tests/authoring_check.rs::every_unoffered_bundle_member_is_breakage`.

## Decisions

- Any repository holding skills is a marketplace; there is no registration step, and a repository-root `SKILL.md` is a one-skill repository named by its validated frontmatter.
- Every offered item is dated by the newest commit that touched what it contains, never by the bare tip, so the About tab can never read older than a package beside it (`crates/core/src/source/browse/updated.rs`).
- Updates reads current/latest facts; Versions keeps timelines. Updates rows are per package per scope. Edits require fork or discard on the package page. Fork edits report state without blocking actions. The planner reports missing recorded files through `EngineReport::recorded_gone`, read as `files_missing`; Updates makes no second existence check. Recorded positions let skills and commands exclude layout moves from missing files. Hooks and agents record no positions and treat any planner `Missing` row as missing files. Single-package apply repairs missing files without moving holds. Home, Library and package page use the same row. Enforced by `crates/core/tests/edits_and_forks/missing_files.rs`, `ui/src/components/home/attention-rows.test.ts`, `ui/src/components/library/installed-row.test.tsx`, `ui/src/pages/package.test.tsx` and `ui/src/stores/updates.test.ts`.
