# Trash

Covers: crates/core/src/trash.rs, crates/cli/src/commands/trash_cmd.rs, crates/app/src/trash.rs

Where every removal's bytes go, and the bound that keeps a host from filling with them. Removal never deletes; the pass at the end of a writing verb is the other half of that promise.

## Boundaries

- `crates/core/src/trash.rs::move_to_trash` is the one writer: the apply engine's `Trash` op, the project restore and a Pi package's replacement or removal land through it, under a name that opens with the moment it was moved. A name without that stamp is not kendex's and is neither listed nor removed. Enforced by `crates/core/src/trash/tests.rs::a_name_is_dated_by_the_stamp_it_opens_with` and `::a_listing_reports_name_age_and_bytes_newest_first`.
- `crates/core/src/trash.rs::SIZES_FILE` is the size record, `sizes.json` inside the trash: each measured entry's bytes by name, written by the pass alone. Its name carries no stamp, so the listing and `kendex trash` skip it. Enforced by `crates/core/src/trash/tests.rs::a_name_is_dated_by_the_stamp_it_opens_with` and `::a_listing_reports_name_age_and_bytes_newest_first`.
- `crates/cli/src/commands/engine_common.rs::tidy_trash` is the pass at the command line, and its call sites are the list: `apply_cmd.rs`, `refresh.rs` (`updates --apply` runs it), `remove.rs` and `update_pi.rs`. It runs after the invocation's own writes and before the line the run closes on, and takes none of what the invocation wrote (invariant 1); which cancel, failure and empty-run exits reach it is the code's. A plan-only `apply` and every other verb call no pass and leave their entries for the next one. Enforced by `crates/cli/tests/trash_cli.rs::an_apply_brings_the_trash_within_its_bounds_and_keeps_what_it_wrote`, `::refresh_and_remove_close_on_the_pass_too`, `::a_plan_only_apply_leaves_the_trash_alone` and `crates/cli/tests/update_pi.rs::update_reinstalls_from_the_declared_source`; that the other verbs call no pass is not mechanically enforced.
- `crates/app/src/trash.rs::tidy` is the same pass in the desktop app, and this bullet is the one statement of where it runs and where its lines go. Its call sites are the list: `crates/app/src/repo_effects.rs::execute`, the one door every command writes a report through, once the plan is on disk, and `crates/app/src/commit_offer.rs::restore`, whose removals land in the trash with no plan behind them. Which commands reach the door is the code's (`git grep -n -e 'repo_effects::write' -e 'repo_effects::execute' -e 'write_nothing_leaving' crates/app/src`); the package-check install reaches it only on its path with no work pending, and a plan the door refused runs no pass. Each app command is its own invocation, so the pass takes none of what that command moved aside (invariant 1). What went, or why the pass stopped, is a line in the app's own words on the account the door hands back (`undone` on the wire, which `ui/src/lib/undone.ts::sayUndone` shows whenever the account holds a line), never a failure of the command; the package-check install and the restore answer with no account and drop the line. Enforced by `crates/app/tests/trash_pass.rs::every_write_closes_on_the_pass_and_the_account_says_what_it_did` for the door through remove and unsubscribe and for the restore; that no other app path moves a copy into the trash is not mechanically enforced.

## Invariants

1. The keep set is every entry the invocation itself wrote (`Env::hold_trashed`), plus, newest first, every entry within `KENDEX_TRASH_KEEP_DAYS` days (default `DEFAULT_KEEP_DAYS`) while the running total of bytes stays within `KENDEX_TRASH_KEEP_MB` MB (default `DEFAULT_KEEP_MB`); the entry that crosses the size bound goes, and everything older goes unmeasured. Enforced by `crates/core/src/trash/tests.rs::entries_past_the_age_bound_go_and_the_rest_stay`, `::entries_past_the_size_bound_go_oldest_first`, `::an_entry_this_invocation_wrote_survives_its_pass` and `crates/cli/tests/trash_cli.rs::an_apply_brings_the_trash_within_its_bounds_and_keeps_what_it_wrote`.
2. The pass fails closed: a bound that is not a count, a trash that will not read, a size record that will not read, parse or write, or an entry that will not measure or remove stops it with what is left intact and the count of what went before; the CLI verb prints the reason as a warning and the app puts it on the command's account, and neither fails the command; a bound exported empty or as whitespace reads as unset. Enforced by `crates/core/src/trash/tests.rs::a_setting_that_is_not_a_count_stops_the_pass_with_everything_intact`, `::a_setting_exported_empty_reads_as_the_default`, `::a_removal_that_fails_stops_the_pass_and_reports_what_went_before`, `::an_entry_that_will_not_measure_stops_the_pass_and_the_listing`, `::a_trash_that_will_not_read_stops_the_pass`, `::a_record_that_will_not_read_or_parse_stops_the_pass_with_everything_intact`, `::a_record_that_will_not_write_stops_the_pass_after_its_decisions`, `crates/cli/tests/trash_cli.rs::a_bound_that_is_not_a_count_removes_nothing_and_an_empty_one_is_the_default` and `crates/app/tests/trash_pass.rs::every_write_closes_on_the_pass_and_the_account_says_what_it_did`.
3. `kendex trash empty` with no `--older-than`, or with an age of zero, asks first, and with no terminal refuses naming `--yes`, before it removes anything; with an age it removes only the entries past it, oldest first, so a removal that stops leaves the newest entries and the verb exits nonzero naming the count and the cause. Neither takes what the invocation wrote. Enforced by `crates/cli/tests/trash_cli.rs::empty_without_a_bound_asks_and_refuses_with_nobody_to_ask`, `::empty_older_than_removes_only_the_entries_past_that_age`, `::an_empty_that_stops_exits_nonzero_naming_what_went`, `crates/core/src/trash/tests.rs::empty_takes_every_entry_or_every_entry_past_an_age` and `::an_empty_that_stops_leaves_the_newest_entries`.
4. An entry is measured once in its lifetime: the pass that first needs its size writes it to the size record, every later pass reads it back, and a pass that learned nothing writes nothing. A row the pass removes goes with its entry, before the removal is tried; a row whose entry left through `kendex trash empty` or by hand goes on the next pass's write. `kendex trash list` measures fresh. Enforced by `crates/core/src/trash/tests.rs::an_entry_is_measured_once_in_its_lifetime`, `::the_record_holds_only_the_entries_the_trash_holds`, `::entries_past_the_size_bound_go_oldest_first` and `::a_crossing_entry_whose_removal_fails_keeps_no_row`.

## Decisions

- Two bounds, age and size; mirrors in the source cache stay unbounded: [D004](../decisions/D004-trash-retention.md).
- One size record inside the trash, each entry measured once: [D005](../decisions/D005-trash-size-record.md).
