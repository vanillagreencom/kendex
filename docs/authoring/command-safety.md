# Command safety hook

The `command-safety` bundle refuses recognized whole-environment reads in submitted shell command text unless a proven direct pipe filters named variables. It also applies a project command pattern. The bundle includes the hook and the commit-guards settings loader. It does not inspect a desktop session or process list.

Install the `command-safety` bundle; its environment-dump check needs no setting and cannot be disabled by the project pattern. The pattern defaults to the host-safety rule below. To replace that pattern, set `COMMAND_SAFETY_DENY_PATTERN` in `kendex.settings.toml` under `[env]`, or in the install with `kendex add --bundle command-safety --setting COMMAND_SAFETY_DENY_PATTERN=<pattern>`; the bundle's commit-guards skill declares the key. The value is a nonempty POSIX extended regular expression. The shared settings grammar and precedence are documented in [the commit-guards skill](../../skills/commit-guards/SKILL.md#configuration).

Claude Code, Codex, Gemini CLI, and GitHub Copilot execute the hook. Pi executes it while the `pi-hooks` carrier is registered. Cursor and OpenCode install advisory instructions instead of an executable check. Antigravity executes hooks but does not receive this one: it sends the command as `toolCall.args.CommandLine`, not the `tool_input` this hook reads, and a hook reaches Antigravity only by naming it in its `harnesses` line.

The fixed check recognizes unnamed `env` and `printenv` reads, `export -p`, bare `set`, unnamed `declare -p`, `declare -x` and `typeset -x`, `systemctl show-environment` with or without `--user`, and the supported reads of `/proc/*/environ`. Read a named variable with `printenv NAME`, or use a direct pipe such as `systemctl --user show-environment | grep '^NAME='`. Direct `grep NAME` and `grep -E '^(A|B)='` filters pass only for proven newline records. A raw NUL read must use the literal NUL-to-newline tr stage before named grep. Default xargs output joins the entries onto one line and cannot gain that permission. Grep modes that change record framing, unknown producer options and unproved transformations cannot approve a dump. `env NAME=value command` is a launcher; its target is checked separately. `--` ends env options while following assignments remain assignments.

The fixed check reads ordinary literal quoting, supported env, command and sudo prefixes, and direct pipe and list boundaries. Command heads can also use literal dollar quotes and mixed or adjacent quote fragments in the C locale. A command head with a backslash in an ANSI-C dollar quote refuses conservatively; the check does not decode those escapes. Dollar-quoted arguments keep their conservative handling, so `env | grep $'^NAME='` refuses. A known producer argument such as `systemctl $'show-environment'` also refuses. Ordinary variable-valued env assignments and inline options retain target command selection. A reserved word in shell-head position ends ordinary executable selection. The complete unsupported suffix receives conservative known-dump detection across list, pipe and brace text. An ANSI-C escaped word anywhere in that suffix refuses, including escaped argument data. Function names, patterns and options do not restart selection. Exec and builtin use that conservative suffix policy without an option grammar. The selected unsupported context remains active for later list commands and registered bodies, before receiving-program checks or body recursion. Those contexts can refuse command-like data and cannot gain permission from a grep. Ordinary arguments, quoted examples, pathname basenames and argument arrays do not create reserved-word syntax. A grep in another list command does not permit a dump. A stdout redirect or an intermediate program such as tee cannot prove direct filtering. Nested dumps can refuse conservatively even with an inner or outer grep. Literal forwarded env assignments and repeated named -u removals select a target program in a proved shell-script invocation. Named removals in script arguments require no output redirection. Command-head -u removals retain target checking under timing, grouping and output redirection. Unsupported wrapper options and wrappers without a program refuse. The same producer owns these decisions and the grouped file-writing set receipt. Ordinary quoted argument data retains the existing literal argument class for the recorded shell-script receiver; no words inside that string are recognized. Single- and double-quoted heredocs retain the existing literal cat file-writing class when their recorded body, stage and redirect facts match. No delimiter quote subtype or body recognition is added. Ordinary shell invocations with proved literal options and a literal command string, and ordinary all-literal eval joins without a leading option operand, use recursive command parsing. That parser distinguishes shell setup, named reads and quoted argument data from environment output. It also checks literal quoted command arguments after a proved shell script's forwarding operand when input and output are not redirected. Unproved executable strings retain main's known-read refusal. Other conservative clean producer results, quoted data, removed bodies, syntax prefixes, redirected targets and inherited input return to main's known-read refusal. Direct-head main permissions and existing stricter refusals remain. Inherited heredoc input in a pipeline retains conservative known-read refusal across the complete original command. Merged pipes retain conservative refusal for known reads in literal input. Here-string input retains its existing execution checks. Recognized shells, eval and source commands check supplied literal input, including non-stdin descriptors. A direct literal cat receiver can treat one local quoted heredoc body as data, including when forwarded to another literal cat receiver. Other receivers retain the complete original-command fallback for that registered body. A direct literal python3 receiver can also treat one local unquoted heredoc body as data after expansion checks, outside a pipeline. These permissions require a plain default-input heredoc, a clean producer result, no inherited input and no unsupported or conservative receiving context. It bypasses only the registered-body fallback. All remaining command checks stay active. Other registered bodies use the complete original-command classification before receiving-body interpretation. Their receiving stage does not replace the original token order. Recognized receiving shells keep main's direct body decisions and their existing independent program checks. Unproved executable contexts, missing body identifiers and unread registered bodies refuse. Unquoted heredoc substitutions remain executable. Here-strings do not establish a heredoc body. Undecoded escaped delimiters refuse conservatively. ANSI-C escaped heads, producer operands and unsupported suffix words keep their existing refusal. Process substitutions, shell programs, transformed pipes and env split strings have no general interpretation guarantee. The check does not inspect unseen programs, aliases, functions, PATH replacements or runtime-built names. An unanchored `grep NAME` can also match NAME in a value; permitted filtering is not output redaction.

The fixed check runs before cwd, Git and project settings. It also runs outside a Git worktree. An argument array keeps each argument; a pipe character in one argument does not establish a shell pipe. A missing payload reader or unreadable payload produces an advisory warning and allows the call.

An absent setting applies the shipped host-safety pattern, so a fresh install refuses a `systemd-run` memory cap measured in kilobytes or megabytes, quoted or not:

```text
(^|[^[:alnum:]_-])systemd-run[[:space:]][^&;|]*Memory(Max|High)=[[:punct:]]?[0-9]+[KkMm]([^[:alnum:]]|$)
```

A cap that small starved a build's cgroup into a kernel allocation failure inside a filesystem transaction, and the host's root volume went read-only. A cap in gigabytes, or a run with no cap, passes. A project that sets the key replaces this pattern, so its own pattern keeps this rule where it still wants it; `^$` turns only project-pattern matching off. The project-pattern part stays inactive outside a Git worktree. An explicitly empty value, invalid pattern, missing policy tool or unreadable setting produces one keyed warning and allows that pattern check. These conditions do not disable the earlier fixed check.

A malformed value on any `[env]` key produces one keyed warning and allows the pattern check, not only a malformed pattern. The settings loader reads the file whole, like every kendex settings reader, so a policy read past the bad line would come from a file the rest of the toolchain rejects. The warning replays the loader's line naming the file, the line and the key to rewrite.

The project pattern matches tool command text both as received and with backslash-newline pairs removed. For that pattern alone, an argument array is joined with spaces. Quotes and comments remain text, so a matching literal example is also refused. Put isolated validation behind a script whose invocation does not match the pattern.

For a Quickshell project, this example blocks direct `qs -c vshell`, `qs -p quickshell/vshell`, and `pkill quickshell` calls. It allows `scripts/validate qml`.

```toml
[env]
COMMAND_SAFETY_DENY_PATTERN = "(^|[[:space:];|&])qs[[:space:]]+(-c[[:space:]]+vshell|-p[[:space:]]+quickshell/vshell)([[:space:];|&]|$)|(^|[[:space:];|&])pkill([[:space:]]+-[^[:space:];|&]+)*[[:space:]]+quickshell([[:space:];|&]|$)"
```

Missing settings support produces one keyed warning and allows the pattern check because the hook cannot determine whether a policy exists. Repair the installed commit-guards support. Keep the pattern specific to the commands the project must prohibit. The hook does not classify commands hidden inside scripts.
