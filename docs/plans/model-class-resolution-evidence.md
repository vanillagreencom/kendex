## Repository evidence

These observations are file reads, not implementation validation. Earlier observations describe the original design tree. The source observations below describe the design-stage tree unless marked P3. Current implementation receipts belong to the completion artifacts. P4 and P5 integration remains pending.

- The original `models.rs` hard-coded Codex/OpenCode GPT ids and light/fast Pi pins. The current branch has typed `TIERS` rows and `ModelRequest`/`ModelResolution` with one resolver. Preserve that work.
- The design-stage size/risk helper selected classes from workflow size and generic risk. P3 has no such helper. The approved item policy uses explicit standard or top requests.
- P3 `crates/cli/src/commands/tier_model.rs::run` accepts explicit model requests. The rejected item-tier/risk inputs are absent. The existing Top model reason stays in the item brief.
- The general CLI owns rank/model/agent requests and evidence transport. Its explicit top compatibility remains. The overseer owns an item's top justification in the existing brief, not the general availability protocol.
- `skills/orch/scripts/lib/overseer-launch.sh` still holds a Fable/Astra default in `OL_DEFAULT_PREFERENCE`. KEN-2496 owns its actual default edit. P5 parser/pick/launch integration remains pending. Neither integration nor this design amendment proves the fleet has switched defaults.
- `skills/orch/scripts/lib/lane-model.sh` holds usage bucket matching and wall judgment, not family selection.
- `skills/orch/scripts/lib/adapters/claude.sh` holds the alias pin and the one capacity table.
- The design-stage Pi normalization pinned opus and haiku. P3 `pi-extensions/pi-agents-tmux/extensions/subagent/settings.ts::resolveAgentModel` sends raw intent and registry evidence to core before either child launch path.
- `crates/core/src/source/plugin_registry.rs::{REGISTRY,PLUGIN_MANIFEST,read}` recognizes marketplace catalogs. `crates/core/src/engine/desired_kinds.rs::desired_plugins` produces enable toggles only. The repo has no root `.claude-plugin` package. The chosen mod therefore ships inside orch and uses native directory loading; it does not silently add plugin installation capability.
- [D008](../decisions/D008-copilot-agent-model.md) requires Copilot class inheritance. [D015](../decisions/D015-copilot-compaction-handoff.md) retains the Copilot context-event owner. D021 refines them and supersedes neither.
