# Changelog

## Consumer-impacting changes

### 3.1.1

- **Idle-window foreign (subagent-shaped) queries no longer swap or rewrite the shared Claude session (vstack#1001).** 3.1.0 protected subagent queries that arrive while the parent query is ACTIVE; one that starts while the parent is IDLE was indistinguishable from the parent conversation, so its short foreign context rebuilt the parent's session file from foreign history and its completion replaced the parent's session record with the child's id — a prompt-cache flush in both directions per use. The bridge now stamps each session record with a conversation fingerprint anchored on the opening messages of a pi history — the elements that never change (compact/tree-nav mutations set `needsRebuild` and are exempt from the check). A mismatching context that is no longer than the recorded conversation runs as a clean one-shot with exactly the reentrant-path semantics: no resume id, no session-file delete/rewrite, no record replacement on completion or failure, and any steers it captured continue its own child session rather than resuming the parent's. A mismatching context LONGER than the record's cursor still rebuilds (a real conversation only grows, so this lets the genuine conversation reclaim a record ever captured under a foreign fingerprint instead of degrading permanently to one-shots).
- The fingerprint is component-wise — `u:<12hex>` (short sha256 of the first user message's normalized text) or `u:<12hex>|a:<12hex>` (plus the first assistant message's normalized text once the conversation has one) — because a first user message alone is a weak anchor: unrelated conversations routinely open with identical text ("continue"), and a same-opener foreign context aligned with the cursor would resume across genuinely different histories. The user component must always match; the assistant component is compared only when both the record and the incoming context carry one, so a record stamped on turn 1 (no assistant yet) still matches its own grown conversation and upgrades to the two-component form on its next reuse.
- A foreign or reentrant one-shot with unresolved tool state at abort/teardown no longer marks the parent's record `needsRebuild`/`forceRotate`: the mismatch choke point (`reportToolResultMismatch`) and the cursor-advance delivery paths now observe the query's detachment, so such a query emits its full diagnostics and integrity entries without ever touching the shared record.
- The persisted `claude-bridge-session` entry gains a `conversationFingerprint` field. Entries written by earlier versions restore as identity-unknown and keep the pre-fingerprint behavior; such records adopt the anchor on their first REUSE-matched turn. New exports: `conversationFingerprint`, `conversationFingerprintsMatch`.

### 3.1.0

- **Connectors mode now enforces a fail-closed builtin ALLOWLIST at call time.** Every connectors-mode child carries a `PreToolUse` hook that permits only Pi's bridged custom tools (`mcp__custom-tools__*`), claude.ai connector tools (`mcp__claude_ai_*`, writes still subject to the write-deny gate), and the discovery built-ins (`ToolSearch`, `ListMcpResources`, `ReadMcpResource`) — and denies everything else, including future CLI built-ins the static denylist has never heard of. The hook applies in BOTH write modes (a one-shot write executor is still a connectors session ingesting third-party content), and every exception path inside it converts to a deny. New exports: `connectorBuiltinAllowlistHook`, `isAllowlistedConnectorSessionTool`, `denyAllToolsHook`.
- **MIGRATION: `enableConnectors` and `connectorWriteMode` now resolve from user-scope settings and env only.** A project's checked-in `.pi/settings.json` or `.pi/claude-bridge.json` can no longer flip them, even for a trusted project — connectors expose live account data, so a cloned repo must not be able to switch them on (or un-gate writes) by being the cwd. If you previously enabled connectors per-project, move the keys to `<PI_CODING_AGENT_DIR>/settings.json` (or `claude-bridge.json`), or set `CLAUDE_BRIDGE_ENABLE_CONNECTORS`/`CLAUDE_BRIDGE_CONNECTOR_WRITE` in the process env. Note the boundary precisely: this closes the *checked-in-file* channel; the process env remains an accepted channel by design, so an embedding whose launcher lets a project script set the bridge's env still controls these switches — env hygiene is the embedder's contract. All other options keep the existing trusted-project layering.
- **Reentrant (subagent) queries no longer touch the shared Claude session.** A subagent call routed through the parent's provider instance used to be able to shrink the parent's cursor to its own short context, clamp into a REUSE plan that resumed the parent's Claude session, or overwrite the parent's session record on completion. The prompt-batch planner now rejects a cursor beyond the messages array as proof of foreign context, the delivery-path cursor can only advance, and a reentrant fresh query runs as a clean one-shot: no resume id from the parent, no shared-session writes.
- **Deferred (mid-query) user messages are never silently lost on failure paths (#967 invariant, closes vstack#993).** Every path that discards captured steers now records a `deferred_user_messages_dropped` diagnostic (count + previews), and any session record that survives the drop is persisted with `needsRebuild` so the next turn re-imports the steers from Pi history instead of resuming past them forever. Previously a terminal failure persisted the advanced cursor with no rebuild, losing the steers permanently — and a FAILED deferred replay (continuation error, or no session to resume) finalized the turn as a success with the messages gone; those legs now surface the failure and mark the rebuild too.
- **Deferred replay preserves image blocks (vstack#993).** The replay queue was text-only, so a mid-query user message carrying images replayed as its text alone and an image-only steer was skipped entirely. Captured runs now carry their block form and replay through the same block path as the main prompt, so images survive; image-only runs are captured instead of dropped.
- Terminal `result` failures and late connector results arriving after a tool-use turn boundary (Pi stream already ended) are now captured: failures classify for account routing instead of masquerading as success, and a connector result observed late is audited `ok`/`error` instead of `unobserved`.
- A managed rate limit whose SDK iterator then throws is counted once: the router's `recordRateLimit` cooldown is no longer doubled by a re-classified `recordFailure` for the same rejection. Companion-router callbacks are also exception-isolated — a throwing telemetry callback can no longer fail a delivered turn.
- A failed connector-inventory prime (network blip, missing credentials) is no longer cached for the process lifetime; the next turn retries, keeping declarations and the disk-cache fallback reachable.
- A managed profile with a missing `.credentials.json` no longer silently borrows the DEFAULT account's OAuth token: when a credential dir is explicitly selected, only that dir is probed (`credentialCandidatePaths`).
- The account probe child (`probeProfile`) now runs under full bridge tool isolation plus a deny-all `PreToolUse` hook — it previously spawned with `bypassPermissions` and no tool restrictions.
- Non-success terminal subtypes (`error_max_turns`, `error_during_execution`) surface with session bookkeeping intact as before, and the session-verify warning toast now home-relativizes paths (the local diagnostic dump keeps absolutes).
- New exports: `scopeKeyFor` (the canonical credential-scope key rule shared with the connector cache's on-disk format) and `connectorServersSnapshot`.
- Internal module split: `index.ts` shed the SDK-stream consumer, account host/probe, query-option assembly, connector runtime, and command registration into dedicated modules. The bundle's export surface is unchanged (verified by diffing the export list before/after).

### 3.0.1

- **Connectors mode now loads only USER-scope settings in the child Claude Code** (previously `["user", "project", "local"]`). Claude Code settings files can set an `env` map and `apiKeyHelper`, so a checkout's `.claude/settings.json` could reintroduce the provider-override env the bridge scrubs from the child (e.g. `ANTHROPIC_BASE_URL`) on any connector query run in that cwd. Connector state lives in user scope, so connectors still surface unchanged. If a session genuinely needs project/local settings in the child, set `provider.settingSources` explicitly in bridge config (it still wins verbatim) — knowing it reopens the repo-controlled settings surface. Non-connectors behavior is unchanged. New export: `settingSourcesForQuery`.

### 3.0.0

- **Multi-account subscription routing (optional).** A companion extension may publish an account router on `globalThis` under the versioned symbol `vstack.pi.claude-account-router.v1` to supply a subscription profile (opaque id, label, optional `CLAUDE_CONFIG_DIR`) for each fresh Claude request. The child environment, `cc-session-io` session files, resume IDs, connector inventory/cache scope, and usage probes are all scoped to the selected profile together. Classified pre-output failures (auth, billing, rate-limit, overloaded, server, network) rotate to the next profile — capped at 16 attempts per request — while protocol setup frames are buffered (`RetryEventBuffer`) so a retried attempt never leaks a duplicate `start` frame or replays committed output. Once visible text/thinking, a Pi tool call, or a child-executed connector dispatch has reached Pi, the request is never replayed on another account; post-output failures are still recorded for the next request's routing. Managed child processes drop inherited Anthropic API/provider-override env (`ANTHROPIC_API_KEY`, `ANTHROPIC_BASE_URL`, `CLAUDE_CODE_USE_*`, …) so the selected profile remains the billing identity. Without a router the bridge behaves exactly as before. The reciprocal `vstack.pi.claude-bridge.account-host.v1` service exposes a local `/usage` probe for account-management commands.
- **BREAKING: provider ids renamed `claude-bridge/*` → `pi-claude/*`, with NO compatibility alias.** The provider registers only as `pi-claude`; commands are `/pi-claude` and `/pi-claude:connectors`. Saved sessions recorded under the old `claude-bridge` provider id will not resolve their provider; their assistant thinking signatures are also no longer recognized as bridge-authored on rebuild. This is accepted — reselect the model via `/model` and continue. Effort-override keys use bare model ids, `pi-claude/<id>`, or `*` (old `claude-bridge/<id>` keys are ignored).
- **BREAKING: bridge-side Extra Usage switch removed.** The `allowExtraUsage` setting, `/claude-bridge:extra` command, and the automatic `/extra-usage` helper are gone. Extra Usage is owned by the claude.ai account settings: if enabled there, the child Claude Code uses it natively — the bridge neither enables nor blocks it. Extra-usage/overage error copy still classifies as a rate limit (rotation trigger under a router). `isExtraUsageRequiredMessage` is no longer exported.
- **BREAKING: persisted session entry shape changed.** The `claude-bridge-session` custom entry now stores only the opaque `accountProfileId` for managed sessions — never the account's `CLAUDE_CONFIG_DIR` path, which is account-identifying and traveled with shared session archives. The config dir is re-derived through the router on restore (router absent → default profile rule). No back-compat reader for the previous shape.
- **Non-success terminal results now surface.** Claude Code results with subtypes such as `error_max_turns` and `error_during_execution` previously ended the turn silently as an empty success; they now push an explicit error event. Session continuity is preserved: the session record is still written. Deferred (mid-query) user messages are dropped on these failed turns — the error has already ended the Pi stream, so replaying them would run continuation queries whose output could never reach Pi while their tool side effects still executed.
- **BREAKING: connector-cache on-disk format bumped to version 2.** The payload's `scope` field now stores the full sha256 hex of the scope key instead of the raw `CLAUDE_CONFIG_DIR` path (account-identifying; the filename was already hashed for the same reason). External readers of `<pi dir>/connector-cache/*.json` (vstack#892) fail open on the version bump: version-1 files are rejected wholesale and rewritten on the next inventory fetch.
- The account-host `probeProfile` service now enforces an internal 10s deadline: a stalled probe child is killed and the promise settles (previously a caller that omitted `signal` could hang forever and leak the child process).
- The session-verify warning toast no longer includes the `CLAUDE_CONFIG_DIR` value (it asks to be pasted into a public issue and config-dir paths are account-identifying; the local diagnostic dump still records it) and now points at the vstack issue tracker instead of the upstream fork's.
- Account rotation announces a model switch once per distinct model per request instead of re-toasting an identical notice on every retry attempt.
- A rejected rate limit followed by a successful fallback-model recovery now completes exactly like a success (one `[rate-limit]` notification, no trailing error, session persisted) — previously possible double-notification/dropped-session paths were removed with the failure-state rework.
- New exports: `streamClaudeAgentSdk`, `__testSetSdkQueryFactory`, and the account-router surface (`CLAUDE_ACCOUNT_ROUTER_SYMBOL`, `CLAUDE_BRIDGE_ACCOUNT_HOST_SYMBOL`, `RetryEventBuffer`, `classifyClaudeFailure`, `subscriberProfileEnv`, `accountSessionScope`, `claudeDirForProfile`, `commitsVisibleOutput`, rate-limit info helpers, and the `ClaudeAccountRouterV1`/`ClaudeBridgeAccountHostV1` types).
- Rebuild imports now recover real sibling tool results when a steer split one parallel tool batch across later turns (`recoverLaterToolResults`), instead of pairing the original batch with false "[no tool result recorded]" placeholders; recovered `tool_result` blocks are inserted before any text blocks per Anthropic message convention.
- Aborting a turn with in-flight tool calls no longer raises a `tool_result_delivery_mismatch` integrity error (diag dump + toast); the expected interruption is logged and the session still rebuilds.
- Extension display name is now "Pi Claude".

### 2.1.0

- Delivering multiple queued Pi follow-ups in one call (steer-queue drain, `followUpMode="all"`) no longer forces a Claude session rebuild: the REUSE path now recognizes an unbounded trailing run of user messages, combines them into one prompt, and resumes the existing session — no session-file rewrite and no prompt-cache flush (vstack#963).
- Mid-query queued follow-ups are no longer silently dropped: when Pi injects several user messages during an active query, the entire trailing run is captured for replay after the query instead of only the last message, and the session cursor only advances over messages actually captured. Anything skipped now emits a `deferred_user_replay_skipped` diagnostic instead of vanishing (vstack#967).
- New exports: `planIncrementalPromptBatch(messages, cursor)` (REUSE-path prompt-batch planner) and `planDeferredUserReplay(messages)` (mid-query trailing-user-run capture plan).
- `cc-session-io` dependency floor raised to 0.3.2 (content-block `addUserMessage` with empty-content guard; `importMessages` keeps non-tool_result blocks alongside tool results).

### 2.0.1

- Claude Code's in-process meta-tools (`ToolSearch`, `ListMcpResources`, `ReadMcpResource`, `ScheduleWakeup`) are now classified as child-executed (`isChildExecutedTool`), matched by exact name. They no longer appear as Pi tool calls, no longer end the Pi turn, and no longer produce a `pendingResults` entry that the reaper later drops — the "dropped 1 tool result(s) whose handler never matched (ToolSearch)" warnings, the phantom failed tool calls, and the spurious pi-turn boundaries they caused are gone (vstack#980).
- These built-ins are also excluded from the connector-call audit trail: `claude-bridge-connector-call` entries (and host audit sinks) now record claude.ai connector calls only, as the trail was always documented to. Connector calls under `mcp__claude_ai_*` audit exactly as before.
- New exports: `isConnectorTool(name)` (narrow claude.ai connector-namespace test) and `isChildInternalTool(name)` (exact-match child built-in test). `isChildExecutedTool(name)` is now the union of the two; consumers that used it as a connector test should switch to `isConnectorTool`.
