## Shipped

### `ab6ee286` — `fix(pi-codex-minimal-tools,pi-qol): honor null provider-header deletion markers`

- Affected extensions: `pi-codex-minimal-tools`, `pi-qol`.
- Trigger: coding-agent 0.84.0 Breaking — "`ModelRegistry.getApiKeyAndHeaders()` now returns `ProviderHeaders` with `string | null` values and preserves `null` header-deletion markers. Extensions that inspect returned headers must handle `null`; extensions forwarding them to pi-ai streams should pass them through unchanged" ([#7030](https://github.com/earendil-works/pi/issues/7030)).
- Defect A: `pi-codex-minimal-tools/src/background-image-generation.ts:298` typed the resolved headers as `Record<string, string>` and applied them with `headers.set(key, value)` onto a real `Headers` for a raw `fetch`. `Headers.set()` stringifies `null`, so a header Pi marked for deletion was transmitted with the literal value `"null"` — the Cloudflare-AI-Gateway placeholder-credential shape Pi's fix exists to prevent. Now deletes on `null`; `buildHeaders()` exported to make the case testable.
- Defect B: `pi-qol/extensions/qol/session-rename.ts:240` filtered auth headers through `headerRecord()`, keeping only non-empty strings. The `null` deletion markers were dropped before being forwarded to `completeSimple()`, so pi-ai never received the deletion instruction and re-sent the header. Now preserves `null` while still dropping empty and non-string values; exported for the same reason.
- Verified correct, no change needed: `pi-qol/extensions/qol/compaction.ts:177`, `pi-qol/extensions/qol/handoff.ts:69`, and `pi-skills-manager/extensions/skills-manager/creation.ts:72` already forward `auth.headers` through unchanged, which is exactly what the entry prescribes.
- Tests: `pi-qol/tests/provider-headers.test.ts` (3 new cases), `pi-codex-minimal-tools/tests/background-image-generation.test.ts` (1 new case). Suites run with Pi peer packages symlinked from `pi-claude-bridge/node_modules` (removed afterwards): pi-codex-minimal-tools 74 pass 0 fail; pi-qol 113 pass 0 fail.

### `e07034a9` — `fix(pi-agents-tmux): rebuild the partial message from Pi 0.84 delta-only updates`

- Affected extension: `pi-agents-tmux`.
- Trigger: coding-agent 0.84.0 Breaking — "Changed JSON and RPC `message_update` events to emit only `assistantMessageEvent` deltas, removing the cumulative `message` and `assistantMessageEvent.partial` fields that caused quadratic output growth" ([#7290](https://github.com/earendil-works/pi/issues/7290)).
- Scope confirmed from Pi source before editing: `packages/coding-agent/src/modes/json-event.ts` strips `partial` and rebuilds the event with only `type` + `assistantMessageEvent`, and it is applied **only** at the JSON/RPC stdout boundary. `packages/coding-agent/src/core/agent-session.ts:755` still emits the in-process `MessageUpdateEvent` with both `message` and `assistantMessageEvent.partial`, so in-process extension listeners are unaffected (see Non-impact).
- Defect: bg one-shot agents run Pi in JSON stream mode — the changed surface. `runner.ts:988` kept only the newest `message_update`, and `runner.ts:883` flushed that single event as a `buffered: true` record when the process exited nonzero, errored, or timed out without a `message_end`. That design was sound only while each event carried the whole message-so-far; against 0.84.0 the flush preserves one token, gutting the record you read when a subagent dies mid-answer.
- Fix: `transcripts.ts` gains a per-`contentIndex` accumulator (`createPartialAssistantMessageState`, `applyPartialAssistantMessage`, `partialAssistantMessage`, `resetPartialAssistantMessage`). The runner folds `text_*`/`thinking_*` deltas in, resets at each message boundary, and attaches the rebuilt message to the flushed record as `partialMessage`. `*_end` content supersedes accumulated deltas; a snapshot-bearing event suppresses the rebuilt copy rather than duplicating it; tool calls are not rebuilt because `tool_execution_*` events already record them.
- Docs: `pi-agents-tmux/DEVELOPMENT.md` stated "those events are full message-so-far snapshots" — now false, and rewritten to describe the delta reconstruction.
- Tests: `extensions/subagent/__tests__/partial-assistant-message.test.ts` (7 new cases) plus an end-to-end delta-shape flush case in `tests/session-lanes.test.ts` across all three stream shapes. Suite run with Pi peers and `typebox` symlinked from `pi-claude-bridge/node_modules` (removed afterwards): 311 pass, 0 fail, 32 files. Without those peers, 16 tests fail identically before and after the change from an unresolved `typebox` import.

### `051b1b91` — `fix(pi-claude-bridge): honor Pi 0.84's per-directory AGENTS.override.md`

- Affected extension: `pi-claude-bridge`.
- Trigger: coding-agent 0.84.0 Added — "Added per-directory `AGENTS.override.md` context files, which replace `AGENTS.md` or `CLAUDE.md` in the same directory while preserving context from other directories" ([#7681](https://github.com/earendil-works/pi/pull/7681)).
- Defect: `pi-claude-bridge/src/agents-md.ts:30` walked parents looking for `AGENTS.md` only. The bridge exists to forward Pi's standing instructions into the Claude Code subprocess, so once Pi honored overrides the bridge forwarded the file Pi itself had superseded.
- Fix: per-directory candidates now follow the leading entries of Pi's own order, confirmed from `packages/coding-agent/src/core/resource-loader.ts:71` (`["AGENTS.override.md", "AGENTS.md", "AGENTS.MD", "CLAUDE.md", "CLAUDE.MD"]`): `AGENTS.override.md`, then `AGENTS.md`. The `CLAUDE.md` entries are deliberately omitted — the Claude Code subprocess loads `CLAUDE.md` natively, so forwarding it would apply the same context twice. Candidates must now be regular files, matching Pi's `statSync().isFile()` check. Same resolution applies to the `piUserDir` fallback.
- `bundle/index.js` is the artifact Pi loads (`pi.extensions: ["./bundle/index.js"]`), so it was rebuilt in the same commit.
- Tests: `npm run test:unit` — 504 pass, 0 fail (3 new cases: override precedence, nearest `AGENTS.md` beating an ancestor override, and a directory named `AGENTS.md` not ending the search).
