# pi-web-tools development

For maintainers. What it does for a consumer is [README.md](README.md); the Exa API map is [EXA.md](EXA.md); each tool's schema descriptions in `src/tools/` state its own arguments.

## Invariants

- Only package tools are managed. `src/active-tools.ts::computeNextActiveTools` adds and removes names from `PACKAGE_TOOL_NAMES` and never touches a native or third-party tool; `tests/provider-selection.test.ts` holds it.
- A tool whose backing is absent is withheld, not registered to fail: `desiredWebTools` drops the Exa-only tools without `EXA_API_KEY` and drops `web_search` when no provider resolves. `web_fetch` stays, because its primary paths need no key and the Exa fallback is skipped when the key is unset.
- Provider order in `auto` is one list, `src/provider-selection.ts::resolveWebProviderCandidates`; the doctor command prints it from the same function. A provider is a candidate only when `enabledProviders` names it and its key or condition is present.
- Stored text lives on disk, one file per content id in the session's lane directory: `src/storage.ts::storeWebContent` writes the file and appends a `pi-web-tools.content` entry that carries the id and the storing session's id without the text, and `beginWebContentSession` reads those ids back on `session_start`, so a content id survives a resume or a fork while its file survives the lane retention rule (`scripts/lane-retention.ts`). `getWebContent` tells an id the session never recorded (`unknown`) from a recorded id whose file is gone (`missing`). Memory holds a bounded, least-recently-used set of items. A tool that returns a preview stores the full text first.
- Exa paths store a provider-capped excerpt, and `get_web_content` labels it `stored excerpt`; direct HTTP, GitHub, PDF and YouTube-caption paths store the full extracted text of what they read. Raising `textMaxCharacters` on an Exa path raises the provider cap, on a direct path only the preview.
- The byte budgets are constants in `src/extract/byte-budget.ts`; these two bullets are the one statement of what they count and when they release. Page, Jina Reader, GitHub file, README and PDF bodies go through `UrlReads`: a text body is cut at `TEXT_READ_BYTE_LIMIT`, a PDF over `PDF_READ_BYTE_LIMIT` is refused. A call's `CALL_BYTE_BUDGET` cuts the read that crosses it (a PDF is refused) and fails each later URL before its network or git work. A cut sets `bodyTruncatedAtBytes` and `bodyTruncatedBy`, which the preview and `get_web_content` show. Uncharged: GitHub API JSON, local video (read whole, up to its own 50 MB), YouTube, Exa and Gemini.
- Every call in the process shares `IN_FLIGHT_BYTE_BUDGET`. A read reserves its ceiling, or a file's smaller size, or an unencoded body's smaller content-length, which then cuts it (`declared-length`). It waits in FIFO order and fails its URL after `IN_FLIGHT_WAIT_TIMEOUT_MS`, or stops on abort. A body read stops as soon as it holds its reservation: whole at its declared length, cut at a ceiling when no length was declared, and never waiting for one more chunk. A read that receives no chunk for `BODY_IDLE_TIMEOUT_MS`, kept under `IN_FLIGHT_WAIT_TIMEOUT_MS`, fails with `web_fetch body stalled` and returns its room; its URL then takes the same fallbacks as any other read error. The deadline is per chunk, so a body that keeps sending slowly holds its room until its ceiling or an abort. A URL either budget fails raises `ByteBudgetExhausted`, and `web_fetch` routes it as any failed URL: a remote URL that is not a transcript request goes to the Exa fallback given an Exa key and a provider other than `http`; any other URL fails with the budget named. Two reads degrade instead of failing their URL: the Jina fallback after a thin HTML page keeps the thin page on any failure, a budget failure included, and records it in `jinaError` (`src/extract/http.ts`); the GitHub API README read returns the repository metadata without the README on any failure but a budget failure or an abort, a stall included (`src/extract/github.ts`). Unread room returns when the read ends; the bytes read stay reserved until `web_fetch` releases the URL after processing it. A URL's next read releases its earlier one first, so waits cannot deadlock, and the Jina fallback after a thin HTML page holds that HTML text uncounted: up to two text bodies per URL.
- Rasterized PDF pages stay within `MAX_PAGE_PIXELS`: `src/extract/pdf-pages.ts::pageScaleArgs` lowers the DPI of the whole document to fit its largest page, and `pdftoppm` renders the CropBox that `pdfinfo` measures.
- `src/extract/html.ts::htmlToMarkdown` removes script, style, noscript and svg blocks in one pass, then converts the other tags in one left-to-right scan (`MarkupScan`), reproducing the regex replace chain it replaced on well-formed markup.
- Multi-URL `web_fetch` caps the aggregate inline preview (`MULTI_URL_AGGREGATE_CAP_SMALL_BATCH` and `MULTI_URL_AGGREGATE_CAP_LARGE_BATCH` in `src/tools/web-fetch.ts`) and switches to a manifest at `MULTI_URL_LARGE_BATCH_THRESHOLD`; an explicit `textMaxCharacters` opts out. When the manifest itself cannot fit, rows fall back to id-only so every content id stays resolvable.
- A transcript request is captions or an error. `videoMode: "transcript"`, or a prompt `src/extract/youtube.ts::isTranscriptPrompt` recognises, never falls through to an Exa excerpt or a Gemini summary; `provider: "exa"` is rejected for transcript URLs and a mixed batch continues its other URLs. `transcriptLanguage` is BCP 47 and a base language recovers a regional track.
- Secrets are read in `src/settings.ts::loadSettings` in one order: the process environment, then the private config file, then Pi settings (accepted with a warning), then the project's `.env` and `.env.local`. Project files are read only after `recordProjectTrust` saw the workspace trusted. An `op://` reference past `PI_WEB_TOOLS_OP_READ_TIMEOUT_MS` (clamped between 100 and 10000) is unset, never a blocked startup.
- `loadSettings` memoizes the resolved settings, `op://` keys included, while every input it resolves from reads the same: its merged package config, the settings-file diagnostics, and the raw text of the project `.env` files and the private config file. It keys the memo on the project's trust, the process working directory and the environment variables it reads. `op read` runs once per change, not once per provider request; a settings-changed event or a new session resolves again. A resolution in which an `op://` reference failed is kept for one `SETTINGS_RECHECK_MS` window only, so the reference is tried again after that window.
- `PI_CODING_AGENT_DIR` counts only when root-anchored, matching `crates/core/src/harness/pi.rs::pi_root_is_absolute_for`. The rule lives in `src/package-config.ts::piUserDir` and `src/package-config.ts::rootAnchored`; `src/extract/github-clone.ts::defaultCacheDir` uses `piUserDir` for the clone cache root.
- Research mode defaults live in `src/tools/web-research.ts` and resolve as explicit tool argument, then the `exaResearchModes` profile, then the mode default (`applyResearchMode`). `full` runs the primary query plus each `additionalQueries` entry and dedupes URLs.
- Codex-model activation is by provider id, not model name (`src/provider-selection.ts::isOpenAiNativeModel`); the native rewrite in `src/native-openai.ts` replaces only a tool named `web_search` in the outgoing payload.

## Tests

`node:test` suites under `tests/`, run through `tsx`. The host packages are optional peers and are not installed in the tree:

```bash
cd pi-extensions/pi-web-tools
npm install --no-save --no-package-lock --ignore-scripts --no-audit --no-fund @earendil-works/pi-ai@0.84.1 @earendil-works/pi-coding-agent@0.84.1 @earendil-works/pi-tui@0.84.1 typebox tsx 'youtube-transcript-plus@^2.0.1'
npm run check
```

`npm run check` is `typecheck` then `test`; `.github/workflows/skill-tests.yml` runs the same install. Provider suites stub `fetch` and assert request and response shapes; a new provider ships with its shape test and a case in `tests/provider-selection.test.ts` for where it sits in `auto`.
