# skills/

The catalog's skills, one directory per skill, each rendered under `.agents/skills/<name>/` for this repository's own install. The same render rule covers `agents/<n>.md` (one render per harness directory) and `hooks/<n>` (the harness hook directories that already track it).

- A change to a source with a tracked render lands the render in the same commit; a `tools/guard` lane checks presence, not bytes, because a render may carry an injected instructions block the source has no copy of. The one exception is a render the change leaves unchanged when the source change only moves a frontmatter key between values its harness renders to nothing, the `render_blind` rows in `tools/guard`. A source with no tracked render has nothing to land.
- A change that moves what `kendex refresh` would record for any entry, through its source, the manifest sections that shape it, or the kendex code that hashes, renders or records it, re-records `.kendex-lock.json`; CI fails on the `record` row, plus a stale row for each entry whose source hash moved, and [`../docs/DEVELOPMENT.md`](../docs/DEVELOPMENT.md) § The self-install says how a worktree re-records it.
- Sync a render by replaying the source diff onto the render, never by copying the source file over it.
- A render the change adds or removes joins or leaves `.kendex-generated.json`, the committed inventory every reader of a render path consults; a path it does not list is judged hand-written, so `doc-drift-check` names a new render as uncovered code. `kendex refresh` at the checkout root is the file's one writer, and in a worktree it re-renders the whole tree rather than one change, so a worktree adds the entry by hand, in sorted order and one per line, and `cargo test -p kendex-core --lib own_inventory` judges the result.
- Shell stays Bash 3.2 compatible; `tools/bash32-lint` names Bash 4+ constructs in the guard, `tools/bash32-parse` parses the same tree and `tools/` with a real Bash 3.2 under `tools/guard --full` and the `guards-scans` shard, and the macOS leg of the skill suites shard runs every shell suite but linear's, whose CLI has its own Bash 4 contract, on the runner's `/bin/bash` 3.2.
- Preflight's `fail-open`, `mktemp-trap`, `masked-returns` and `early-close-pipe` lanes check a shell script for the `set -euo pipefail` preamble, an unchecked or untrapped `mktemp`, a declaration masking a status, and a shell writer piped into an early-closing reader; `preflight --help` states what each lane fails on. A must-fail control for `early-close-pipe` writes its input from the shell, never `cat` reading a file, which pushes several hundred KB before it blocks and passes a buffer-sized fixture either way.
- A script proves its jq filters with jq 1.7.1, where `f? .r` does not parse and `f? | .r` does.
- A script measures a commit header with commit-guards' locale-stable `gg_chars`, never raw `awk length` or `wc -c`.
- A script that sources another skill's lib declares that skill `required` under `dependencies` in its own `SKILL.md`, and every fixture that copies a skill into an isolated project installs the required sibling beside it; a copy parked outside that layout refuses at startup rather than running the case. A script that sources the lib on one path only, feature-detects it there and refuses that path when it is absent declares the skill `optional` instead. Executing another skill's script is a dependency by the same rule as sourcing its lib, and a declaration that closes a cycle with the sibling's own edge is still made: the dependency walk in `crates/core/src/engine/deps.rs` accepts cycles.
- A package change feature-detects every dependency and never names one machine's directory layout.
- A change to a file that holds a finding kendex accepted (`crates/core/src/quality/allowance.toml` names each) refreshes the table with `cargo test -p kendex-core -- --ignored regenerate_allowance` and lands its diff in the same commit; `crates/core/tests/allowance.rs` fails while the table is stale, and the refresh refuses a listed finding the file no longer raises. A new finding elsewhere in a kendex package stays a finding: the refresh adds no row, and a row is written by hand only for a line the package really runs or emits.
- A test that shells out to git clears `GIT_DIR`, `GIT_COMMON_DIR`, `GIT_WORK_TREE` and `GIT_INDEX_FILE` together. Under `orch/tests/` that clearing is `skills/orch/tests/lib/git-env.sh`, sourced on the line under each suite's `set -...o pipefail`.
- A fixture repository a test later removes disables git's background maintenance at creation, `gc.auto 0` and `maintenance.auto false` as `skills/bot-instructions/tests/lib/harness.sh` spells it, so the removal cannot race git's background writer.
- Every skill suite runs on the pull request and in the merge queue through `.github/workflows/skill-tests.yml`, on both events, for every `micro`, `small` and `standard` diff; a `render` or `trivial` diff runs no shard, apart from the exception [`../tools/ci-job-set`](../tools/ci-job-set) states for a `trivial` one. The macOS leg stands down only where every changed path is prose; [`../tools/ci-job-set`](../tools/ci-job-set) states what each class runs.
