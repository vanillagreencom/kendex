# Render spec

One section per output. Each names the exact path, what the generator owns inside it, which doctrine blocks it carries and in what order, and how repo text from `[bot-instructions]` is escaped into that file's syntax.

- Whole-file outputs in this reference apply to full mode.
- [§ Local output](#local-output) owns local mode and its installed-doctrine pointer.
- Doctrine block ids are the `###` headings of the doctrine source, whose parse rule is SKILL.md § Doctrine.
- The routing table below is the only other place they are written down, and `doctrine-routing` holds the two to the same set.

## Local output

Read when selecting `--output local` for `render`, `check` or `adopt`.

- Local mode limits those commands to the `AGENTS.md` review region.
- The default `--output full` keeps every enabled bot output.
- The doctrine loader selects `SKILL.md` or `SKILL.md.disabled`.
- The pointer uses that filename and the `#doctrine` anchor inside the selected checkout installation.
- Checkout parent paths resolve through their symlinks.
- The installation's own symlink keeps its checkout path.
- Source reads use its canonical target.
- An external `--spec` needs a matching selected installation inside the checkout. Otherwise local mode refuses: use `--output full` or install the package inside the checkout.
- Remote files are excluded from validation, adoption, writes, orphan removal and ownership reports.
- Local review reads the package doctrine directly; repository doctrine overrides remain in the full render.

## Common rules

**Block assembly.**

- A block's text is its heading's slice with the heading line dropped and surrounding blank lines trimmed.
- `[bot-instructions.doctrine.replace]` substitutes the slice.
- `[bot-instructions.doctrine.append]` adds its text after the shared block.
- A replacement takes precedence when both tables name a block.
- The `reply-contract` block's `<issue>` placeholder becomes `<PREFIX>-<n>` when `[bot-instructions.repo] tracker` is set.

**Marker.** Every file the generator owns whole, and the one region it owns inside `AGENTS.md`, carries a marker: the file's **first comment**, preceded only by a prologue the format requires. There are exactly two such prologues:

1. YAML frontmatter at byte 0 in a markdown output that carries it (a `.instructions.md` file and a `.macroscope/correctness/<surface>.md`).
2. The `yaml-language-server` schema line at the top of `.coderabbit.yaml`.

**Ownership is that the first line IS the marker**, not the marker anywhere in the file.

- The test is that the line opens with the marker's opener, `<!-- generated by bot-instructions ` or `# generated by bot-instructions `, trailing space included.
- Nothing after the opener is compared: a marker an earlier copy wrote with a version after the token still reads as owned, so a refresh replaces it.
- The marker a render writes is narrower, byte for byte, with the recorded paths the only free field.
- The HTML form is one line; the `#` form opens with the opener and closes on a second line.
- `render`, `adopt` and `orphan` ask that one question.

The first line, **or the first line after a leading prologue**:

- A leading YAML frontmatter block is skipped, and so is the `yaml-language-server` line, at every path.
- A rendered `.macroscope/correctness/<surface>.md` copied to `.macroscope/approvability.md` keeps its frontmatter, and that copy is `orphan`'s case.

The marker is a comment in that file's syntax naming this package and its render inputs. SKILL.md § The render inputs states the set.

- The comment ends with the sentence `Edit [bot-instructions] in the effective manifest or the spec copy, then re-render.`
- A markdown output uses an HTML comment on **one line**.
- YAML and TOML use `#`, over two lines, and so does `.macroscope/ignore.md`, whose grammar is glob-per-line with `#` comments rather than markdown's.

**Every recorded path is refused, not escaped, outside a safe class.** A path outside `[A-Za-z0-9._/-]` fails naming it.

- The marker names no package version, source commit or content hash: any of them would conflict between two pull requests that change this package and rewrite every marker on each consumer refresh.
- A generated file therefore does not say which spec copy rendered it; `check` against a given copy says whether the files are what that copy renders.

**The marker gate is read at the moment of the replacement**, never on an earlier read of the repo.

- A path whose marker is absent then fails naming the path rather than being replaced.
- `orphan` keeps its pre-write read, because it writes nothing.
- The render's removal of an orphan rereads the marker at the moment of removal.

**One open decides and replaces.**

- A generated file's bytes do not depend on the file, so its replacement reads nothing.
- `AGENTS.md` is a read-modify-write, the splice and `adopt` taking a region or a file over. There the ownership check, the region and the bytes spliced all come from the one read the write phase makes.

That read decodes strictly, and so does every other read in this package. **Text this run judges by, or writes back, must round-trip.**

- A file holding a byte that is not UTF-8 is refused naming the path, before anything is written.
- Every validator read refuses on the same rule, in the working tree and in the index alike.

**A path list is neither content nor display text, and round-trips.** The one exception to the rule above: the `git ls-files` path list decodes with surrogates, which `os` calls and `subprocess` argument lists encode back to the bytes git gave, so a name that is not UTF-8 is neither refused nor substituted.

**Write phase.**

1. The generator builds and validates a complete scratch tree.
2. It replaces each path.
3. It splices the owned region.
4. It removes each marked file the TOML no longer produces.

- Removal comes last, so a write that fails leaves every orphan in place for the next render to find.
- A failure part way through names what it replaced and what it removed before the failure.
- `check` reds on every path still carrying the old bytes until a re-run finishes the set.
- `render` also names, as `removed PATH`, a marked file an earlier render removed while the index still tracks it.
- `--dry-run` and `--discover` name it as `would remove PATH`, so a caller that builds a commit from those lines stages the deletion.
- The set is not replaced atomically as a whole.

**Each individual replacement is atomic**, the `AGENTS.md` splice included: an interrupted write leaves the old bytes, never a truncated file.

- Write a temp file and rename it over the target, one temp name per write.
- The temp name carries the writing process's pid.
- Every exit from the span between creating the temp and renaming it removes the temp, whichever step raised.

**The scratch tree is in memory, never on disk.**

- The build holds each output's bytes, and the byte validators read the structure those bytes were serialised from.
- A validator failure leaves the repo untouched.
- `AGENTS.md` is outside that scheme: the build produces the region's body alone, and § `AGENTS.md` says what the write does with it.

**No timestamps and no input hashes** in a rendered file. A render is reproducible from its inputs.

**Ordering is fixed, never sorted at render time.**

- Doctrine blocks appear in the order each section below states.
- `[[bot-instructions.surface]]` entries appear in TOML declaration order, followed by the spec copy's default surfaces in the order `SKILL.md` § Default surfaces declares them.
- Exclusion entries appear with the derived render trees first, in lexicographic order, then `[[bot-instructions.exclusions.path]]` entries in declaration order.

**Repo text keeps its line breaks** except in CodeRabbit's `tone_instructions` scalar, which is one line by construction.

- No repo text reaches the `AGENTS.md` owned region at all: the one line it carries is the directive.

**Doctrine text is reflowed by its origin, not by its destination.**

- A block as the spec copy wrote it is this package's own hard-wrapped prose, and its paragraphs are joined on every destination that carries them.
- A block a repo overrode through `[bot-instructions.doctrine.append]` or `[bot-instructions.doctrine.replace]` is repo text, so the rule above governs it and its line breaks reach every destination.

**`exclude_globs` is real on one surface only.**

- Macroscope has an `exclude` frontmatter key evaluated after `include`, so the subtraction is expressed there.
- Copilot's frontmatter has no exclude key and CodeRabbit's `path_instructions` entry has no exclude field. On both, the subtraction is rendered as a closing PARAGRAPH of the instruction text, one blank line under it, naming the paths the rules do not cover.
- Those bots load the instructions for the excluded files and are asked to disregard them.

One table, one row per doctrine block, one column per destination that carries doctrine.

- A number is that block's position in that destination.
- A dash is a deliberate omission with its reason below.
- Every per-surface section below cites this table rather than restating its own list.
- The generator reads it as its single routing input.

| `scope` | 1 | – (b) | – (a) | 2 | – | 2 | 1 | 2 |
| `rounds` | 2 | – (b) | – (a) | 3 | – | 3 | 2 | 3 |
| `severity` | 3 | 1 | – (a) | – | 1 | 4 | 3 | 4 |
| `no-preferences` | 4 | – (b) | – (a) | 4 | – | 5 | 4 | 5 |

| `render-out-of-scope` | 6 | – (b) | 1 | 1 | – | 1 | – (c) | 1 |

| `reply-contract` | 8 | – (b) | – (a) | – | 4 | 8 | 6 | 8 |

`[bot-instructions.repo] summary` placement, since the destinations differ:

- It opens `.github/copilot-instructions.md`, immediately after the `# <repo name>` line, ahead of the one block that file carries.
- Everywhere else the summary follows the last block: both `pr_agent` `[review_agent]` keys, `pr_agent extra`, and `macroscope doctrine.md`.

**The exclusion set's placement.**

- Where it is rendered, it follows the `render-out-of-scope` block immediately, as the closing paragraph of that block, in the exclusion set's own fixed order.
- Three destinations carry it: `code-review.md`, `pr_agent issues`, and `pr_agent extra`, the columns whose `render-out-of-scope` cell carries a number and whose bot has no file-based review exclusion.
- Codex and Copilot are both sent to `code-review.md`.
- `.coderabbit.yaml` and `macroscope doctrine.md` carry the block without the paths, since `path_filters` and `ignore.md` subtract them for real.
- `REVIEW.md` omits the block entirely, note (c).

What each surface gets:

| Surface | Mechanism | Enforced |
|---------|-----------|----------|
| CodeRabbit | `reviews.path_filters`, exclusion-only | yes |
| Macroscope | `.macroscope/ignore.md` | yes |
| Codex | the rendered paths in `code-review.md` | no |
| Copilot | the rendered paths in `code-review.md` | no |
| Qodo | the rendered paths in `issues` and `extra` | no |

- On CodeRabbit, the excluded files are not reviewed.
- On Macroscope, the exclusion is repo-wide across check runs.
- The `AGENTS.md` directive sends Codex to `code-review.md`, and Copilot reaches it through the same file.

**(a) `.coderabbit.yaml` carries one block.**

- CodeRabbit reaches the rest through `knowledge_base.code_guidelines.filePatterns`, which names `AGENTS.md` and the pointed file, and CodeRabbit loads what the patterns name.
- `render-out-of-scope` is the exception because it rides the `path: "**"` instruction entry, where it does scoping work.

**(b) `copilot-instructions.md` carries one block.**

- Copilot reaches the rest by following the pointer to `code-review.md`, which no vendor page documents (`references/limits.md` § GitHub Copilot code review).
- `severity` is the exception because it holds the approve rule: on a repo whose rules require an approval, that rule decides whether a head merges, so it goes in a file Copilot loads itself.

**(c) `REVIEW.md` omits two.**

- `render-out-of-scope` names trees whose exclusion Qodo already carries in `[ignore]` and in the `[review_agent]` guidance.
- `trust-model` is about a merge gate's evidence rather than about writing a finding.
- Both reach Qodo through `.pr_agent.toml`.

**`code-review.md` carries all eight**, and so does `macroscope doctrine.md`. The first is where Codex, Copilot and CodeRabbit are all sent, and the second is Macroscope's only instruction surface, so a block omitted from either reaches those bots nowhere.

**`best_practices.md` carries no doctrine.** It gives `[[bot-instructions.surface]]` text a route to Qodo, and `.pr_agent.toml` already carries every block.

## `AGENTS.md` § Code Review Rules

- Read by Codex, by Copilot code review on GitHub.com, and by CodeRabbit through `knowledge_base.code_guidelines.filePatterns`.
- Rendered when `[bot-instructions.bots] codex` is true.
- The same flag renders § `code-review.md`, which is where the doctrine itself goes; this region is the pointer to it.

**Owned region.**

- From the heading line through the line before the next heading at level 1 or 2, or end of file.
- The generator replaces that region's body and touches nothing else in the file.

The **opening** matches `^## Code Review Rules$` exactly: no trailing whitespace, no CR, no leading BOM.

- Exactly one such heading must exist: zero is an error, and two is an error rather than a guess about which one to replace.
- The **terminator** is `scripts/lib/markdown.py`'s heading predicate at level 1 or 2, which every site in this package reads: wide about the indentation before the hashes, exact about the whitespace after them.
- Where the opening predicates differ, the stricter one is the contract: a repo whose heading carries trailing whitespace gets an error naming the byte.

**Missing section.** An error. The generator never creates `AGENTS.md` and never adds the heading.

**The bootstrap is add-the-heading, set `[bot-instructions.bots] codex`, `adopt`, then `render`.**

- The flag precedes the `adopt` because `adopt` takes a region over only for a capability that is on.
- `render` refuses to replace the unmarked region a hand-added heading leaves, and there is no bootstrap exemption.
- `adopt` takes the region over and names it in what it prints.

**The splice happens at write time.**

- The build phase produces the region's body.
- The write re-reads `AGENTS.md`, locates the owned region in those bytes, and replaces it there, so an edit landing between the build and the write survives.
- A file whose region cannot be located at write time, the heading gone or duplicated since the build read it, fails naming the path.

**Body.** The marker as an HTML comment, then one directive line, and nothing else:

```markdown
If you are a review agent reviewing code, read <code_review_path> before you comment.
```

No doctrine block reaches this region, so the routing table has no column for it.

**Any longer region is a finding**, so a repo cannot keep the doctrine here by hand.

- `adopt` reports one under `agents-region` and writes the marker unless `--dry-run` is set, so a single `render` repairs it.
- `check` reports one under `drift`, which holds the region against a fresh render and is that comparison's only owner.
- `render` replaces it, which is the migration.

**Escaping.**

- Full mode interpolates only the configured path, whose class `repo-toml.md` § `[bot-instructions.repo]` fixes.
- Local mode uses the selected installation's checkout path and Doctrine anchor, under [§ Local output](#local-output).
- No doctrine or repo string reaches this region.

## `code-review.md`

The pointed file: this repo's complete review doctrine, in one place.

- `[bot-instructions.repo] code_review_path` names it, defaulting to `.github/instructions/code-review.md`.
- `repo-toml.md` § `[bot-instructions.repo]` states where it may sit.
- Rendered when `[bot-instructions.bots] codex` is true.
- Read by Codex and by Copilot code review because the `AGENTS.md` region and `.github/copilot-instructions.md` each send them here.
- Read by CodeRabbit because `knowledge_base.code_guidelines.filePatterns` names it.

**Owned.** The whole file. The generator creates it, unlike `AGENTS.md`.

**Body.**

1. The marker comment.
2. `# Code review rules`, the file's only level-one heading, then one line naming the audience.
3. The blocks the `code-review.md` column of the routing table carries, in its order, as `##` sections keyed by block id.
   - Package-authored doctrine is joined into one paragraph per paragraph of the spec copy.
   - A block a repo overrode keeps its own line breaks, per § Common rules.
4. The exclusion set as the closing paragraph of `render-out-of-scope`, in the set's fixed order, joined with commas.

**Collision.**

- A configured path this render already writes is an error naming it.
- The question is asked against the whole output set at the end of the build, never against a second list of the paths this package writes.

**Escaping.** Markdown, passed through, with the same heading predicate as everywhere else so a repo string cannot forge a section.

## `.github/copilot-instructions.md`

Read by Copilot code review, repo-wide, from the pull request's head branch.

**Owned.** The whole file.

**Body.**

1. The marker comment.
2. `# <repo name>` followed by `[bot-instructions.repo] summary`.
3. `## Code review`, one sentence naming the configured `code-review.md` path and telling the reader to read it first.
   - The sentence is emitted on one line and never wrapped.
   - The repo name is the file's only level-one heading.
4. The blocks the `copilot-instructions.md` column of the routing table carries, in its order, as `###` sections keyed by block id under `## Code review`, joined as `code-review.md` joins them.
5. `## Path rules`, one sentence naming `.github/instructions/` as where per-path rules live, emitted only when at least one surface exists, a default surface included.

**Budget.**

- The rendered file must not exceed `[bot-instructions.budgets] copilot_chars` (default 6000).
- Over it, the render fails naming the character count and the budget.
- GitHub documents no numeric cap here; see `references/limits.md`.

**Escaping.** Markdown, passed through, with the same heading predicate as above so a repo string cannot forge a section.

## `.github/instructions/<name>.instructions.md`

Read by Copilot code review on GitHub.com, JetBrains and Xcode, scoped by `applyTo`.

**Owned.**

- One whole file per `[[bot-instructions.surface]]`, named `<surface.name>.instructions.md`.
- Files in that directory carrying no marker are hand-written and are left alone.
- A marked file no current surface produces is an orphan.

**Body.**

```markdown
---
applyTo: "<globs joined with a comma and no space>"
excludeAgent: "cloud-agent"
---

<!-- generated ... -->

<surface.instructions>
```

- `excludeAgent` is emitted only when `reviewer_only = true`, and then only as `cloud-agent`, which hides the file from the working agent and leaves code review reading it; `code-review` would do the opposite.
- `applyTo` is a single non-empty string holding a comma-separated glob list, not a YAML array.
- The glob dialect refuses a comma, so the join is unambiguous.

**Escaping.**

- The frontmatter is YAML.
- The glob dialect refuses `"`, so no escaping is needed and a pattern that would need it is refused at input time.

## `.coderabbit.yaml`

- Read by CodeRabbit from the pull request's head branch.
- The file outranks the repository and organization dashboards.
- An organization or workspace global override, which a repo cannot see, outranks the file.
- An unset key resolves down a precedence ladder this package does not control (`references/limits.md` § CodeRabbit), so the render writes full state, including keys that match their schema default.

**Owned.** The whole file.

**Head.**

1. The `yaml-language-server` schema line.
2. The marker comment.
3. A sentence stating that this file is not a delta and that a global override, if one exists, outranks it.

**Keys.** The render **walks the vendored schema** and emits, at every depth, every property the schema defines a default for **plus every property this package chooses a value for**.

- The value comes from the posture below where this package has an opinion, and from the schema's own default everywhere else.
- A property the vendor defines no default for is written only when this package overrides it.
- An object carrying its own default is that default whenever nothing beneath it is in the set, never `{}`.
- `scripts/lib/render_coderabbit.py`'s `in_full_state` is the one predicate for this paragraph, read by the render and by the validator alike.
- A property the vendor adds arrives at its own default and shows in the diff.

The top-level **order** is fixed here rather than taken from the schema:

1. `language`
2. `tone_instructions`
3. `early_access`
4. `enable_free_tier`
5. `inheritance`
6. `reviews`
7. `chat`
8. `knowledge_base`
9. `code_generation`
10. `issue_enrichment`

A vendored copy that defines fewer top-level properties than that order names fails the render, naming the one it lacks.

- `code_generation` gets no path instructions: the vendored schema gives it no enable switch, so `reviews.finishing_touches`, whose docstring and unit-test entries are off, keeps a bot from pushing code.
- `issue_enrichment` is written off, since this package configures review and not issue triage.
- `inheritance` is written `false` explicitly. It decides whether an unset key takes a parent level's value instead of resolving down the ladder, so a full-state render states it.
- `tone_instructions` is `[bot-instructions.tone] coderabbit` with newlines collapsed to single spaces, emitted as a folded scalar.
- Its 250-character cap is the vendored schema's own `maxLength`, and `coderabbit-schema` is its single enforcer.

The shipped default when `[bot-instructions.tone]` is absent:

> Terse and technical. Give the defect, its triggering input, and the consequence. No praise, diff restatement, or summary. One finding per thread. If unsure, name the part you could not verify.

`reviews` carries the findings-only posture:

- Every summary, decoration, labelling, reviewer-suggestion and fortune key false.
- `collapse_walkthrough` true.
- `review_status` and `commit_status` true, because a repo's gate may read that status.
- `request_changes_workflow` true, so a changes-requested review converges without a human dismissing it.
- Every `finishing_touches` and `pre_merge_checks` entry off, because this package never lets a bot push code.
- `reviews.auto_review.base_branches` is `[".*"]` rather than the default branch by name; `references/limits.md` § CodeRabbit gives the evidence.

**An override naming no property the vendored schema defines fails the render**, naming the key.

- Such a choice would never apply, and the key would resolve to the vendor's default with every validator green.
- A schema refresh that renames a property reaches this.
- `load_schema`'s top-level check is the same shape one level up.

**`reviews.path_filters`.**

- The exclusion set, each entry prefixed `!`.
- Each entry is preceded by a comment carrying its reason: the entry's own `reason` where it has one, and the fixed string `repo-toml.md` § `[bot-instructions.exclusions]` states for a derived entry.
- Exclusion-only: a single entry without `!` turns the list into an allowlist and un-reviews every unlisted file in the repo.
- CodeRabbit feeds these patterns to `git sparse-checkout`.
- `repo-toml.md` § The glob dialect enforces both rules.

**`reviews.path_instructions`.**

- One entry per `[[bot-instructions.surface]]`.
- `path` is the surface's globs joined as a brace alternation when there is more than one (`{a/**,b/**}`). minimatch understands that, and it is safe here because `path_instructions` never reaches sparse-checkout.
- `instructions` is the surface text with `exclude_globs`, when present, rendered as a closing sentence naming the paths the rules do not cover.
- Each entry is capped at 20,000 characters.
- A final entry with `path: "**"` carries `render-out-of-scope` when the exclusion set is non-empty. The path filters already remove those trees; the instruction stops a finding arriving through a file that references them.

**`knowledge_base`.**

- `opt_out` is the inverse of `[bot-instructions.retention] coderabbit`, so `false` by default.
- Every learning scope is local.
- `code_guidelines.filePatterns` names `AGENTS.md` and the configured `code-review.md` path, in that order.
- Those patterns are the only way CodeRabbit reads either file, and the second is how every doctrine block reaches it.
- Code guidelines are stateless and keep working under an opt-out.

**Escaping.**

- Every string is emitted as a block or folded scalar with explicit indentation, never a quoted one-line scalar.
- Repo text is passed through with no escaping.
- A repo string containing a line that would terminate the block is refused, and so is one carrying a control character, by the same refusal `.pr_agent.toml` relies on.
- **A line is what the READER calls a line, not what `\n` calls one.** The `control` class of `repo-toml.md` § The content refusals holds `U+0085`, `U+2028` and `U+2029` for that reason.
- The **reader** runs that class, and the emitter does not. Every repo string arrives through a row of that table; a default in the vendored schema does not, and `coderabbit-schema` and `exclusion-consistency` each read the emitted document and refuse it, naming themselves, before `render` writes anything.
- The one exception is the **empty string**, which a block scalar cannot carry. It is emitted `""`. It arises only from the schema's own defaults, never from repo text.

## `.pr_agent.toml`

Read by Qodo from the root of the default branch.

**Owned.** The whole file.

**Head.** The marker comment, before the first section, as `#` lines.

**Sections.**

- `[github_app]`: `pr_commands` from `[bot-instructions.cadence] qodo_commands`, `handle_push_trigger` from `[bot-instructions.cadence] qodo_push_trigger`.
- `[review_agent]`: `comments_location_policy = "inline"`, `issues_user_guidelines`, `compliance_user_guidelines`.
- `[pr_reviewer]`: `extra_instructions`, plus the noise keys off (`require_tests_review`, `require_security_review`, `require_ticket_analysis_review`, `enable_review_labels_security`, `enable_review_labels_effort`, `require_score_review`, `require_estimate_effort_to_review`, `require_can_be_split_review`, `persistent_comment`, all false).
- `[pr_description]`: `publish_labels = false`.

**Two sections carry the same guidance.**

- `/review` reads `[pr_reviewer] extra_instructions`.
- `/agentic_review` reads `[review_agent]`.
- The generator writes the same doctrine into both, split differently.
- The routing table's three `pr_agent` columns say which block goes where and in what order.
- `issues` and `compliance` split the set between the two `[review_agent]` keys.
- `extra` holds all eight in one string, because `[pr_reviewer]` has no per-agent split.
- Keep every block in `extra` in one of the two `[review_agent]` keys and the reverse when editing those columns; no validator checks it.
- `qodo-parity` checks only that the section each review verb in `qodo_commands` reads carries guidance.
- In `issues` and `extra`, `render-out-of-scope` takes position 1 and carries the exclusion paths after its text.
- Qodo's `[ignore]` filters what it analyzes for `/improve`, not what the review agent reads, and Qodo has no per-path exclusion for review content, so prose is the only exclusion route to its review agent.

**`[ignore]`.** `glob` from the exclusion set, each entry as written, without the `!` prefix CodeRabbit needs.

**Escaping.**

- Guidance strings are TOML basic multi-line (`"""`), so every value reaching one is under the toml-delimiter and control refusals in `repo-toml.md` § The content refusals.
- A backslash is escaped; that is the only rewriting done here.
- Everything the format cannot carry is refused at input instead.

## `REVIEW.md`

## `.macroscope/`

- Rendered only when `[bot-instructions.bots] macroscope` is true.
- Read from the most recent commit on the pull request, except for a fork pull request, which reads the default branch.

**`.macroscope/ignore.md`.**

- One glob per line, `#` comments, blank lines ignored: the grammar Macroscope documents, cited in `references/limits.md` § Macroscope.
- The file is markdown by extension only, so the marker takes the `#` form, never an HTML comment, which would be a pattern matching nothing.
- Each glob's reason is a `#` comment on the line above it, taken from the same two sources `path_filters` uses: the entry's `reason`, or the fixed derived string.
- A `reason` is single-line, refused at input otherwise, so no reason puts a pattern line into this file.

**`.macroscope/correctness/doctrine.md`.**

- No frontmatter, so it applies repo-wide.
- The marker as an HTML comment, then the blocks its routing-table column names, which is all eight.
- Its name is reserved, as are `correctness` and the two `.macroscope/` root names.

**`.macroscope/correctness/<name>.md`.**

- One per `[[bot-instructions.surface]]`: frontmatter `include` from `globs` and `exclude` from `exclude_globs`, both as YAML string arrays, then the marker, then the surface's `instructions` as the body.
- The render never emits one with an empty body.
- Macroscope evaluates `exclude` after `include`, which matches the TOML's meaning directly.

**Not written.** `.macroscope/check-run-agents/`, `.macroscope/approvability.md`, and `.macroscope/correctness/correctness.md`.

- The first two create merge-blocking check runs and per-run spend, which is a repo owner's decision.
- The third is Macroscope's governing file, carrying `waitsFor`, `requires`, `waitsForTimeout` and `waitsForDiscoveryTimeout` for the whole correctness run.
- This package writes no frontmatter key but `include` and `exclude`, so a render over it would drop those four.
- A repo keeps its own governing file, hand-written and unmarked, and no surface may be named `correctness`.

**Escaping.**

- Frontmatter is YAML.
- Globs are emitted as quoted scalars, and the glob dialect refuses the one character that would need escaping.
