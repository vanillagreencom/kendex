# Rewrite Markdown to what its readers need

This workflow converts Markdown onto this skill's convention, restructures it, or cuts what its readers do not need. [../SKILL.md](../SKILL.md) § Writing says when it applies. The scope is what was asked for: one file, one folder or the whole repository. Every step runs over the files in that scope. A step that names no file in scope is skipped. Step 1 names the files that cite them among their readers. Step 5 edits those citers.

A scope of `docs/` or a file under it edits `AGENTS.md` only for the "Read when" lines of the docs it keeps or deletes. It edits no `SKILL.md`. A rewrite of an `AGENTS.md` or `SKILL.md` body runs only where the request names that file or the whole repository. That naming is the owner's approval of the rewrite.

## Steps

1. **Readers.** For each file, name who reads it and when: each loader, how it loads (at session start, at skill activation, by a route to one section, from a hook or from a program), the task it is doing, and whether it reads the whole file or one section. A program that parses a heading or a table is a reader, and so is a file that cites a heading, anchor, rule name or path of it. Count the words each loader reads, in the installed copy where kendex renders project instructions above the body. The readers give the file its jobs: an entry read before the loader knows its workflow, a workflow run from first line to last, or a reference read at one section ([../references/skill-files.md](../references/skill-files.md)). For a repository-wide scope, the files are every Markdown file the repository owns: the root and every nested `AGENTS.md`, every harness-specific instruction file, every file under `docs/`, and every `README.md`, `DEVELOPMENT.md`, `SKILL.md`, workflow, agent file and reference doc.
2. **Directive list.** Number every rule of the old file, one row each. A rule's "never" clause is part of its row. List the file's headings, anchors and named rules as rows too, and its path. Search the repository for each of them: source files, scripts, manifests, tests and printed help, not renders, which follow their sources. Record each citer in its row, and whether a program parses or prints the name. md-refs judges only the forms the commit-guards skill's CHECKS.md § md-refs lists. A bold rule name, a path alone in a code span and a plain-text citation outside those forms pass it unjudged. So the search is the check. Write the list under `tmp/`. Attach it to the tracker issue the work serves. The list records every fact that moves or goes.
3. **Verdict per rule.** For each row, write the mistake it prevents, whether an agent makes that mistake untold, what the mistake costs, and what else already stops it. [../SKILL.md](../SKILL.md) § Per file type sets the bar. It names what can stop a mistake. Each row takes one verdict: keep, move to a named file and section, or cut as a duplicate, a tool's refusal, never applies, or competence. Record each departure from the type's guidance with its reason.
   - **Cut.** A cut carries a trace. Follow one ordinary request from the agent that needs the rule to the check that stops the mistake. Name each file and step. The check acts before the effect: a refusal after a merge does not stop a mistake made before it. The route is the files step 1 says that agent reads for that task. A rule in a file off that route stops nothing. The trace covers every case the rule governs. If the refusal leaves the agent to read long help to recover:
     - The cut stands.
     - The literal form the recovery needs stays where the rule was.

     If you cannot trace a cut, keep the rule.

   - **Move.** Apply [One home per fact](../SKILL.md#one-home-per-fact) before moving a rule. A rule whose home is another file or another package's step moves there in the same change. It keeps its name as its heading at the new home. A literal form moves with the rule that needs it. The homes outside the skill are a comment at the code for a reason, an architecture doc for a principle, a decision record for a choice, `DEVELOPMENT.md` for a maintainer step, the runbook for an operator step, and the tracker issue for a plan or research file. A reference stays only where a named reader loads it ([../references/reference-docs.md](../references/reference-docs.md)). Write each moved rule at its new home. Read it there before you delete the old copy. A removed paragraph proves removal alone.
   - **Keep.** A kept rule keeps its actor, condition, scope, exceptions, order and enforcement claim. A row whose meaning changes is a defect of the write, or a separate change that names it. Verify each kept claim by [../SKILL.md](../SKILL.md) § Writing. Check that each kept source link is readable. Keep an observation within the conditions its source checked. A failed, unchecked or unread verification stays unresolved, with its source and next action. Disagreement with an active decision does not make its policy obsolete:
     - Keep the choice and any owner-only approval.
     - Report the disagreement through decider.

     A kept rule that would serve every install, and that no installed package states, is also reported through `kendex report`.

   - **Design claims.** Follow [One home per fact](../SKILL.md#one-home-per-fact), starting with the ownership rule before the design-claim questions. A behaviour a test holds is deleted, the test being its home. A behaviour no test holds becomes a test item on the tracker.
4. **Edit in place or rewrite.** Edit in place only where step 1 finds one job and the file's order already follows its type's section. There:
   - Delete the cut rows.
   - Apply the moves.
   - Leave the rest as written, apart from the split below.

   Where the file does not meet that condition, write from a blank page. A file with two jobs, such as an entry that other packages also read by section, or a workflow holding a contract that other jobs look up, is split by job. Each part is written from a blank page. So is a one-job file whose order does not follow its type's section, such as a README with its sections out of order or an architecture doc written as a journal. For a blank-page write, open the reader list, the verdict table, the type's section and its example ([../SKILL.md](../SKILL.md) § Per file type). Copy no old text except a literal form a verdict keeps. A `SKILL.md` holds what [../references/skill-files.md](../references/skill-files.md) gives an entry, whatever roles its example has. In either write, split each block and table cell by [../SKILL.md](../SKILL.md) § The standard. The split keeps the same directives in the same order. It adds none.

5. **Citations.** For every heading, anchor, named rule and file path the change moves, renames or deletes, change each citer step 2 recorded in the same pull request, or keep the name. Keep a name a program parses or prints, and one a citer outside the repository uses. A pattern that only classifies files keeps working or goes. A link to a deleted file goes. Update a claim in a touched file that the change makes false, by [../SKILL.md](../SKILL.md) § Maintenance.
6. **Conversion.** These apply only where the scope holds the files. A file this step moves or deletes takes step 5 for its citers.
   - Plans, research reports, measurements and handoffs under `docs/` leave by [../SKILL.md](../SKILL.md) § Plans and research. Name the inspected tracker attachment as the destination of retained evidence. A missing local report whose tracker attachment is unread leaves preservation unchecked. Read the attachment before you claim either preservation or loss.
   - Delete a doc under `docs/architecture/` that holds no principle by [../references/architecture.md](../references/architecture.md).
   - Redo decision records from [../examples/decision.md](../examples/decision.md) under the [decider](../../decider/SKILL.md) bar and its update workflow. A record whose choice still holds stays active, with its authority unchanged. Keep a one-line pointer for a removed record only where a citation outside the repository needs its path.
   - Keep the root `AGENTS.md` section `## Code Review Rules`, which the bot-instructions package renders. A file a package renders and keeps current, such as that package's `.github/copilot-instructions.md` and `.github/instructions/` files, is the package's. It stays.
   - Migrate hand-written harness-specific rules, `.claude/rules` content included, only under the consumer's selected instruction-migration policy and only where the request authorizes the source and destination files. A prose rewrite alone authorizes no migration. With no selected policy, or with files outside the authorized scope, keep the existing rule files.
   - A reference keeps its canonical schema or pattern and its field semantics. For defaults, follow [One home per fact](../SKILL.md#one-home-per-fact).
7. **Refresh.** If the rewrite changes kendex-owned inputs, follow the selected project's declared refresh owner and verification route. In an ordinary local checkout with no declared refresh owner and no recorded lane:
   - Run `kendex refresh --scope project --yes --leave`.
   - Then run `kendex verify --scope project`.
   - Stop on failure.

   An ordinary worktree keeps normal project resolution. A recorded implementation lane does not refresh. An authorized refresh lane passes `--lane-refresh` as its brief permits. A hosted control checkout receives committed outputs through `sync-base` after the owner's refresh pull request merges. For a hosted control checkout with no declared owner, confirm an owner outside the control host.

8. **Mechanical checks.** Search the repository again for every name and path steps 4 to 6 moved, renamed or deleted. The second search finds no stale citer. Run the commit-guards `md-type` and `md-refs` lanes over the files the rewrite touched. Reflow a file only where `md-reflow --check` names it. The rewrite is not a tree-wide reflow. Then run the repository's own validation.
9. **Check by use.** A top model from another provider than the writer's does real tasks of the readers step 1 names. It reads only the new files each task's route reaches. Give it a task for each reader. Give it a failure case for each cut: the request the cut rule governed, which its trace says another check now stops. Run each failure case through the agent's steps before the tool call named in the trace, the call itself and the steps that follow its result. The writer's task list gives each task's old outcome and the words its route read before the change, and each failure case's traced stop. For each task the checker reports the route, the outcome against the old one, and the words read before and after. The words are a reading, not a target. A rule that became a list or a table is tested on its actor, scope, exceptions and order. The result names the head it checked and the checker's model and effort. It is attached to the tracker issue the work serves. The writer edits none of it. The second-opinion skill guarantees another model, not another provider. Name its target. The check passes when every task reaches the old outcome and every cut's trace holds. The writer repairs each failing row. The same checker reads the repaired rows once more. A second failure goes to the owner for a ruling, never to another round.
