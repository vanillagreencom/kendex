# harness-ci development

Maintainer notes. Consumer docs: [README.md](README.md); the wiring rules: [SKILL.md](SKILL.md). The classifier this package wraps is change-scope's; its invariants are in [change-scope's DEVELOPMENT.md](../change-scope/DEVELOPMENT.md).

## Invariants

- `change-class` is a wrapper: it runs change-scope's `change-scope` over the range it was given, with `--paths-output` so it holds the changed paths the classifier read before any rule, and adds what CI alone needs: the queue-only class, the per-push mode and the lane verdicts. The class, the classifier's stderr lines and its exit 2 wiring error are carried as they stand; the wrapper's own records go ahead of the `class:` line, which closes the log. `scripts/harness-only` is a forwarder to change-scope's reader, kept so every workflow, action and consumer that names this path keeps its call.
- The queue-only class is judged on the whole changed-path set the classifier read, before any of its rules. A wiring error the classifier raises after the paths were read is therefore still judged for it, so the base settings' `setting-refused:` and `setting-unset:` records and their annotations print ahead of the error, as they did when one script held both; the `queue-only:` line itself prints on a verdict alone.
- `aggregate-needs` accepts a skipped job only when the classifier succeeded and either its waiver is `true` and the job is in the caller's explicit skippable set, or the job is named in a `--lane` whose verdict, read out of the classifier job's outputs in the results it was handed, is `false`. An absent verdict authorizes nothing, the verdict is never a separate argument a workflow could compute wrongly, and a job named by two `--lane`s is refused rather than decided by argument order.
- The judged tree's configuration decides nothing. `change-class` reads the repository's queue list, selector and per-push reason, `HARNESS_CI_QUEUE_PATHS`, `HARNESS_CI_QUEUE_SELECTOR` and `HARNESS_CI_PER_PUSH_REASON`, from the `[env]` tables of the settings files the commit `--base` names holds, through change-scope's `base_settings`, never from the judged tree or the caller's environment, which the wrapper unsets first. That commit is the pull request's base end [references/wiring.md § The endpoint expressions](references/wiring.md#the-endpoint-expressions) names or a merge group's base, never the merge base, which the author picks by choosing where to fork.
- The queue selector is the one command `change-class` runs out of a repository, and it runs the base commit's copy in a private checkout of that commit, made as the render proof's checkout is, never the judged tree's: the branch under judgement can neither name the command nor change what it runs, while a change to the selector itself is judged by the copy it replaces. It is asked only on `pull_request` and `merge_group`, the events whose merge route it decides, and only where every path rule read `queue_only=false`, at the verdict, because the jobs a merge group runs can depend on the class: kendex's own selection, `tools/ci-job-set`, runs no shell shard on a `render` change, and on a `trivial` one only where a path the Rust source reads gives it a measured class's row.

## Tests

`tests/` runs in kendex CI on every change to this repository; run one locally with `bash skills/harness-ci/tests/queue-only.test.sh`. The suites source change-scope's `tests/lib/sandbox.sh`, which lays out both packages.

| Suite | Covers |
| --- | --- |
| `aggregate-needs` | Successful dependencies, skips the waiver or a lane's own verdict authorized, a true or absent verdict and another lane's verdict refused, a rejection naming each unaccepted job and the verdict read, refused results, invalid input, every `--lane` shape but `JOB=LANE` and a job given two `--lane`s, and must-fail controls for classifier success, dependency success, the waiver, skippable membership, the lane verdict, lane membership, the `--lane` shape and the duplicate job |
| `change-class` | The wrapper over change-scope's classifier: the one class line on stdout, the classifier's stderr lines in order with its `class:` line last, after the `queue-only:` and `per-push:` records this package adds; the classifier's wiring error as the wrapper's, with the same status, and the base settings' records printed ahead of it; the verdict in the GitHub output file with the queue and lane answers beside it; no flag carrying a class; and the must-fail control of a wrapper printing the class line ahead of its records |
| `ci-template` | `templates/ci.yml`: one job named `CI` needing every other job, both gated events, the `lanes` step run on the action's lane verdicts, the lanes each event, `lanes` answer and verdict runs, an absent verdict leaving `lanes` to decide, both events reading the verdicts the same way, a dead classifier running every lane, the declaration read from the default branch's checkout, the classify step asking for the queue-only default, no line reading the change class, the aggregate's waiver and `--skippable` and `--lane` arguments fed to the real `aggregate-needs`, the render-reach, kendex install and mirror steps continuing on error, and must-fail controls for a lane without its status function, CI without the waiver, a lane output reading the class, a declaration read from the judged checkout, a template not asking for the default, CI without `always()`, a template without `merge_group`, a render-reach step that fails the job and an evaluator that refuses every expression |

| `render-claims` | The action's default-branch claiming lanes for every path a proved render changes, in place, added, deleted or at either end of a move: the merge group runs them, a pull request or push runs them only where the base names `HARNESS_CI_PER_PUSH_REASON`, and a pull request still defers a `:queue` lane to the merge group |
| `wiring-shapes` | Every shape in `references/wiring.md` keeps each expression on one line, orders the push endpoints, names the shipped script path, and steps its indentation by two |

The classifier's own suites, the real-kendex rows among them, are change-scope's; [its DEVELOPMENT.md](../change-scope/DEVELOPMENT.md) names them. The absence of change-scope beside this package, which the wrapper, the forwarder and `scripts/lib/change-class.sh` each refuse at startup, is held by change-scope's `absence` suite.

`tests/lib/workflow.sh` reads a workflow's job conditions, needs, names and triggers, plants a defect in a copy, and runs `tests/lib/gh-eval.py`, which evaluates the conditions, through `gh_eval`, which turns a refusal into an answer no row expects; kendex's `tools/tests/ci-aggregate.test.sh` reads its own `skill-tests.yml` with the same two files.

`tools/bash32-lint` checks the shipped scripts for Bash 4+ syntax, because consumer runners include macOS system Bash 3.2.
