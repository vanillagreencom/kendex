# slack development

Maintainer notes. Consumer docs: [README.md](README.md); the agent contract: [SKILL.md](SKILL.md); why the package is shaped this way: kendex decisions D009 and D014, which supersedes D009's polling and its one relay per person.

## Layout

- `scripts/slack`: the Bash launcher. It loads the checkout's settings through the orch skill's `kendex-env.sh`, checks for Python 3.8 and the orch install, names that install in `SLACK_ORCH_DIR`, and execs `scripts/lib/main.py`.
- `scripts/lib/main.py`: argv to one verb; `verbs.py` holds setup, post, thread, compact, install and status; `relay.py` the listener and its Socket Mode loop.
- `scripts/lib/api.py`: the Slack Web API client, `websocket.py` the RFC 6455 client the Socket Mode connection runs on, `mailbox.py` the `lane-mail` calls, `markup.py` the outbound tracker-link judge and Slack markup read back as typed, `store.py` the binding, journal, status record and lock, `secret.py` the secret-value check, `settings.py` the environment, `refusals.py` every keyed line and its explanation.
- `systemd/slack-listen.service`: the unit template `install` fills.
- The orch skill must be installed beside this package: the launcher sources `../orch/scripts/lib/kendex-env.sh` and is the one place that spells the location, which `secret.py` reads from `SLACK_ORCH_DIR` for `references/secret-value.ere`. Each root's `.agents/skills/orch/scripts/lane-mail` is that root's mailbox.
- The launcher names the optional sibling Linear install in `SLACK_LINEAR_DIR`. `markup.py::outbound` runs once at `RootRelay._send` and `verbs.post`, before secret checks. It measures link expansion before choosing Markdown or mrkdwn, then renders once. `TrackerMetadata` owns per-root discovery and its day-long cache, including failed reads. Its clock is injectable. Tracker discovery uses `orch-env` and `gh repo view` in each root; Linear reads use the sibling skill's launcher, never another API client. The launch checkout's loaded team does not override another root's settings.

## Constraints

- The relay keys every inbound delivery `channel:ts` and hands the key to `lane-mail`. Its journal skips a stamp it already carried; for a stamp the journal lost, the crash between the append and the mark, `lane-mail`'s locked check is the judge, and the refused repeat is read back as the envelope that landed and journaled under that id.
- The journal is replayed into memory at start and appended to as the relay works, one fsync per line. The compaction day lives in `status.json`, which is rewritten every poll, so the journal grows only with deliveries, positions and connection changes.
- One relay holds one Socket Mode connection, opened with `SLACK_APP_TOKEN` through `apps.connections.open`, and routes each message event by its channel. One reader owns socket sends and queues acknowledged envelopes; the worker owns journal, API and mailbox calls. History, HTTP 429 waits and mailbox work cannot hold socket reads or pong replies. Lane-mail calls have the named `LANE_MAIL_TIMEOUT_SECONDS` bound. An event moves no position. Each delivered owner message gets eyes at delivery and one `delivered` notice naming its Slack ts, mailbox id and live or catch-up path. Refused eyes adds remain unmarked and print their cause, except `already_reacted`. The first poll after every connect and reconnect reads history within the reconnect lookback, including messages missed during a stop after acknowledgement. A refused live delivery stays in its `RootRelay` memory until a later poll delivers it, independently of the history lookback. Status stays failing until delivery succeeds. A process stop loses that in-memory event; bounded catch-up alone covers restarts. Initial discovery reads `SLACK_THREAD_DAYS` back even past a younger position. It retains reply-free direct and ignored parents from history in the existing parent records before narrowing reconnect history. Reconnect history starts at the saved channel position; retained eligible parents still get replies reads from their saved positions. Only top-level messages past the channel position are delivered. `relay.py::RootRelay.live` bounds reconnect thread reads alone. `Binding.bound_at` lasts until journal reset; setup and owner changes retain it. D017 owns live reply eligibility and parent retention; `schemas/journal.md` owns the fields.
- `websocket.py` is built, not declared as a dependency: the catalog is standard-library only, and Socket Mode needs text frames, ping and pong, and close alone. A frame it cannot read closes the connection, which the relay answers with a reconnect and a history read. After `IDLE_SECONDS` of silence `WebSocket.recv` pings, and as many again with no frame it reads the connection as dropped, so every read the relay makes runs the check.
- Outbound idempotency is the journal's `out` lines plus two horizons. First, an envelope older than `SLACK_THREAD_DAYS` is never posted, and `compact` drops an `out` line only once the envelope's `at`, journaled on the line, is past that same horizon; `settings.py::Settings.horizon` is the one place it is computed. Second, a start whose journal holds no `start` line writes one at the mailbox's newest envelope and posts nothing at or before it but open asks. `setup` records `bound_at` in the binding, and that start reads Slack from there. The end of a master hold reads the master's `to-overseer.seen` line count and skips notices at or below it. The resume classifies the complete snapshot through `RootRelay.routes` before posting, so a token refusal cannot leave later read notices out of its suppression set. Its `resume` line carries the count and skipped ids; replay adds those ids to the carried set. `compact` keeps them by the resume's `at`, stamped at the resume poll, so a skipped notice cannot outlive its record while still eligible to post. A missing, unreadable or invalid count skips nothing. An open ask still posts whatever its line. Held answers still post. Closure follows [orch communication-modes.md § Owner asks](../orch/references/communication-modes.md#owner-asks). The relay consumes mailbox closure classes independently of the posting horizon. Its resolved journal line records the source id; replay retains consumption while the thread's mapping survives compaction.
- The hold is judged once per poll, after any history read due and its replies sent, before any envelope is posted, from `SLACK_MASTER_FILE`'s mtime against the injected clock. `hold` and `resume` lines are journaled on the transition alone, and `State.held` carries it across a restart. Presence times describe the hold; they never decide which notices the master read.
- A Slack call fails with one of two network keys, by where urllib raised it; `api.py`'s docstring states the rule. Every envelope post Slack refuses is repeated on the next poll, with two exceptions: a lost response (`slack-response-lost`) is journaled `unknown` and never repeated, and a dead token (`slack-auth-failed`) stops the relay. A repeated post fails the poll: `--once` exits 1 and the status row reads `failing` with the error.
- An owner's file is downloaded before its message is delivered, and every download failure becomes a `file <id> not fetched: <why>` line in the message, so no file holds a message back. Slack answers a download the app lacks `files:read` for with its sign-in page and HTTP 200; `api.py::Slack.download` reads an HTML answer whose length is not the size the message's `files[]` entry gives as that page, so an owner's own HTML file is saved and the sign-in page in its place is not, refuses a body shorter than its Content-Length, which http.client reads as a clean end, and refuses a chunked body cut short, whose `HTTPException` no other Slack call catches.
- A receipt mark is a reaction, never a message, and never fails a poll: a refused mark is printed, and a refused mark or swap, or a `drain --receipts` that `lane-mail` refuses, stays pending for the next poll. Delivery attempts :eyes: once for its own message. Each poll retries previously unmarked deliveries before new deliveries, so a new refusal waits until a later poll and a stop leaves its mark recoverable; `compact` keeps the `in` and `mark` lines of a directive not yet marked :white_check_mark: whatever their age, so a directive with no `mark` line is still marked once Slack takes the reaction. Whether the overseer has read a directive is `lane-mail drain --receipts`, the verb that reads `to-lane.cursor`; the relay runs it only while an `eyes` mark waits.
- `markup.py` reads an owner's text back as typed: Slack's escapes as `&`, `<` and `>`; a link as `label (URL)`, or the URL alone; a mention as `@name`, or `@<user id>` when Slack will not name the user; a channel as `#name`, or `#<channel id>` when Slack sends no name; `<!here>` as `@here`; a user group as its label, or `@subteam` with none; a date as its fallback text. Emoji stay `:name:`.
- The bot user id comes from `auth.test` at start; a message from that user or from any bot is never routed. Slack sends the relay's own posts as events too; this rule drops them.
- `SLACK_API_URL` names another API endpoint. The suites point it at the fake, whose `apps.connections.open` answers a `ws://` URL on the same port; nothing else sets it.

## Tests

```bash
for t in skills/slack/tests/*.test.sh; do bash "$t"; done
```

`markup.test.sh` tests the markup module directly in fixture checkouts, without Slack or mailbox writes. `websocket.test.sh` drives the client over a socket pair. The other suites start `tests/lib/fake_slack.py`, a fake Slack Web API and Socket Mode WebSocket with a control surface under `/_test/`. They build checkouts that link the real orch scripts, so every mailbox write goes through the real `lane-mail`. The assertion library and the fixture builders are `tests/lib/harness.sh`. A control runs a mutant: `sk_mutant` copies `scripts/` and replaces one pattern exactly once.
